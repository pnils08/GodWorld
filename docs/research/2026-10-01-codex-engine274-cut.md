# engine.274 cut — adversarial code review

**Verdict: HOLD as written.** Read-only source review; no bench, Sheet, or Cycle validation. The early break and the overwork overwrite are real. The proposed mechanism needs its hospital placement, RNG contract, shared-helper loading, and acceptance tests made explicit before build. The C101–C109 counts, POP-00801 history, and row positions in the plan are live observations supplied by the plan; source code alone cannot independently verify them. A concurrent uncommitted engine.272 edit shifted conduct's scan arithmetic to `runConductEngine.js:87-99` without changing that arithmetic; this review did not modify it.

## Findings

1. **High — the proposed RNG cap is false for the hospital branch.** The cut says the cap bounds “events and RNG draws” (`docs/plans/2026-09-21-care-and-justice-system.md:611-615`). The hospital branch precedes the proposed cap and draws for each first income hit (`phase05-citizens/runCareerEngine.js:1076-1100`, especially `:1088-1096`). A newly reachable hospitalized row after the tenth texture event can therefore add a draw and a `Career-Health` log line. The shared `roll` then feeds `applyEmployerSuccess_` (`:1299-1304`, `:425`, `:442`, `:460`), hiring contests (`:1493-1502`), and reconciliation cuts (`:1760-1765`). **Fix:** define `LIMIT` as texture-event count only; explicitly allow uncapped hospital hits and their draws. Test the draw trace and downstream employer/matcher/reconcile results with late hospital hits, including a first-hit Cycle and a subsequent Cycle where `hospitalIncomeHit_` suppresses the draw. A seeded rerun proves replayability, not preservation of former recipients or draw offsets.

2. **High — overwork must move after the hospital and hard-status gates.** The plan's “above the cap and above the tenure/xp draw” wording (`docs/plans/2026-09-21-care-and-justice-system.md:609-611`) leaves placement ambiguous. The existing row gates exclude minors, retired stages, detained/deceased/etc., and hospitalized/critical citizens before career drift (`phase05-citizens/runCareerEngine.js:1047-1102`). `emitPressureTag_` mutates `LifeHistory`, `DialState.pressure`, summary counters and a log intent (`utilities/citizenDialMap.js:443-466`). Putting it before those gates would create overwork pressure for rows that currently cannot take that path; moving it below the cap would retain the reach defect. **Fix:** keep the eligibility and hospital branches in their current order, then compute dial bands, emit overwork, re-read `existing`, apply the texture cap, and only then parse `CareerState` and do tenure/xp/event rolls. This also preserves the cut's promise that capped rows do not parse career state (`runCareerEngine.js:1102-1115`). Add negative cases for hospitalized, critical, detained, minor and retired rows and positive cases for active rows beyond the cap. The hospital `existing` read at `:1064` and `setHospitalIncomeState_` calls at `:1079-1095` remain safe only with that ordering; the metadata rewrite itself preserves other lines (`phase05-citizens/generationalWealthEngine.js:579-609`).

3. **High — the shared helper has no specified load site, so existing harnesses can fail before assertions.** The cut proposes one `rotatedScanStart_(n, cycle)` (`docs/plans/2026-09-21-care-and-justice-system.md:612-617`), while the conduct formula is currently inline, pure and zero-draw (`phase05-citizens/runConductEngine.js:83-99`). `scripts/conductEngine.test.js:47-50` and `scripts/engine32MultiCycle.test.js:83-90` evaluate the conduct file alone with selected globals. Career VM harnesses load explicit file lists, including `scripts/hospitalIncomePersistence.test.js:26-35`, `scripts/employerSuccess.test.js:317-325`, and `scripts/dialWave2Seams.test.js:23-30`. An external shared helper will be absent unless each relevant harness loads or injects it. **Fix:** name the helper's actual substrate file and add it to both conduct harnesses and every harness that invokes the career engine, including the proposed `careerEngineReach.test.js`; preserve the exact `Math.floor(Number(cycle) || 0)` and coprime-stride arithmetic, with no RNG or persisted cursor. Test conduct recipient IDs and draw counts against its pre-cut implementation, not merely that `conductEngine.test.js` stays green. The new helper must handle `n=0` consistently with both engines' early returns (`runConductEngine.js:55-57`, `runCareerEngine.js:572-574`).

4. **Medium — post-loop output changes need an explicit contract.** `sumTenure`, `sumLevel`, `careerCounted`, `industries`, and `training` increment only when texture fires (`phase05-citizens/runCareerEngine.js:1217-1226`, `:1273-1279`); `avgTenure`/`avgLevel` and `S.careerEvents` are calculated from that selected set (`:1789-1795`), not from every row reached. Rotation changes that sample. `logRows` starts with custody dismissals (`:676-682`), then gains hospital and texture lines in rotated traversal order (`:1096`, `:1251-1271`), then employer/hiring/reconciliation lines (`:1299-1312`, `:1783-1786`). Those later passes still scan or sort using physical ledger/business order (`:396-425`, `:1364-1383`, `:1453-1456`, `:1736-1759`), but their shared RNG state and log insertion order can differ. `S.careerSignals.businessDeltas` remains a downstream causal input (`phase06-analysis/economicRippleEngine.js:351-389`). **Fix:** state that the averages and industry counts remain texture-recipient summaries; assert `careerEvents <= 10`, count/log consistency, and physical `rows` identity/order. Capture log order and downstream signals in a fixed synthetic fixture before accepting the rotation. Do not turn the averages into all-citizen aggregates incidentally.

5. **Medium — the listed tests do not prove the causal reach and persistence claims.** The proposed list (`docs/plans/2026-09-21-care-and-justice-system.md:617`) could pass with a helper-only scan test and a mocked pressure emitter. The actual hospital hit requires status, admission age, positive income, a usable EconomicProfileKey, and no prior marker (`phase05-citizens/runCareerEngine.js:1076-1099`); the real income guard is `hospitalIncomeHit_` / `setHospitalIncomeState_` (`phase05-citizens/generationalWealthEngine.js:579-609`). The overwork defect requires a pressure emitter that appends to the row and then a same-row career texture (`utilities/citizenDialMap.js:443-466`; `runCareerEngine.js:1181-1187`, `:1228-1248`). **Fix:** run the full career function in an isolated VM with synthetic rows, actual pressure functions, log intents, and an isolated Business_Ledger stub; force ten earlier texture hits, put an eligible hospital row and an overwork/event row later in the scan, then assert cell, log, `DialState.pressure`, income, and second-Cycle no-repeat after a ledger round trip. A `dirty` assertion alone is vacuous because Career sets it unconditionally after the loop (`runCareerEngine.js:1282-1283`). Include `Career-Health` as a separate uncapped class. Test the exact rotated recipients and draw trace for identical inputs and for a changed row order; a source-text check or helper-only test cannot establish these behaviors.

6. **Medium — the predicted overwork count is not an invariant.** The cut predicts the first overwork `Strain` count unchanged (`docs/plans/2026-09-21-care-and-justice-system.md:615`). The existing emitter is behind the tenth-event break (`phase05-citizens/runCareerEngine.js:1032-1034`, `:1181-1183`), and pressure tagging can be claimed by a prior hood emitter (`utilities/citizenDialMap.js:443-455`; `phase05-citizens/runNeighborhoodEngine.js:539-555`). A full walk can reach eligible late rows immediately; new tags need no earlier career texture or drive growth if their DialState already meets the condition. **Fix:** replace the count prediction with a measurable bench comparison by eligible row and pressure-slot claim, and accept increases attributable to newly reached rows. Keep the `cycle + r` text seed tied to the physical row index (`runCareerEngine.js:1182`), so rotation changes visitation without silently changing a citizen's wording selection.

## Confirmed and bounded claims

- **The early-break defect is real.** The break precedes all row gates and the hospital branch (`phase05-citizens/runCareerEngine.js:1032-1036`, `:1047-1100`). The exact C101–C109 totals and POP-00801 case still require the plan's live data; this review did not read Sheets.
- **The `existing` overwrite defect is real.** It is captured before `emitPressureTag_` (`runCareerEngine.js:1063-1064`, `:1181-1183`); a same-row texture rebuilds from that stale value (`:1228-1248`). The pressure log intent and `DialState.pressure` can survive independently (`utilities/citizenDialMap.js:451-466`). Re-read the row after pressure emission, before texture append; also assert the line reaches the later dial fold, rather than accepting a log-only test.
- **The named neighboring pressure sites do not have this same overwrite shape.** Generational wealth appends from the current cell after emission (`phase05-citizens/generationalWealthEngine.js:405-412`); neighborhood returns immediately after a successful tint and otherwise reads `existing` after the emitter (`phase05-citizens/runNeighborhoodEngine.js:544-573`); migration does not later replace `LifeHistory` in that risk loop (`phase05-citizens/migrationTrackingEngine.js:267-296`). Their pressure behavior can still differ by slot/order, but these three sites do not reproduce the stale `existing` overwrite.
- **Tenure remains event-linked as stated.** It increments in temporary state before the event roll and is serialized only on the state-line roll after a texture event (`runCareerEngine.js:1102-1115`, `:1187`, `:1231-1248`). No per-Cycle tenure persistence is gained by merely finishing the scan.
