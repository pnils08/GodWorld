## Findings

1. **Written tag at the pulse call — SHIP.** `primaryTag` is assigned from entry tags, optionally retagged for a signed A's/Oaks sports week, then graded or dropped **before** any write (`phase05-citizens/generateCitizensEvents.js:3546-3575`). The only `primaryTag =` sites in this function are `:3548`, `:3555`, and `:3575`; nothing reassigns it between grading and the pulse call. The same value becomes the log's first tag, the LifeHistory bracket tag, and the helper's `writtenTag` argument (`:3648-3652`, `:3664-3676`, `:3688-3690`). The sports retag precedes `lineKind` capture and cannot make a Neighborhood pulse from a Sports kind (`:3549-3563`). A reserved grief response only replaces the selected entry before this sequence (`:3365-3371`, `:3409-3421`); it does not retag `primaryTag` afterward. Bare `Neighborhood` maps to `{}` and is graded before admission; the resolver checks the exact mapped kind before prose routing (`utilities/citizenDialMap.js:83`, `:365-384`; `generateCitizensEvents.js:1098-1103`). A selected Neighborhood line with no valid sign is skipped rather than pulsed (`:3564-3575`). `pulseKindForLine_` therefore receives the tag the writer used on this path.

2. **Apps Script global — SHIP, with deployment boundary explicit.** Repository-wide source search found one definition, `utilities/neighborhoodPulseMap.js:147-150`, and the generator call at `generateCitizensEvents.js:3690`; there is no second `pulseKindForLine_` declaration in shipped source. The helper is a top-level function beside `recordPulse_`, not a Node-only export (`neighborhoodPulseMap.js:122-155`). `.claspignore:1-25`, `:42-64` excludes Node scripts/tests but not either production file; the regenerated stub map lists the helper (`docs/engine/ENGINE_STUB_MAP.md:4483-4493`). Apps Script loads the project functions into a shared global scope before invoking the Cycle, so textual file order is not a dependency. A mismatched deployed bundle with the old pulse map and new generator would fail because the call is unguarded, but that is a deployment atomicity/readback gate, not a collision found in these commits. The harness explicitly exposes the same helper to its `new Function` generator (`scripts/testNeighborhoodLoop.js:55-58`, `:94-103`).

3. **Consumers of signed `S.neighborhoodPulse.sentiment` — SHIP.** `recordPulse_` accumulates signed effects and increments `events` once for a pulsing call (`utilities/neighborhoodPulseMap.js:96-114`, `:122-136`). The only production direct readers found are the Phase-8 writer and story seeds: the writer treats sentiment as a signed numeric sum, divides by a positive event-count reference, and clamps both positive and negative deltas (`phase08-v3-chicago/v3NeighborhoodWriter.js:278-286`, `:524-530`); `applyStorySeeds_` ranks hoods by the separate `events` field, not sentiment (`phase07-evening-media/applyStorySeeds.js:176-185`, `:900-904`). No reader found uses sentiment as a count or assumes it is nonnegative. The pulse map already supported negative sentiment on other kinds, and the existing paired writer test uses a negative raw sentiment pulse (`scripts/testNeighborhoodLoop.js:356-403`). The new kind changes a first-draw Neighborhood +1 to −1; it does not add a second `recordPulse_` invocation (`generateCitizensEvents.js:3681-3690`). Other tag/text pulse effects remain additive, so a line's *net* pulse need not equal exactly ±1 if another rule also matches (`neighborhoodPulseMap.js:96-114`).

4. **Harness true-up — SHIP-WITH-FIXES, no weakened core assertion found.** The old harness omitted globals now read by the generator, including grief/dial resolution; the true-up injects those and loads source helpers into its Apps Script-style function scope (`scripts/testNeighborhoodLoop.js:48-58`, `:72-103`). It uses the contract's seeded World_Config defaults; `hoodFloorSurfaceQuota:0` deliberately disables the GC crossing path because the fixture has no Generic_Citizens tab (`:72-80`, `:239-265`; `phase01-config/engine94SheetContract.js:566`; `generateCitizensEvents.js:2313-2336`). That limits this harness's production-path coverage but does not suppress the hood-state pulse path. C2g was split into **stricter exact hood sets**: the rent line follows the seeded pressure bar 3 in Fruitvale/Temescal/West Oakland, while the decay literal remains Fruitvale-only (`testNeighborhoodLoop.js:339-350`). Writer runs now seed all 22 writer hoods while generator-only runs keep four (`:161-195`, `:362-383`, `:443-457`), making C3/C5/C6 possible under the writer's current row contract. C6 swaps the flat comparison hood from Downtown to West Oakland but retains the same fixed-dynamics control and nonuniform/falling/nudge assertions (`:473-518`). Its introductory comment still calls that control Downtown (`:475-479`); fix the comment for clarity. The `queueAppendIntent_`/`queueBatchAppendIntent_` no-op stubs mean C5's logged-sheet component is not persistence proof (`:42-43`, `:459-469`), though ledger/map determinism and different-seed divergence remain real checks. None of these harness limits is evidence of a Cut A production regression.

5. **C7 generator proof — SHIP-WITH-FIXES.** C7a–e test the helper and accumulator directly (`scripts/testNeighborhoodLoop.js:523-534`). C7f–h then wrap the **global** `recordPulse_`, run the real generator for 60 Cycles, and inspect first-draw `source:nbhdState` pulses (`:536-562`); the call is after the written-line admission and is limited to `ev === 0` (`generateCitizensEvents.js:3563-3575`, `:3681-3690`). My local run produced **269 down-fact and 78 up-fact first-draw calls; 33 assertions passed, 0 failed**. Thus C7f makes the down path nonvacuous. But C7h checks only `seen.upAsDown === 0` without `seen.up > 0` (`testNeighborhoodLoop.js:540-545`, `:559-562`); it would pass if all up facts vanished. C7's wrapper filters only `source:nbhdState`, while the same `Neighborhood` kind can also come from `source:neighborhood` and `source:communityLife` (`generateCitizensEvents.js:1013-1019`, `:1038`). Add a positive up-count assertion and at least one emitted graded Down/Up case for each remaining source route, comparing its written primary tag with the pulse kind. The direct helper assertions alone cannot establish those generator paths. `node utilities/neighborhoodPulseMap.test.js` also passed locally; it checks map bounds and old pulse semantics, not this generator integration (`utilities/neighborhoodPulseMap.test.js:14-35`, `:69-107`).

**Gate:** land the narrow C7 coverage fixes and comment correction, then review the paired C113 bench's per-hood pulse sentiment, event counts, and saved Sentiment. This diff review does not stand in for that bench or for a deployed Apps Script readback.
