# Codex review — pipeline.77 implementation

**Target:** commit `4c476657`. **Gate: HOLD.** Source review only; no cron, model, Sheet, or live proof. The shared worktree acquired later uncommitted changes while this review ran; line references below are to the requested commit (`git show 4c476657:<path>`), except unchanged downstream files. Two release blockers are the grade's route into citizen state and the score call's ability to prevent a fresh verdict from being written. The footer and word-range issues are narrower fixes.

## 1. Gate isolation — FIX (release blocker)

The normal returned score is isolated from Rhea's verdict: `gatePass`, `draftSha256`, `flags`, and `out` are fixed before the second request (`scripts/cron-rhea-gate.js:764-790`); only `out.contractScore` is assigned afterward, and an ordinary request/parse failure becomes `contractScore.error` (`scripts/cron-rhea-gate.js:801-815`). Exit status still uses `out.pass`/`out.parseError` (`scripts/cron-rhea-gate.js:818-828`). The runner's `exactRheaProof` checks pass plus draft hash, not score (`scripts/cron-desk-run.js:84-90`).

There is nevertheless an availability and freshness breach. `callOpenRouter` has no request timeout (`scripts/cron-rhea-gate.js:283-315`), while the runner kills the gate child at 600 seconds and then reads the fixed verdict filename (`scripts/cron-desk-run.js:2990-3008`). Because the score is awaited **before** the verdict write (`scripts/cron-rhea-gate.js:807-821`), a hanging second request can turn an otherwise passing article into a flagged write if no verdict exists. If a same-name older verdict exists for identical draft bytes, the runner can instead accept it: this commit neither removes that file before invoking the gate (`scripts/cron-desk-run.js:2990-3006`) nor checks a run identity in `exactRheaProof` (`scripts/cron-desk-run.js:84-90`). Give the score call a shorter timeout and write or lock a fresh Rhea verdict before optional scoring; reject stale verdicts on child failure. The uncommitted workspace has a later stale-file/manifest patch; it is outside this target and does not cure the target's score-before-write timeout.

## 2. Rubric gaming and sourcing boundary — SHIP with bounded risk

The W3 writer sees purpose/voice/opening/closing/length and an explicit instruction that sourcing remains separate (`scripts/cron-desk-writer.js:434-446,1102`). The grade judge receives prose plus the seat contract and is instructed to grade shape, not facts (`scripts/cron-rhea-gate.js:329-349`); its response is stored under `contractScore` after Rhea's decision (`scripts/cron-rhea-gate.js:764-815`). The W1 suffix is appended to the **ask**, after `inputPacket` was built (`scripts/cron-desk-run.js:2060-2079`); W3 `known` is copied from `angleInput.known` FACTs only (`scripts/livedExperiencePacket.js:860-861,926-931`). Thus neither the score nor its critique becomes a typed FACT by this route, and the score does not alter the current sourcing verdict.

This is a typed-evidence boundary, not a guarantee that the next article's framing is unaffected: W1 `focus` and `closeQuestion` are carried as editorial plan text into W3 (`scripts/livedExperiencePacket.js:884-890`), and the judge's free-form `short` becomes the grade line (`scripts/cron-rhea-gate.js:361-363`; `scripts/cron-desk-run.js:1490-1495`). Keep watching for rubric language or unsupported claims in those fields; the Packet's source audit remains the decisive check.

## 3. Grade line on the citizen page — FIX (release blocker)

`runWrite` sends `graded: ...` through `citizenVoice --record-text` for passed **and flagged** drafts (`scripts/cron-desk-run.js:3121-3133`). `preText` bypasses voice generation but still enters the regular record block (`scripts/citizenVoice.js:169-193`): the classifier chooses an event and affect from work/media/reputation and mood vocab (`lib/reflectionClassifier.js:35-49,65-79,302-319`), writes that metadata onto the page (`scripts/citizenVoice.js:195-203`), can resolve/open tensions (`scripts/citizenVoice.js:205-225`), and appends an unapplied `Reflection_Intake` row whenever either tag exists (`scripts/citizenVoice.js:227-240`). The drain reads those rows and composes dial changes (`scripts/drainReflectionBacklog.js:43-74`; `utilities/citizenMemory.js:185-190`). This is a **possible causal path**, not proof that a particular grade receives a particular tag; no classifier call was made for this review.

Even if classification returns no tag, the page document is a normal reflection: wake recall selects from recent page documents, excluding only `type=tension` (`lib/wakePerception.js:279-299`; `scripts/citizen-wake.js:340-352`), and exchanges include recent page text (`lib/personaProvider.js:272-289`). A desk score is editorial feedback, not an experienced event or self-authored mood. Carry it to W1 through a typed, page-adjacent grade record or a page document explicitly excluded from classifier/intake/tensions and general citizen recall. At minimum skip intake; skipping intake alone still lets the grade change citizen voice through normal recall. The older `filed:` self-record path does not establish that grading a failed draft is safe.

## 4. W1 ask suffix — FIX, nonblocking after grade isolation

The suffix follows `PACKET_JSON ... END_PACKET` and its return-format instruction (`scripts/livedExperiencePacket.js:953-955`; `scripts/cron-desk-run.js:2060-2075`). It does not mutate the JSON packet. The returned plan is parsed and validated, with a second attempt on invalid output (`scripts/cron-desk-run.js:2094-2129`; `scripts/livedExperiencePacket.js:540-585`). But `validateAngleOutput` checks shape, minimum chase length, and assignment replacement; it has no rejection for an echoed `graded:` line inside otherwise valid `chase`, `focus`, or `closeQuestion` (`scripts/livedExperiencePacket.js:560-585`). This can leak critique into story §2 or W3 framing, though not into `known` FACTs. Put feedback in a typed editorial field, or reject grade echoes in plan fields.

`recentPage_(popid, 12)` is bounded by a list request of at most 36 candidates, then 12 document fetches (`lib/citizenPage.js:132-158`); its error result yields no grade, and the W1 caller catches thrown errors (`scripts/cron-desk-run.js:2068-2079`). This is nonfatal for an error response, though the underlying fetches have no explicit deadline (`lib/citizenPage.js:138-160`), so a hung network read can still consume the runner's time.

## 6. Code-based `inTarget` and body parity — FIX

Marbury's contract says `evidence-bounded; 350-600` (`scripts/newsroom-wake-packages.json:400-409`). The range parser treats **any** string with exactly one numeric range as a hard limit, and overrides the judge's `inTarget` (`scripts/cron-rhea-gate.js:320-324,351-363`). Thus an evidence-justified 601-word memo is automatically marked out of target. That is a defensible reading only if `350-600` is intended to be absolute; it discards the explicit evidence-bounded qualifier. Resolve the contract's priority and make the rule explicit before using this grade to train Marbury's next plan. Other conditional two-range contracts are left to the judge by this parser, as designed.

The counter tokenizes the same sort of word as `thinCheck`, and both stop above `## INTAKE` (`scripts/cron-rhea-gate.js:239-240,326-327`; `scripts/cron-desk-run.js:1404-1409`). They do **not** always count the same body: `thinCheck` removes fenced blocks and HTML comments, while `articleProseForReview` keeps fences (and only `contractWordCount` removes comments); whole-document fence handling also differs. The W3 writer receives the target string, not a shared counting function (`scripts/cron-desk-writer.js:438-445`). Use one article-body extraction/count for thin and shape grading, and state whether fenced text is countable.
