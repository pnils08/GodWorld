## 4. The Worker Call (`call_worker` vs `workerWake.js` & `cron-civic-run.js`)

1. **Cost & latency of one `call_worker` invocation:**
   - `workerWake.js:551-583` (`buildWake`) is a pure builder: each call runs `whoTheyAre` (builds citizen perception pool + loads dials + office map, `L111-121`), `FILLS[officeId].build` (reads up to **~5–10 live Google Sheets tabs** twice when `lean: true`: once `window: 1`, once unwindowed for `record_read`, `L563-568`), `gatherMemory` (2 Supermemory calls: `searchPage_` + `recentPage_`, `L137-141`), and `pastDecisions` (`L571`).
   - Running the worker answer (mirroring `cron-civic-run.js:3733-3779`) adds an OpenRouter tool loop of up to **6 tool calls / 8 turns** using the worker's configured model in `scripts/civic-office-map.json` (`moonshotai/kimi-k3.1-pro` for `DA-01`, `deepseek/deepseek-v4.1-flash-1017` for the other 13 lean workers), where each `record_read` / `neighborhood_read` / `sheet_read` caps results up to `6,000–7,900` chars (`workerWake.js:664,733`). One `call_worker` inside a reporter's `6`-call tool loop therefore executes an entire **nested multi-turn LLM + Sheets + Supermemory wake** per call.
2. **Can it run without writing? Only if a dedicated `call_worker` runner is written — `runWorkerDatawake` writes everything:**
   - `workerWake.buildWake` (`workerWake.js:551`) writes nothing to disk, page, or sheet.
   - However, live execution today lives in `cron-civic-run.js:3733-3824` (`runWorkerDatawake`). Calling it **without** `opts.noWrite = true`:
     - **Overwrites the worker's weekly report file:** `fs.writeFileSync(path.join(DATAWAKE_DIR, office.agentDir + '_' + o.date + '.json'), ...)` (`:3807-3809`). Because `w.lean` is `true` even when `question` is set (`workerWake.js:561`), `:3790` stamps `rec.template = 'worker/2'`, so `workerWake.lastReport` (`:519-533`) and `buildCivicDomainSlice.js:539-551` treat the reporter-Q&A file as the worker's canonical weekly report! (Note `buildWake` itself only suppresses reading `lastReport` when `question` is passed at `:572`, not saving it.)
     - **Writes to the citizen's Supermemory page:** `officeWall.recordPosition(rec.popid, 'datawake: ' + statement, { key: 'datawake-' + o.date, kind: 'datawake', ... })` (`:3815-3816`).
     - **Moves citizen dials:** On `positionWall.recorded === true`, `:3819` calls `queueJobStatement(rec.popid, rec.cycle, 'CIVIC', statement, 'worker ' + rec.agentDir)` (`:85-89`), which `flushJobStatements()` (`:91-104`) classifies and appends to live **`Reflection_Intake`**.
     - **Stages Police Chief patrol moves (`CHIEF-POLICE`):** `workerWake.toolsFor(officeId, opts)` (`workerWake.js:629-630`) always includes `patrol_set` (`LEVER_TOOLS.patrol`) for `CHIEF-POLICE` even if `opts.records` / `question` is active, and `runWorkerDatawake:3780-3786,3808` validates and appends moves to the move ledger.
