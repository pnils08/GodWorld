## 1. Containment — FIX

The checked-in registry gives `writerTools.maxToolCalls: 6` only to `elliot-marbury` (`scripts/newsroom-wake-packages.json:367-380`; `scripts/newsroomWakePackages.test.js:165-170`). The normal write runner derives the option from the active package only when `PACKET_ACTIVE`, and a persona-less direct runner call has no active package unless an explicit evaluation package is selected (`scripts/cron-desk-run.js:155-170`, `:2724-2729`, `:2868-2873`). Fan-out package gating supplies the persona (`scripts/newsroomWakePackages.js:100-115`). The writer rejects `--writer-tools` with `--tools-ab` or without `--packet-only` (`scripts/cron-desk-writer.js:804-808`). Its absent/zero value stays zero through `resolveMaxToolCalls` and `maxToolCalls: PACKET_ONLY && !TOOLS_AB ? WRITER_TOOLS : 6`, so ordinary typed packets offer no tools (`scripts/cron-desk-writer.js:232-235`, `:698-717`, `:1163-1168`). The exceptional toolset has no `memory_note` (`:1167-1170`).

The **one-journalist** boundary is configuration, not a writer invariant: `validatePackage` accepts `writerTools` on any package if the number is 1–8 (`scripts/newsroomWakePackages.js:38-42`), and a direct writer invocation with any typed Packet and `--writer-tools 6` passes the writer's guard without checking Elliot, the package version, or the packet actor (`scripts/cron-desk-writer.js:232-235`, `:804-805`). Thus another configured package or direct packet-only caller could gain this capability. Bind the exception to the authorized package/actor at the writer boundary as well as at the runner.

## 2. Tool-line evidence boundary — HOLD

`selectUsedToolLines` accepts an **entire** candidate line if any numeric token absent from the original manifest occurs anywhere in both line and Article, or if any five consecutive line words occur in the Article; it does not join player, season, claim, or source (`scripts/livedExperiencePacketV2.js:597-622`). In-memory synthetic probes admitted an unrelated line about `3 awards` from an Article's `3 hits`, and a line containing `7 awards` because both shared the generic phrase “the season line does not say” (no `7` in the Article). `appendToolFacts` then adds the whole admitted line as `FACT` to `known` and `manifest.approvedFacts` (`:624-639`), enlarging the numeric allowance used by the audit (`:647-657`). The claim that only lines actually used cross the boundary is therefore false.

`canon_search` is especially broad: it searches `output/`, `docs/`, and `editions/`, including staged output, and returns snippets plus a match-count header (`lib/mags.js:576-598`, `:611-645`, `:664-681`; `scripts/cron-desk-writer.js:499-500`). The writer splits every result line into a candidate with `tool:canon_search:<query>` provenance (`scripts/cron-desk-writer.js:1243-1249`). A matching prior-coverage or staged-draft snippet, possibly containing a name or quoted speech, can thus become an approved FACT without a canon/source-class check. For a packet with *some* approved quote, the audit accepts quoted words found anywhere in approved FACT text even if the quote itself is absent from `approvedQuotes` (`scripts/livedExperiencePacketV2.js:658-676`). An in-memory synthetic packet with one unrelated approved quote and a selected `canon_search` FACT containing different speech returned `auditArticle.ok: true` and no `UNAPPROVED_QUOTE`. With **no** approved quotes, a five-word-or-longer speech span remains blocked (`:670-674`); Elliot's first-run manifest has none (`output/cron-compare/sports_c111_elliot-marbury_packet-v2_anthropic-claude-sonnet-5-5.state.json:455`). Rhea has a separate model speech check and may still flag such a draft (`scripts/cron-rhea-gate.js:424-440`), but the deterministic boundary has been bypassed. Require claim-specific matches and source-class validation; never promote a retrieved quote as speech through `approvedFacts`.

## 3. Manifest amendment and downstream proof — FIX

`appendToolFacts` strips standard `(POP-12345)` and bare `POP-12345` tokens from fact **text**, makes claim IDs from text and source, recomputes `manifest.id`, and runs W3 `assertBase` (`scripts/livedExperiencePacketV2.js:52-55`, `:65-106`, `:624-644`). The writer writes the amended state before INTAKE rendering and its first audit; the repair pass re-audits against the same in-memory amended packet (`scripts/cron-desk-writer.js:1234-1269`, `:1306-1315`). `runWrite` reloads that state before local checks and passes its path to Rhea (`scripts/cron-desk-run.js:2885-2898`, `:2957-2967`). Rhea records the amended ID, and the staged sidecar copies Rhea's ID (`scripts/cron-rhea-gate.js:320-343`, `:726-731`; `scripts/cron-desk-run.js:93-101`, `:3019-3027`). INTAKE and story-doc paths do not key on the old ID (`scripts/cron-desk-run.js:2701-2719`, `:3115-3120`).

The remaining proof gap is that `exactRheaProof` compares **only the Article hash**, not `rhea.reviewProfile.manifestId` with the current state manifest (`scripts/cron-desk-run.js:84-101`, `:2969-2973`). If a gate invocation fails and an older same-Article verdict remains at the fixed verdict path, a changed manifest could be staged under that verdict; the sidecar would merely copy the older ID. Bind the pass proof to the amended manifest ID (or its state hash) and require a fresh verdict. This was not observed in the first run.

## 4. `dossier_read` matching and duplicate facts — FIX

The dossier tool tries exact name, then the **first** card whose name contains the request or vice versa, without a uniqueness check (`scripts/cron-desk-writer.js:614-629`). `Ramos` currently matches only Arturo Ramos in the mirror, but the short query `Mar` currently matches Mariano Rosales, Mark Aitken, and Martin Richards; the first wins by mirror order. A partial request can therefore return a different card from the intended player. Require an exact name or a unique verified alias; return ambiguity instead of choosing the first card.

The subject's season and rate lines use the same `buildMarburySlice.seasonLine`/`rateLine` functions as the slice (`scripts/cron-desk-writer.js:619-633`; `scripts/buildMarburySlice.js:75-95`, `:113-123`). A read-only comparison found the 2041 Martin Richards season text byte-for-byte equal. The tool source is `tool:dossier_read:Martin Richards:2041` while the slice source is `output/player_truesource_mirror.json Martin Richards`, so `claimId(text,src)` differs and `appendToolFacts` can add a second ID for that same fact (`scripts/livedExperiencePacketV2.js:52-55`, `:624-639`). Peer lines are **not** byte-for-byte equal: the slice prefixes `Peer —` while the tool does not (`scripts/buildMarburySlice.js:131-136`; `scripts/cron-desk-writer.js:628-633`). The first run happened to add six older Richards lines absent from its initial six-season slice, with no exact-text duplication (`output/cron-compare/sports_c111_elliot-marbury_packet-v2_anthropic-claude-sonnet-5-5.state.json:187-221`). Deduplicate by normalized fact identity and original dossier source, not claim ID alone.
