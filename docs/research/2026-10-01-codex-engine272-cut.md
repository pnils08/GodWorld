# engine.272 cut — adversarial mechanism review

**Scope and verdict:** Read-only review of Mechanism 1–9, Tests, and Deploy at `docs/plans/2026-09-21-care-and-justice-system.md:573-593`. **HOLD for the mechanism as written.** No ruling here on condition A versus B. The cut is a design, not installed code; the failures below are paths the proposed implementation or acceptance must close.

## Findings

1. **P1 — rate 0 still schedules a DialState rewrite, so “off” is not byte-identical.** Mechanism 3 defines `wearDue` from condition/base or `wear.d`, without a `rate > 0` guard (`docs/plans/2026-09-21-care-and-justice-system.md:578`); Mechanism 8 seeds 0 (`:584`). Adding that term to both fold gates makes a quiet condition-true row pass `compressLifeHistory.js:525`, deserialize at `:530-531`, settle at `:543`, serialize at `:640`, and mark the ledger dirty at `:645-648`, although `take = min(0, …) = 0`. The serialized JSON can differ from an old cell even when numerical dials do not: `deserialize_` builds all dial keys (`citizenMemory.js:65-71,255-268`) and `serializeDialState_` emits a normalized object (`compressLifeHistory.js:1243-1249`). **Fix:** validate/read rate before calculating `wearDue`; only make wear a reason to enter the RMW when `rate > 0` and the pure step would actually move. Preserve the old cell if no other path needs it. Test a quiet, valid but noncanonical old DialState string at rate 0, asserting exact bytes and `ledger.dirty === false`.

2. **P1 — a missing or invalid wear key can skip the Phase-9 fold while the Cycle commits.** `inspectEngine94Config_` accepts a seed of 0 when its minimum is 0 (`engine94SheetContract.js:405-422`), and `loadConfig_` retains numeric zero (`godWorldEngine2.js:644-660`), so the seed pattern itself is viable. But both engine paths wrap `compressLifeHistory_` in `safePhaseCall_` (`godWorldEngine2.js:529,2213`); that wrapper catches an exception, logs it, and returns false (`:159-168`), after which Phase 10 still commits (`:574-576,2253-2256`). A missing-key throw *inside* the fold therefore does not fail the Cycle and Mechanism 5 explicitly forbids catch-up (`docs/plans/2026-09-21-care-and-justice-system.md:580,584`). **Fix:** wire the new self-arm ensure into the live pre-cycle sequence beside `ensureEngine176Config_` (`godWorldEngine2.js:220-233`) and make its validation fail before time advances; add a full-entry-point test proving an absent/invalid key cannot commit a Cycle. Read the configured 0 with an explicit finite-number check, never a truthy default. The dry-run entry point (`:1779-1819`) does not run ensure functions and `compressLifeHistory_` exits on dry-run (`compressLifeHistory.js:348-354`), so it cannot prove this production gate.

3. **P1 for B / P2 for cohort contract — sharing the row predicate alone does not make wearers the conduct cohort.** Conduct also requires a usable DialState: `getCitizenDialBands_` returns null for empty or base-less cells (`compressLifeHistory.js:1153-1164`), and conduct skips on that result (`runConductEngine.js:203-208`). Mechanism 6 copies only the inline status/tier/clock/age tests (`docs/plans/2026-09-21-care-and-justice-system.md:581`; `runConductEngine.js:187-201`). In the fold, parsing an empty cell yields `{}` (`compressLifeHistory.js:1230-1236`), while `deserialize_` seeds a neutral base (`citizenMemory.js:65-71,255-256`). Under B, a qualifying row with no DialState can therefore be initialized and worn despite being unable to enter a conduct test; under A, that row cannot acquire a `pressure[cause].l` record (`citizenDialMap.js:423-426`). **Fix:** require an existing parsed `base` for wear, or explicitly extend conduct eligibility and account for initialization. Add a no-DialState and malformed-DialState fixture to the cohort equivalence test. Also test a status change after conduct but before the Phase-9 fold: the two calls occur at different points in both entry points (`godWorldEngine2.js:369,529,2061,2213`), so equal predicates on different row snapshots are not automatically equal populations.

4. **P2 — Node loading of the new shared helper needs explicit wiring in both tests.** The proposed location is beside `getCitizenDialBands_` in `compressLifeHistory.js` (`docs/plans/2026-09-21-care-and-justice-system.md:581`). The real conduct test loads that module through `require` but exports only `getCitizenDialBands_` to `global`, then evaluates `runConductEngine.js` through `new Function` (`scripts/conductEngine.test.js:17-25,48-49`); an unexported/uninjected `conductCohortRow_` is undefined there. The compressor test likewise imports its own globals but its minimal ledger has no Tier, ClockMode, status, or birth-year columns and its context has no config or `simYearOf_` (`scripts/compressLifeHistory.dial.test.js:18-30,50-59`). **Fix:** export the helper from the compressor, inject it into the conduct harness, and give fold tests the real cohort columns, sim-year source, and wear config. Preserve the current `runConductEngine_` inclusion/exclusion order and RNG draws when replacing the inline check.

5. **P2 — `pressure[cause].l` is written before Phase 9 for admitted causes, but not for every cause that held.** The call order is Neighborhoods, Career, GenerationalWealth, MigrationTracking, then the Phase-9 fold in both entry points (`godWorldEngine2.js:355-395,529,2047-2087,2213`). `pressureRunFromState_` updates `l` before the adaptation return (`citizenDialMap.js:423-455`), so adapted admitted causes are visible. However rent and hood share `housing` (`:391-394`); `emitPressureTag_` returns before that state update when the slot was claimed (`:443-451`). For example, a hood tag admitted earlier prevents a later qualifying rent burden (`runNeighborhoodEngine.js:543-548`; `migrationTrackingEngine.js:259-272`) from setting `pressure.rent.l` this Cycle. The reverse can occur if the hood path did not emit: its pressure tint is behind a drift opportunity (`runNeighborhoodEngine.js:470-486,543-548`). **Fix:** specify whether `l` means an *admitted pressure emission* or a *holding condition*. If the latter, record each cause's held status before shared-slot suppression, while keeping the one-tag limit; if the former, describe and test the undercount explicitly. With both hood and rent counted, the winning housing cause still makes the `any` predicate true; this finding concerns the per-cause claim and any future cause-specific selection, not a demonstrated missed wear step in the default A set.

6. **P2 — the Deploy readback expects unrelated DialState bytes to stay fixed across a normal Cycle.** The plan says “the rest byte-identical” (`docs/plans/2026-09-21-care-and-justice-system.md:593`). Existing Phase-5 `pressureRunFromState_` writes DialState (`citizenDialMap.js:437-439`), Maneuver writes it (`maneuverEngine.js:297-303`), and Phase 9 rewrites it for new entries or mood even without wear (`compressLifeHistory.js:513-530,640`). **Fix:** compare a bench trial against a same-input rate-0 control and assert that the *incremental wear effect* is confined to due rows. Separately assert exact bytes for truly quiet, no-step rows. Avoid attributing unrelated normal Cycle writes to wear.

## Claims checked without a separate finding

- Mechanism 1's mood decay and three-push hardening references are supported (`citizenMemory.js:36-38,110-129,201-206`). The pure step belongs on `base`; only the proposed function remains to be built.
- Mechanisms 2 and 5 require adding `wear` to **both** the `deserialize_`/`serialize_` path (`citizenMemory.js:249-268`) and the production `serializeDialState_` path (`compressLifeHistory.js:1243-1249`). The direct Cycle writers found by a DialState read/write search either use those functions (`chaosCarsEngine.js:396-400`) or parse and stringify the complete object (`citizenDialMap.js:427-439`, `maneuverEngine.js:285-303`); no separate active normalizer was found that necessarily drops a new field. Explicit reseeding scripts such as `scripts/backdateCitizenDials.js:144` and `scripts/seedTier1EssenceLive.js:148` overwrite DialState by design and must not be used as a wear-preserving repair.
- Mechanism 4's `settleCycle_` then `foldNewEntries_` slot exists (`compressLifeHistory.js:540-554`); the fold uses the shared row state and is after Phase 5 in both entry points. Mechanism 9 does not need changes to band cuts or conduct odds for this cut (`citizenMemory.js:46-49`; `runConductEngine.js:82-84,211-275`).
