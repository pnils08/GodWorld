## Part 2: engine.196 Holiday Sentiment Scale (`78f5727b`)

### 2.1 Hunt: Is First Friday Really Excluded?
- **Analysis of Implementation:**
  In [`phase02-world-state/applyCityDynamics.js#L386-L444`](file:///root/GodWorld/phase02-world-state/applyCityDynamics.js#L386-L444):
  ```javascript
  var moodStart = m.sentiment;
  // ...
  var moodPreFF = m.sentiment;
  if (isFirstFriday) {
    // adds +0.25 (Downtown Core), +0.15 (North Hills), +0.10 (others)
  }
  var ffMood = m.sentiment - moodPreFF;
  // ...
  // Holiday blocks run, modifying m.sentiment
  // ...
  var holidayMood = (m.sentiment - moodStart) - ffMood;
  m.sentiment = moodStart + ffMood + holidayMood * HOLIDAY_MOOD_SCALE;
  ```

- **Algebraic Proof of First Friday Isolation:**
  Let $S_0$ be `moodStart`.
  Let $\Delta_{FF}$ be the sentiment delta added by First Friday.
  After First Friday executes:
  $$S_{FF} = S_0 + \Delta_{FF}$$
  `ffMood` is evaluated as:
  $$\text{ffMood} = S_{FF} - \text{moodPreFF} = (S_0 + \Delta_{FF}) - S_0 = \Delta_{FF}$$
  Next, holiday logic executes, adding delta $\Delta_{\text{holiday}}$.
  $$S_{\text{holiday}} = S_{FF} + \Delta_{\text{holiday}} = S_0 + \Delta_{FF} + \Delta_{\text{holiday}}$$
  `holidayMood` is evaluated as:
  $$\text{holidayMood} = (S_{\text{holiday}} - \text{moodStart}) - \text{ffMood} = (S_0 + \Delta_{FF} + \Delta_{\text{holiday}} - S_0) - \Delta_{FF} = \Delta_{\text{holiday}}$$
  Finally, `m.sentiment` is assigned:
  $$S_{\text{final}} = \text{moodStart} + \text{ffMood} + (\text{holidayMood} \times \text{HOLIDAY\_MOOD\_SCALE}) = S_0 + \Delta_{FF} + 0.6 \times \Delta_{\text{holiday}}$$
  
- **Verdict:** First Friday's delta $\Delta_{FF}$ carries a scalar multiplier of exactly $1.0$. It is completely excluded from `HOLIDAY_MOOD_SCALE` (0.6).

### 2.2 Hunt: Can the Delta Math Double-Count?
- **Algebraic Verification of Boundary Cases:**
  - **Case A: First Friday with NO Holidays Active ($\Delta_{\text{holiday}} = 0$):**
    $$\text{holidayMood} = (S_0 + \Delta_{FF} - S_0) - \Delta_{FF} = 0$$
    $$S_{\text{final}} = S_0 + \Delta_{FF} + 0.6 \times 0 = S_0 + \Delta_{FF}$$
    *Result:* Exact identity. No double-counting or attenuation.
  - **Case B: Holiday Active, NOT First Friday ($\Delta_{FF} = 0$):**
    $$\text{ffMood} = 0$$
    $$\text{holidayMood} = (S_0 + \Delta_{\text{holiday}} - S_0) - 0 = \Delta_{\text{holiday}}$$
    $$S_{\text{final}} = S_0 + 0 + 0.6 \times \Delta_{\text{holiday}}$$
    *Result:* Exact scaling by 0.6.
  - **Case C: Neither Active ($\Delta_{FF} = 0, \Delta_{\text{holiday}} = 0$):**
    $$S_{\text{final}} = S_0$$
    *Result:* Unchanged.
- **Verdict:** The decomposition is strictly linear and orthogonal. Double-counting is mathematically impossible.

## Part 3: engine.249 Hood Demographics Migration Split (`c15e4d3e`)

### 3.1 Hunt: Rounding Drift vs. Applied Total
- **Macro Level (City Migration $\to$ Hood Aggregates):**
  In [`phase03-population/updateNeighborhoodDemographics.js#L137-L157`](file:///root/GodWorld/phase03-population/updateNeighborhoodDemographics.js#L137-L157):
  ```javascript
  var appliedMigration249 = Math.round(cityMigration249 * (tableTotalPop249 / cityPop249));
  // ...
  var neighborhoodMigration = Math.round(appliedMigration249 * (popWeight249 / sizeWeightSum249));
  ```
  - `sizeWeightSum249` is the sum of `popWeight249` across all 22 tracked neighborhoods.
  - Because each hood's allocation is independently rounded to the nearest integer (`Math.round`), $\sum_{i=1}^{22} \text{neighborhoodMigration}_i$ may deviate slightly from `appliedMigration249`.
  - Maximum theoretical drift across 22 roundings is $\pm 11$ people; empirically in bench test runs (SANDBOX C139), total table change was +345 heads against applied migration of 348 heads ($\Delta = -3$ heads citywide, or $\sim 0.003\%$).
- **Micro Level (Hood Migration $\to$ Age Buckets):**
  In [`phase03-population/updateNeighborhoodDemographics.js#L172-L177`](file:///root/GodWorld/phase03-population/updateNeighborhoodDemographics.js#L172-L177):
  ```javascript
  var deltaS = Math.round(neighborhoodMigration * mixS);
  var deltaA = Math.round(neighborhoodMigration * mixA);
  var deltaSr = Math.round(neighborhoodMigration * mixSr);
  var totalDelta = deltaS + deltaA + deltaSr;
  ```
  - Because `mixS + mixA + mixSr === 1.0`, the sum of three independent rounded integers ($\text{round}(x) + \text{round}(y) + \text{round}(z)$) can differ from $\text{round}(x + y + z)$ by $\pm 1$ head.
  - Total hood population is updated by summing the new bucket values:
    `demo.totalPopulation = demo.students + demo.adults + demo.seniors;`
  - Consequently, a hood's recorded delta can differ from `neighborhoodMigration` by at most $\pm 1$ person.
- **Verdict:** Both macro and micro rounding drifts are bounded integer rounding effects standard to the simulation. Because hood totals are recomputed as the sum of their age buckets, no ghost headcount or arithmetic drift leaks into downstream sheets.
