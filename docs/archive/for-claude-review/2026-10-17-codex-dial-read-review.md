# Verdict: FIX the diagnosis; a confirmed future watermark blocks 13 citizens

Read-only source/dump review; only this file written. No cron, model, Sheet, bench, canon, migration, or deployment ran. Local JavaScript VM probes loaded the three pure dial/compressor source files in memory, with synthetic histories or saved rows; Python/Node counted JSONL records. These are bounded mechanism checks, not live replay or full-suite evidence. Existing dirty output and the plan were untouched.

**Evidence age matters:** `output/simulation_ledger_snapshot.meta.json:3–5` is C111 generated October 11; `output/beats/meta.json:3,34` is C111 generated October 14. The reflection dump does not reproduce its later totals; absence from this dump is not proof of absence today.

## Hunt 1 — the three ruled-out causes: SHIP narrowly, FIX the universal claims

- **1a SHIP for the actual fold, FIX “either way.”** `phase05-citizens/generateCitizensEvents.js:3504–3530` writes `[primaryTag]` to the citizen cell and the composite tag to LifeHistory_Log. Phase 9 parses the cell (`compressLifeHistory.js:537,554–556,1627`), not the log. Known routine tags return their explicit empty map before content routing (`citizenDialMap.js:64–83,170–182,315–337`). Removing the suffix therefore does not starve the approved objective path. However, full composite tags do **not** map identically: `baseTag_` only removes recognized calendar suffixes (`:287–298`), not `|source:...`. Pure probe: `Neighborhood` + “neighbor” → `{}`; `Neighborhood|source:x|neighborhood:West` → `{sociability:3,warmth:2}`. Smallest correction: say the composite log is not the fold's input, not that both inputs are equivalent.
- **1b SHIP for the reported suffix collision; FIX “only reached” as a general assertion.** `CONTENT_RULES` at `citizenDialMap.js:274` cannot see a log-only `neighborhood:` suffix in the current cell fold. The parser preserves whatever bracket tag it receives (`compressLifeHistory.js:818–829`); it does not itself strip composites. Unknown tags and legacy/untagged prose also reach `:334–337` and can match neighbor/community text without any full log tag. The active snapshot's parsed cell entries contain **zero composite bracket tags**. Thus this suffix is not an observed explanation for the stuck cells; the fallback still exists.
- **1c FIX, high — correct conversion does not establish correct stamps.** `advanceSimulationCalendar.js:48–55,200,293–299` produces the absolute-cycle/year-of-year relation; `compressLifeHistory.js:818–823`, `citizenDialMap.js:394–400`, and `lib/citizenDials.js:89–94` invert it. Y3C7 correctly means 111. But `scripts/migrations/engine57_spouse_backfill.js:187` hardcodes **Y3C29**, meaning **133**, into spouse histories. The C111 snapshot has **13 active citizens with folded=133**, POP-01029 through POP-01041 (`output/simulation_ledger_snapshot.jsonl:860–872`), each carrying that line. The filter at `compressLifeHistory.js:556` accepts any cycle above the watermark, without `<= currentCycle`; `:1636–1638` advances to that future value. All later stamped events at C111–C133 are consequently skipped, regardless of their real causes. This is an observed blocking mechanism, not an inferred reflection shortage.
- **Smallest safe repair proposal:** reject/report future event cycles before folding or advancing the watermark, fix the migration's stamp producer, and prepare a separately authorized, receipt-backed repair of the 13 histories/states from their actual history. Do not merely lower folded and replay already-applied entries: that can double count. Preserve the recorded marriages; repair the engineering clock error, not the citizens' lives.
- **Other stamp boundaries checked:** regular generators use absolute `cycleId`/`absoluteCycle`/`config.cycleCount` for LifeHistory_Log.Cycle (`generateCitizensEvents.js:377,3523–3532`; `generateGameModeMicroEvents.js:67`; `runCareerEngine.js:815`; `runRelationshipEngine.js:558–566`; `runHouseholdEngine.js:166,555–590`). Milestones use `C` + absolute cycle in the cell and `inWorldStamp_` in the log (`generationalEventsEngine.js:1722–1735`). `archiveLifeHistory.js:94–114` repairs wall-clock Timestamp, not Cycle. Across the saved 5,350 log rows, no Y-stamp/structured-Cycle mismatch was found. That log window does not cover every historical migration.
- Reflection producers persist the absolute Node cycle, not a Y-stamp: wake `:295,448–451`, voice `:287,238–241`, exchange `:416,192–195`, work-wake `:312,300–303`; all resolve through `lib/getCurrentCycle.js`. The drain (`compressLifeHistory.js:289–312`) **does not use intake Cycle for eligibility**, so a reflection cannot set folded. The other folded producers are `backdateCitizenDials.js:150–152` and `seedTier1EssenceLive.js:156`, both taking the maximum parsed cell cycle; they can preserve/amplify a bad future stamp. `engine57_kids_backfill.js:36` emits Y(next)C0 on multiples of 52: noncanonical formatting, but the current inverse still recovers the same absolute number. Do not confuse that cosmetic boundary discrepancy with the spouse migration's 22-Cycle lead.

## Hunt 2 — real events reaching base: SHIP mechanism; HOLD historical attribution

- **The path is live:** new stamped cell entries bypass the five-Cycle face cadence (`compressLifeHistory.js:531–556`); settle precedes fold (`:604,622`); events are netted once per dial per distinct Cycle (`:1620–1638`). `applyCycleEffects_` resets reinforcement if residual mood is zero or opposite-sign; `applyEvent_` adds room-scaled mood, then hardens on the third same-sign push (`citizenMemory.js:108–152`). Settle multiplies ordinary mood by 0.8 and zeros magnitude below 0.5 (`:205–210`); fandom uses 0.9. Room at base/current 50 is available, not a dead gate (`:87–99,128–131`).
- **Minimum ordinary stamped pattern from neutral:** three nonzero net pushes on the same dial in three distinct Cycles, retaining same-sign residual mood until each next push and at hardening. Three same-Cycle Household lines are only one reinforcement. Consecutive Cycles are sufficient, **not necessary**. Pure probes with settle before each Cycle: Household at C1/C2/C3 → family **54.4768**; C1/C10/C19 → **52.27077523598536**; C1/C12/C23 → **50** because each isolated +5 fades below 0.5 before the next push. Strain at C1/C2/C3 → composure **49.0405376**. Promotions at C1/C2/C3 → drive **56.7954688**.
- A **single Birth or Wedding leaves base 50**, while family mood becomes +10 (warmth +4; Wedding also composure +2). This is what the implemented physics says, even for a major life event. It is not proof the fold failed. Three lifetime family lines, a spouse, or children do not establish the required timed pattern. Ruling 1b does not authorize restoring ambient tag nudges merely to increase base movement; doctrine §§1–2,7–8 calls for causal physics and preserved outcomes.
- **Saved-row test:** replayed each active citizen's retained stamped cell entries, netted by Cycle with intervening settles, from a synthetic neutral baseline through C111. No family-base-50 citizen had a retained pattern that hardened family in this probe. Amara POP-00002 has only C107 `Maneuver-Retreat` + `Household` as family-affecting stamped entries in her retained cell; Mags POP-00005 has none. Their lifetime/log family counts are not equivalent to available fold input.
- **Counterexamples to blanket starvation:** POP-01031 (`snapshot:862`) retains debt Friction C107 + Strain C108–C111, composure/outabout bases both 50, folded 133. The replay yields composure 48.447242125312 and outabout 49.0405376; the future watermark is a concrete reason current entries cannot reach base. Two further candidates, Devon Willis POP-00782 outabout (`:615`) and Rafael Phillips POP-00958 composure (`:788`), stay 50 although a neutral replay of their retained rows hardens those dials. **HOLD their cause:** actual starting mood/streak, historical code, prior folds, legacy folds and reflections are not reconstructed by this probe. It is not valid to call them proven production fold failures solely from that replay.
- **Additional fold limitation:** `foldNewEntries_` applies multiple historical Cycle buckets without settling between them; the caller settles once for the present invocation. A first fold/backlog can over-reinforce compared with timely per-Cycle processing. A same-Cycle late append is also behind an already-equal watermark. Those are source-confirmed limitations, not demonstrated causes of the citywide percentages. Fix requires chronological/receipt-aware replay, not a faster hardening constant.

## Hunt 6 — added 2026-10-17 at the builder's request: FIX the weighting premise; SHIP the bottleneck finding

- **Ordinary rotation probability for an all-current-50 citizen is zero, not minimum weight.** `lib/wakePerception.js:26,405–412` rejects deviation <60 before selection, unless a supplied lived-event recipient is included and marked `livedOnly`. `citizen-wake.js:203–207` excludes livedOnly from rotation. The minimum admitted rotation weight is therefore **2.2** when eventMag=0 and deviation=60, not 1. All-base-50 is distinct from all-current-50 because current includes mood. Local measurement: **205** active citizens have all nine bases 50; none reaches the shaped floor (maximum current deviation **16.9152**); only **12** have all nine *current* values exactly 50. All 205 are currently outside ordinary rotation in this snapshot, subject to the separate lived-event route.
- **Estimate for shaped citizens:** conditional on reaching rotation and being in its eligible candidate set, weighted-draw mass is approximately `(1 + 2*eventMag + deviation/50) / sum(weights)`. For equal eventMag=0, deviation 120 versus 60 has weights 3.4 versus 2.2, a **1.545×** ratio; an equal-weight set of N eligible shaped citizens has approximately 1/N each. These are code-derived draw proportions, not measured wake frequencies: `_hash53` is deterministic for `(cycle, WAKE)` and selection uses a finite grid (`citizen-wake.js:209`), while candidate membership changes. There is no defensible single “once every N days” estimate without slot/rotation state and event arrivals. Default ordinary chance for an all-50 citizen remains 0 regardless of these weights.
- **Other slots do not make that a minimum-weight case.** The voiced slot also excludes livedOnly (`citizen-wake.js:175`); posture selection explicitly requires `!p.livedOnly` (`:196`). A below-floor citizen with a posture change but no admitted lived event is absent from the pool. The recent-reset at `:205` restores **shaped** candidates only, never the excluded city. The lived slot precedes posture/rotation but follows voiced (`:173–191`): an eligible under-floor adult with an unspent event can be picked outright when `pickLived` reaches them, without any dial weight. Its window, seven-per-Cycle budget, birth-household deduplication, age check, and deterministic kind/Cycle/id order apply (`wakePerception.js:655–658,761–777`). `--pop` only works for a citizen already in the assembled pool (`citizen-wake.js:166–169,300–305`); it is not a general threshold bypass.
- **Feedback loop confirmed, inevitability refuted.** Neutral citizens cannot use ordinary rotating reflections to escape the threshold, while admitted citizens can accrue base through reflections. But “writes no reflection and stays at 50” is not universal: lived-event admission, zero-floor PRESS/exchange paths, work packs, objective hardening, wear and other base writers remain. The 1,145 PRESS rows in the older active intake subset are especially important. Smallest proposed design correction: address the **pool admission rule** if ordinary neutral-citizen reflection access is intended; changing `deviation/50` alone cannot admit anyone. Do not prescribe an output quota or increased event frequency to meet a dial-distribution target.
- **Typed metadata loss is real; “none of the life reaches the wake” is false.** The extra JSON parse at `wakePerception.js:414–415` retains only base and maneuver, but `:407` already reads **base+mood for all nine dials**, including numeric fandom. The pool exports `cur`, `baseDials`, selected LifeHistory, MemoryRegisters, archetype, standing, household and financial record (`:431–449`). It does **not** export `DialState.grief`, `debtDefault`, `fan` (team identity), `pressure`, `wear`, or `lifeEvent` envelopes, and no direct consumers of those envelopes were found in this wake/prompt path. Thus duration/receipt/team/causal-state detail can be lost even when its numerical effect survives in current disposition.
- **Indirect paths must be counted:** `renderStanding` turns retained pressure/event tags into prose through `dials.thrown` (`wakePerception.js:594–597`; `citizenDials.js:78–119`); `renderOwnRecord` reads current DebtLevel/income/home (`wakePerception.js:505–529`); the prompt includes that record and the history tail (`citizen-wake.js:253–256`). Family, health, bonds, latest milestone, card, private page and lived-event lines are separately loaded (`:310–345`). A bereavement can arrive as a lived death-survivor line; a default as a retained Money line; sports involvement as fandom disposition/history/feed. None guarantees the original metadata's team, onset, duration or pressure receipt is conveyed. Proposed fix: explicitly project whichever missing state is needed into bounded citizen-readable inputs, with provenance and expiry, rather than claim an already-present story channel is absent.
- **SHIP — neutral-dial omission, with exact bounds.** `citizenDials.js:16–17,49–58` omits a dial for **40 ≤ current <60**; 60 already gets the upper phrase. When every dial is neutral, it returns the literal **“even-keeled, unremarkable”**, not an empty disposition. Pure checks: family 39.99 → “keeps family at arm's length”; 40/50/59.99 → no family phrase; 60 → “close to family.” This suppresses small identity differences in the temperament wording but not the other factual prompt inputs.

**Updated final gate:** retain Hunts 1–5 dispositions; add FIX for any proposal that only reweights the existing rotation pool or asserts the wake consumes these typed metadata fields.
