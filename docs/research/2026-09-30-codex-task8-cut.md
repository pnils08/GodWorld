# Task 8 cut — adversarial review

**Verdict: HOLD the cut before implementation.** The separate phase placement is sound, but the proposed post-write replay reconstruction suppresses current receipts, and ordinary judicial exits cannot pass the current census builder. The bootstrap and missing-scope rules also need explicit, testable decisions. This is a review of the written cut at `c1610e45` against current code; no engine change or live run was made.

## Findings, ordered by consequence

1. **Blocker — contradicted: post-write `seenKeys` makes new ledger-backed movements disappear.** Task 8 builds keys from *freshly read* ledger columns after both writers, then passes the same Cycle's receipts to `buildCareJusticeCensus_` (`docs/plans/2026-09-21-care-and-justice-system.md:600-605`). The fold drops every key already in `seenKeys` (`utilities/careJusticeAccounting.js:75-95,172-180`). Thus a successful new hospital intake, judicial intake, or judicial exit is pre-marked as replay; the movement is zero while the open-row snapshot has changed, producing `incomplete` rather than a truthful count. Restricting keys to older row cycles alone is insufficient for a current exit on an older case, whose `SourceEventId` is the original intake key (`phase05-citizens/judicialLifecycle.js:350-356`). Specify a pre-write ledger snapshot or equivalent prior-state comparison, and prove intake and exit keys independently for same-Cycle and cross-Cycle replay. The schema requires kind-aware identity (`docs/plans/2026-09-21-care-and-justice-system.md:254,266-268`).

2. **Blocker — contradicted: judicial exit receipts have no valid `IntakeType`.** The Task 8 assembler passes `S.judicialEvents` straight to the fold (`docs/plans/2026-09-21-care-and-justice-system.md:603`). `judicialLifecycleReceipt_` sets `intakeType: ''` on every non-intake, including `exit` (`phase05-citizens/judicialLifecycle.js:350-356,419-451`). The builder validates the type on every surviving receipt before applying its kind (`utilities/careJusticeAccounting.js:174-180`), and judicial types admit only `arrest` (`utilities/careJusticeAccounting.js:22-25,55-62`). A released or served case therefore throws rather than writing a census. The existing test constructs an `exit` with `intakeType: 'arrest'`, not the producer shape (`scripts/careJusticeAccounting.test.js:205-214`). Carry the case's `EntryType`/census type on the exit receipt or derive it from the verified row.

3. **Blocker — contradicted: first-Cycle and failed-Cycle bootstrap cannot use one empty-opening rule.** The cut says *every* currently open ledger row becomes a correction while this Cycle's receipts remain intakes (`docs/plans/2026-09-21-care-and-justice-system.md:603-606`). For a newly opened row, `opening=0`, `intake=1`, `correction=1`, `trackedOpen=1`: the builder computes two while its authority has one (`utilities/careJusticeAccounting.js:236-247`). Only pre-existing open rows lacking a booked current movement can be opening corrections. After a failed census Cycle, the last valid `otherResident` occupancy is in the census alone; the ledgers carry only tracked people (`utilities/careJusticeAccounting.js:120-126,194-213`). Resetting opening to zero silently erases the untracked cohort, while correcting from the ledgers cannot reconstruct it. Define whether a gap carries the last valid other-resident stock, marks intervening movement unavailable, or starts a new explicitly labelled series; the current claim of “nothing booked twice” is false.

4. **High — partly confirmed, partly contradicted: phase isolation works, writer-failure detection does not.** A separate `safePhaseCall_` immediately after both `Phase10-CyclePacket` call sites means a census exception cannot retroactively prevent an already written packet (`phase01-config/godWorldEngine2.js:159-169,557-578,2239-2256`; `phase10-persistence/buildCyclePacket.js:771-792`). But the packet function runs hospital then judicial synchronously *before* writing `Cycle_Packet`; a hospital throw prevents the judicial writer and packet (`phase10-persistence/buildCyclePacket.js:73-80`). A fresh tab readback plus matching `SourceEventId` or POPID does not prove this Cycle's transition or exit persisted: the old open row already has the same POPID/source id, and a failed update can leave it unchanged (`phase10-persistence/buildCyclePacket.js:885-923,1066-1101`). The cut also says `sources=missing` when a writer did not run, yielding blank `unavailable`, but says a thrown writer yields numeric `incomplete` (`docs/plans/2026-09-21-care-and-justice-system.md:600-608`; `utilities/careJusticeAccounting.js:220-221,266-280`). Record per-writer execution/result and compare the expected row's status, cycle, and disposition after readback; specify when counts are unavailable versus incomplete.

5. **High — contradicted: the `unallocated` remainder is treated as known zero other-resident demand.** Demand expressly has `unallocated: {status:'unavailable'}` and models only named hoods (`phase04-events/careJusticeService.js:203-230,253-288`). The schema requires the unallocated scope and says a missing source is `unavailable` with blank counts (`docs/plans/2026-09-21-care-and-justice-system.md:231-240,269`), while the Task 7 handoff assigns unallocated as unavailable (`docs/plans/2026-09-21-care-and-justice-system.md:486`). Task 8 proposes a populated remainder scope and `otherResident` from the hood-only helper, without a per-scope availability input (`docs/plans/2026-09-21-care-and-justice-system.md:601-606`; `utilities/careJusticeAccounting.js:118-126,220-270`). The builder will emit zero other intakes and a seemingly complete city total over a large unmeasured population. It can place tracked out-of-table citizens there (`utilities/careJusticeAccounting.js:159-163`), but it cannot represent tracked-known/other-unknown in that scope with its current row shape. Rule the partial-scope semantics and city completeness before using the city row as a total.

6. **High — contradicted: investigation conversion does not persist the arrest fields needed for replay and custody.** The lifecycle converts an investigation to `pending`, sets `ArrestCycle` and emits an intake (`phase05-citizens/judicialLifecycle.js:75-85,350-356`). The emitted receipt omits `arrestCycle` and `decisionCycle`; the judicial writer's open-row intake branch updates status and transition date only (`phase10-persistence/buildCyclePacket.js:1066-1081`). The sheet therefore retains blank `ArrestCycle` and the old decision clock. Task 8's proposed key rebuild says an investigating row seeds no intake and an `ArrestCycle`-set row does (`docs/plans/2026-09-21-care-and-justice-system.md:603`); that rule cannot recognize the persisted conversion. The case contract says an investigation becomes an intake in the conversion Cycle (`docs/plans/2026-09-21-care-and-justice-system.md:202-235`). Include the conversion fields in the receipt and persist them in the existing-row writer path.

7. **High — contradicted: suffix only on a second same-Cycle row misses reconcile collisions.** Current hospital missed-admission repair uses `StatusStartCycle` as the row ID's Cycle, which may precede the current Cycle (`phase10-persistence/buildCyclePacket.js:982-993`). If a closed row already has `H-C<start>-<POPID>`, this repair can append a duplicate even when it is the sole new row today. The cut limits suffix use to a second same-Cycle row (`docs/plans/2026-09-21-care-and-justice-system.md:609`), but receipt identity explicitly allows a later distinct source for the same POPID (`docs/plans/2026-09-21-care-and-justice-system.md:164-170`). Check the candidate ID against *all* persisted and newly appended IDs, including reconcile IDs, and take the next free suffix. Apply the same general check to `J-C...` instead of assuming the open-POPID index proves row-ID uniqueness.

8. **High — contradicted: one batched append is not a replay rule for the census rows.** The cut specifies 216 rows per Cycle and one batched write (`docs/plans/2026-09-21-care-and-justice-system.md:608,615`); the schema declares a five-part row key (`docs/plans/2026-09-21-care-and-justice-system.md:219-237`). It does not say whether a retry after an uncertain write replaces rows by key, detects an already complete Cycle, or appends another 216. The existing Phase-10 append helper fixes a sheet target for retry within one invocation, but a later Cycle retry has no equivalent key check (`phase10-persistence/persistenceExecutor.js:216-228`). Without an idempotent same-Cycle write rule, replay can create two authoritative census rows per key even when receipt folding is correct.

9. **Medium — partly confirmed, partly contradicted: the stay recurrence can balance, but its health/custody claims exceed the model.** With a valid integer stay `s>=1`, `otherClosing=openingOther+otherIntakes-round(openingOther/s)` matches the builder's movement equation if `exits` and `beds` are populated consistently (`docs/plans/2026-09-21-care-and-justice-system.md:606`; `utilities/careJusticeAccounting.js:194-256,342-346`). The stated `intake × stay` is an equilibrium for constant integer intake, not a bound or a general result under changing demand; rounding also changes small cohorts. No range/integer validation is specified for the new dial, and `round(opening/s)` has no individual 1–4 Cycle maximum, unlike the ruled named held term (`docs/plans/2026-09-21-care-and-justice-system.md:198-208,611`). The claimed ~78 hospital beds and ~58 custody are model-only other-resident estimates before tracked occupancy, and actual `other` intakes subtract named cases (`phase04-events/careJusticeService.js:268-274`). State whether the 1–4 rule applies to other residents; validate the dial and describe these figures as illustrative, not capacity/readback evidence. The one-dial-versus-two-system choice is explicitly left to the builder's morning ruling (`docs/plans/2026-09-21-care-and-justice-system.md:611`).

10. **Medium — contradicted: the named validator does not assert A–J.** It checks A, B, B-split, a weak J bound (`BedsOccupied <= ClosingOccupancy`), G blankness, and C sums (`utilities/careJusticeAccounting.js:317-371`). D/E/F/H/I are properties of the fold and inputs, not checked on rows; J's exact `hospitalized`+`critical` count is not compared with ledger states. Thus “`validateCareJusticeCensus_` runs ... a violated invariant throws” and “invariants A–J via the validator” overstate the gate (`docs/plans/2026-09-21-care-and-justice-system.md:595,608,615`). Keep scenario tests for D–J and a separate readback comparison; do not call the row validator comprehensive.

11. **Medium — confirmed silent fallback: missing tracked-by-hood entries become zero.** `careJusticeOtherResident_` defaults the entire input and any absent hood/system/type to zero (`phase04-events/careJusticeService.js:253-270`). If Task 8 forgets a receipt category, the helper turns the modelled total into other residents without an error; its overdraw log only catches `tracked > modelled` (`phase04-events/careJusticeService.js:271-285`). The cut says the map groups this Cycle's intake receipts, including only illness and arrest for subtraction (`docs/plans/2026-09-21-care-and-justice-system.md:606`). Build it from the same *accepted, non-replayed* receipt set that reaches the census, and assert every demand hood has an explicit count for both modelled types. Using raw receipts or a missing key will make `TotalIntakes` disagree with the intended tracked/other split while still satisfying A arithmetically.

12. **Low — F1 confirmed as a real shared-reader change; F3's stated `detained` fix is already present.** The effects reader and demand reader each do exact lookup then substring fallback on the same phase table (`phase02-world-state/applyInitiativeImplementationEffects.js:144,551-560`; `phase04-events/careJusticeService.js:73-93`). A shared helper can remove drift, but must preserve that exact precedence and iteration order; a new matching rule would change deployment and OARI weighting. The texture picker already excludes `detained` (`phase04-events/chaosCarsEngine.js:190-205`), as does the shared resident index (`phase04-events/careJusticeService.js:114-135`). Moving the texture picker to a common predicate is cleanup, not a new detention gate. Keep its uniform draw over the eligible set as the cut requires (`docs/plans/2026-09-21-care-and-justice-system.md:610`).

**Required before build:** settle the replay snapshot/key derivation, conversion and exit receipt shape, first/failed bootstrap, per-scope unavailability, and census same-Cycle idempotence. Then make the proposed tests exercise actual producer receipts and post-write sheet images, including a partial writer failure and a missing census Cycle.
