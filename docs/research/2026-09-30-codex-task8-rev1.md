# Task 8 Revision 1 — adversarial re-review

**Verdict: HOLD.** Revision 1 fixes several producer and writer contracts, and the writer isolation in `bc296679` is present. Its replay carrier still confuses a persisted ledger movement with a booked census movement. Its partial `unallocated` row cannot satisfy the current 22-column arithmetic and availability contract. A missing census Cycle also cannot be reconstructed by draining the last stock alone. This reviews the cut and current code; Task 8 census persistence is not yet installed (`docs/plans/2026-09-21-care-and-justice-system.md:593-634`; `utilities/careJusticeAccounting.js:1-8`; `phase01-config/godWorldEngine2.js:557-565,2239-2245`). No Sheet or engine run was made.

## New or sharpened blockers opened by Revision 1

1. **A ledger key is not a census receipt.** Consider Cycle C's ledger writer succeeding, then its census phase failing before writing. On a rerun, Phase 5's fresh cache reads the C row (`utilities/sheetCache.js:46-65`; `phase05-citizens/judicialLifecycle.js:284-316`); Revision 1 pre-seeds `judicial|intake|id` or `judicial|exit|id` (`docs/plans/2026-09-21-care-and-justice-system.md:621`). `foldCareJusticeReceipts_` drops that movement (`utilities/careJusticeAccounting.js:75-95`), although no C census row booked it. If a complete C census *does* exist, the same recomputation suppresses its movements and row-key replacement can turn a valid C row into an `incomplete` one when the ledger open count disagrees (`utilities/careJusticeAccounting.js:241-247`; `docs/plans/2026-09-21-care-and-justice-system.md:628`). A re-created receipt is not assured on a rerun either: judicial Phase 5 reads the already-closed/open case and emits only the transitions it now takes (`phase05-citizens/judicialLifecycle.js:365-395,413-451`). Specify a census booking carrier or a fail-closed same-Cycle row comparison, and prove both uncertain-write orders with actual producer events.

2. **The claimed pre-write image is timing-dependent.** `createSheetCache_` loads each tab at its first `getData` call, and direct ledger writers do not invalidate it (`utilities/sheetCache.js:46-65,95-97,172-175`; `phase10-persistence/buildCyclePacket.js:862-872,1028-1030`). Judicial Phase 5 calls `getData` on its path (`phase05-citizens/judicialLifecycle.js:284-290,360-365`), but Hospital_Ledger is read from the cache only in the discharge prior-status path (`phase04-events/generationalEventsEngine.js:175-180,434`). On a Cycle with admissions and no such discharge, a Phase 10 `getData` can first load the **post-write** hospital ledger. Explicitly snapshot both tabs before Phase 10 and distinguish that immutable image from the fresh readback; test a no-discharge admission.

3. **The proposed unallocated row has no valid current encoding.** `unavailable` requires *every* count blank (invariant G), while A requires `TotalIntakes = TrackedIntakes + OtherResidentIntakes` on every row (`docs/plans/2026-09-21-care-and-justice-system.md:237-240,263-269`; `utilities/careJusticeAccounting.js:330-345`). A tracked count plus blank other gives an unknown total, not a numeric total. The validator's city sum also treats any unavailable disjoint scope as requiring an unavailable city row (`utilities/careJusticeAccounting.js:337-363`); Revision 1 wants `incomplete` and hood-only other counts (`docs/plans/2026-09-21-care-and-justice-system.md:625`). If an out-of-table tracked citizen appears, hood-only city tracked totals also violate C (`docs/plans/2026-09-21-care-and-justice-system.md:240,265`; `utilities/careJusticeAccounting.js:159-163,348-369`). Decide whether to add an explicit partial/unknown representation and revise A/C/G and the reader contract, or keep the entire unavailable scope blank and label city counts as a coverage-limited series under a ruled schema. Do not make blank mean zero.

4. **The missed-Cycle stock cannot be recovered from the last close alone.** `otherResident` intakes are computed from *that Cycle's* demand and accepted tracked receipts (`phase04-events/careJusticeService.js:203-230,253-288`; `docs/plans/2026-09-21-care-and-justice-system.md:606,631`). If C has no census row, draining the last recorded other stock once for C omits C's admissions/arrests, which are not stored as other-resident rows in either ledger (`utilities/careJusticeAccounting.js:120-126,194-213`). No C row exists to mark `incomplete`, and a next-Cycle row cannot truthfully stand in for C (`docs/plans/2026-09-21-care-and-justice-system.md:623`; `utilities/careJusticeAccounting.js:292-301`). If C *has* an `incomplete` census row, its closing is already a written C value and must not be drained again for C. Distinguish missing census, incomplete census, and failed ledger writer; specify gap backfill or explicit unknown opening and read semantics. The same gap needs tracked exits/corrections in both directions, not only corrections for people still open (`utilities/careJusticeAccounting.js:236-247`; `docs/plans/2026-09-21-care-and-justice-system.md:623`).

5. **Keyed replace needs an integrity protocol.** A five-part key identifies a row, but does not prove there is exactly one row for it, that all 216 expected keys exist, or that the stored Cycle uses the same opening/movement as a rebuild (`docs/plans/2026-09-21-care-and-justice-system.md:219-237,628`; `utilities/careJusticeAccounting.js:215-289`). A timed-out partial batch can leave a subset of C rows; a retry must replace those, append precisely the missing keys, reject pre-existing duplicate keys, and read back all expected values before treating C as booked. The existing append retry guarantees only one target *inside that call* (`phase10-persistence/persistenceExecutor.js:216-228`). Define what happens when an existing complete C row conflicts with recomputation, especially after the pre-write key problem above; never silently replace verified history with different figures.

**Required before BUILD:** settle the partial-scope schema and sim-visible stay policy; specify a durable census booking/replay and gap-recovery rule; guarantee both pre-write snapshots; define exact keyed replacement and readback behavior. Then update the superseded Task 8 prose/tests and exercise first-Cycle old-row exit, no-discharge admission, ledger-written/census-missing rerun, complete-Cycle rerun, missing-Cycle other intakes, and partial 216-row write with duplicate and missing keys (`docs/plans/2026-09-21-care-and-justice-system.md:593-634`).
