## The approved vision (2026-11-26, "This is all correct copy this as the plan")

1. **A city feed.** Each non-sports beat gets entries shaped like the sports entries: one event, its history from canon with cycle numbers, the people, the open questions. The reporter wakes with that and chooses how to cover it.
2. **Written unattended.** After the engine and city hall finish on Sunday, the week's raw events are read, canon is searched for each one picked, and the entries are written — the job the duet does on sports. A workflow step, not a persona voice ("mags is giving a tidy story, it's just a part of the workflow").
3. **A sheet tab, not a file.** Entries live on a tab like the sports feed; the builder can add his own rows and questions the same way.
4. **Shared storylines.** One storyline goes to two seats only when their approach differs and their models differ (the council's accountability on one seat, how citizens are taking it on another).
5. **Daily follow-ups.** The Cycle is weekly; reflections and published pieces change daily. A short weekday pass reads those and adds follow-up entries, so a storyline moves midweek and seats react to each other.
6. **Free seats stay free.** Farrah, Jax, P Slayer and Ines get no entries; "keep them as the pressure".

Named conflict, accepted by the approval: the 2026-07-10 ruling ("As long as you control everything it's going to always [be a] tidy story"). Built-in difference: the writer reads raw events and citizens' pages, never a pre-digested summary; the free seats stay.

## Design

**Tab `City_Feed`** — the sports feed's shape, so one mold reads both:

| Column | Holds |
|---|---|
| Cycle | the Cycle the event belongs to |
| Beat | faith, health, economy, transit, schools, safety, arts, food, neighborhoods, lifestyle, trends, environment, civic, investigations |
| EventType | event, follow-up, question (a builder's row is `question`, as on the sports feed) |
| NamesUsed | people and places, "Name (role)" |
| Notes | the entry: the event, then its history with cycle numbers, then the open questions |
| StoryAngle | the first open question, one line — a question, never a conclusion |
| Storyline | engine storyline id when one exists (`CRISIS-…`, `INIT-…:stage`), else a slug the writer mints and reuses week to week |
| Refs | one ref per history sentence: canon doc id, sheet tab + row, or staged file |
| Seats | seat slug(s) the entry goes to |
| WrittenBy | `city-desk` or `builder` |
| EntryId | `CF-<cycle>-<n>` |

**The writer (`scripts/cityFeedWriter.js`), a workflow:**

1. Inputs, raw only: `output/beats/*.jsonl` + `prev/` (the week's rows and what moved), LifeHistory window, citizens' pages for the week, `desk_signal` storyline registry (ids and stages only), the feed's own prior rows (open storylines), the week's staged headlines. Never `world_summary` prose, never a lane `handle.angle` / `hookLine`.
2. Candidates per beat in code (what moved, what is new, what a prior entry left open). The model picks which to carry and why; no score picks for it.
3. Per pick, a tool loop on the tools the seats already have: `canon_search`, `canon_recall`, `citizen_lookup`, `sheet_read`, `ask_worker`. It returns history sentences, each with a ref.
4. **Ref check in code before any write:** every history sentence's ref resolves (canon doc exists and contains the named cycle / person; sheet row exists and holds the figure). A sentence that does not resolve is dropped and logged. No cause on the record → an open question, never a reason.
5. Seats: one seat by beat. A second seat only when the two packages' write models differ (`scripts/newsroom-wake-packages.json`) and the entry names a different approach for each; checked in code. Never Farrah, Jax, P Slayer, Ines.
6. Append rows (read back). Idempotent per Cycle (`output/city-feed-state.json`): a second run adds nothing.

**Trigger:** the civic chain's week state (`engineFiredAt` set, chain applied, beats `meta.json` at the Cycle) — the hourly tick's own condition, no clock time. The writer adds no CLI step. What it waits on (beats dump, engine audit, desk signal) is written by `/run-cycle` Steps 4–5.56 through `scripts/runCycle.js`; taking the CLI out of those steps is its own job and is named to the builder, not built here.

**The record (`scripts/cityRecord.js`, `makeCityRecord(SEAT, opts)` on the `makeSportsRecord` mold):** the seat's own entries for C and C−1 lead, whole, newest first; its own pieces already filed this Cycle open the record; colleagues' pieces on the same Storyline ride as "Filed this Cycle by …"; the people the entry names are sources. The flat record leaves the wake and stays reachable through `sheet_read`. No entry for a seat → the seat's present record, unchanged. No "ASSIGNED ANGLE / HOOK / the angle is fixed" text anywhere; the entry is the day's record and the job line stays the seat's.

**Weekday pass (after the builder's read of phase 1):** Mon–Fri before 06:15, the same writer in `--follow-up` mode reads the prior day's citizens' pages and gate-passed pieces and adds `follow-up` entries on open Storylines. A seat's refusal or own pitch (item 5 of the second message) is designed after the first live read.

**Canon:** the tab is not an ingest source; canon is what gate-passed pieces carry. `dumpBeatTabs.js` reads an explicit tab list and `backupSpreadsheet.js` copies every tab — neither breaks on a new tab. Engine phases do not read it.

## Acceptance

1. An entry reads like a sports row: one event, at least two history sentences with cycle numbers, named people, at least two open questions — proven by Task 4's print.
2. No history sentence reaches the tab without a ref that resolves — proven by the suite and by opening every ref in Task 4 by hand.
3. An event with no cause on the record yields a question, not a reason — proven on the three C117 Faith_Ledger crisis rows.
4. A seat on the city record opens on a person or an event, not on the record — proven by Task 5's piece beside the C117 piece, and the grade's opening line.
5. Two seats share a Storyline only with different write models — proven by the suite against the package file.
6. A fire with `/run-cycle` complete produces the week's entries with no further command — proven by the first Sunday log.
7. Farrah, Jax, P Slayer and Ines receive no entry — proven by the suite.
