## Findings

1. **HIGH — A Mara-only project turn can move the tracker before its dated step.** `scripts/cron-civic-run.js:2348-2369` computes `stepDue` and tells the model to leave `trackerUpdates` empty when it is false, but the `callVoice` checks at `:2366-2367` contain only `maraAnswerCheck` and `statementNumberCheck`. `validateVoiceJson` at `:1536-1565` accepts any valid phase and any other tracker fields. **Input → wrong output:** Mara asks an OARI question while its next step is scheduled for a later Cycle; a syntactically valid answer with `trackerUpdates.ImplementationPhase` or `NextActionCycle` is accepted and written to the project voice, allowing the later close/apply path to treat an unauthorized move as a decision. The M1 item 11 rule that no tracker change is accepted before the due step is only prompt text. The new test at `scripts/maraM1.test.js:159-168` tests the answer helper, not this route or its tracker gate.

2. **HIGH — A status can falsely close a promise as kept.** `scripts/maraPromises.js:103-141` verifies source identity and an exact tracker value, then accepts the caller's `kept|dropped|changed` label without checking whether the value or answer supports that label. `scripts/maraM1.test.js:77-85,109-118` explicitly accepts `kept` for a promise to send a referral by next week using only `NextActionCycle: 1000` on the same initiative. The answer route at `scripts/maraPromises.js:127-138` likewise accepts any bound reply, including a deferral, for `kept`. **Input → wrong output:** a future date or “not done yet” reply closes the promise as kept; `loadRecord` then removes it from Mara's open list (`scripts/maraPromises.js:144-153`). This defeats M1's “keeps promises honest” acceptance even though provenance matches.

3. **HIGH — A malformed directive can be published as valid and break the weekday reader.** `scripts/cron-civic-run.js:994-1010` checks only whether field markers occur anywhere in a block. An empty `**Address:**`, `**Why:**` without a Cycle/source, or empty `**Acceptance:**` passes. `scripts/cron-civic-run.js:1428-1432` accepts any such block; `scripts/buildCivicOfficeSlice.js:1170-1174` later throws on an empty Address. **Input → wrong output:** one roster block with `- **Address:**` and the other field labels but no values yields an AUTO and a successful directive manifest, then a weekday seat's confrontation load throws instead of giving it a question. The same filter silently discards an invalid `## Not directing` section while retaining valid blocks (`:1009-1010`), after which `writeOutputs` emits “Mara Vance issued no directive” beside those blocks (`:1384-1385`). The tests cover valid sections, not these rejected-section or empty-field cases.

4. **HIGH — A partial commit is counted as a finished directive by the hourly tick.** On a failed memory or page write, `commitDirectiveWrites` records `complete: false` (`scripts/cron-civic-run.js:1210-1239`); `runDirective` writes `commit: partial`, logs a manual re-run instruction, and exits successfully (`:1457-1465`). `refreshWeekState` marks the stage `done` as soon as `directive_c<N>.json` exists, without inspecting `commit` (`:4093-4097`). **Input → wrong output:** an unavailable `mara-world` or failed page readback leaves a partial receipt and no complete memory history, but the tick stops scheduling the stage. The receipt resume branch (`:1255-1267`) works only if someone explicitly runs the stage again. `scripts/maraM1.test.js:137-157` calls the commit helper twice by hand and does not exercise this scheduler state.

5. **HIGH — The approved `mara-world` history split has no copy gate in the candidate.** Plan M1 item 7 (`docs/plans/2026-10-31-civic-autonomy.md:256-259,278`) requires source-id plus full-text candidates, a screen script, builder review, and a copy/readback receipt for the in-world manual history. The exact 16-file diff adds only the live `mara-world` search/upsert wrapper (`scripts/maraMemory.js:3-10,31-65`) and its weekly run entry (`scripts/cron-civic-run.js:1219-1220`); it adds no screen/copy code or receipt. The separate untracked `output/mara-directives/mara-world-seed-candidates.md:1-20` lists summaries and IDs rather than every entry's full text, and says nothing has been copied. **Input → wrong output:** the first live `mara_memory` search sees an empty new container even when the approved in-world C74–C103 history exists in the manual container; Mara has no access to that institutional record. This does not show an out-of-world leak—the cron does not read `mara`—but the required safe migration is unfinished. The C114 proof has no memory reads (`output/codex/mara-m1/proof_directive_c114.json:98-120`) and was a dry commit, so it cannot validate the copy or readback.

6. **MEDIUM — The accepted directive need not cite a recorded promise.** `scripts/maraDirective.js:67-76` parses `**Promise:** P-…`, and `scripts/cron-civic-run.js:1390-1394` copies parsed IDs to the manifest, but `filterDirectiveBlocks` at `scripts/cron-civic-run.js:989-1010` never checks those IDs against the existing record or this attempt's validated staged promises. **Input → wrong output:** a model emits a well-formed block containing a fabricated `P-` ID after a rejected or omitted `promise_record` call; the AUTO and manifest present it to an office as a recorded promise. Later status validation rejects the unknown ID (`scripts/maraPromises.js:103-105`). The C114 proof happened to stage the five IDs it cited; the acceptance rule is not enforced.

7. **MEDIUM — The no-decision director path still demands a decision.** The Mara-only prompt says “No operational decision is asked” (`scripts/cron-civic-run.js:2357-2364`), but it appends `outputContract`, whose required example says `cascadeSummary: what you decided and why` and `statements[].decision: the concrete decision` (`:1511-1520`). `validateVoiceJson` rejects a statement without a decision (`:1536-1542`). **Input → wrong output:** a director whose honest answer is only “the briefing is not known yet” must still fill a decision field or have the response rejected; the resulting voice can state an invented operational choice. The M1 test checks `maraAnswer` validation but never tests a no-decision full project JSON.

8. **MEDIUM — The promised full weekday move and Sunday statement inputs are abbreviated.** `scripts/cron-civic-run.js:1177-1193` renders Sunday `decision`, `quote`, `fullStatement` and summary but omits other statement fields, notably `trackerUpdates`; it renders weekday moves as type, initiative, title and confrontation ID, dropping the rest of each payload. The prompt uses those renderers (`:1352-1356`). **Input → wrong output:** a weekday move carries a substantive proposal or answer detail only in its payload, or a Sunday statement's tracker update changes the stated step; Mara receives a shorthand line instead of that evidence and may report no follow-through or ask the wrong question. This breaches M1 item 5's full `statement + moves` and Sunday statement input contract (`docs/plans/2026-10-31-civic-autonomy.md:254`). There is no test comparing rendered material with the source JSON.
