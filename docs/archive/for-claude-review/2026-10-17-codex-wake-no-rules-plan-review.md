# Verdict: HOLD before build

Source review and local-dump arithmetic only; no cron, model, Sheet, bench, canon, or test execution. Only this requested file is written. Current checkout is dirty and ahead of origin; unrelated work is untouched. Each hunt below separates an implementation fact from a ruling interpretation.

## 1. Completeness — FIX

- The table is incomplete. `lib/wakePerception.js:406-408` rejects short/missing AND unparseable DialState, not merely absent state. `lib/citizenDials.js:35-45` nevertheless defaults missing individual dials to 50, so this is not rigorous data validation. `wakePerception.js:420` rejects missing name OR neighborhood; a missing neighborhood can instead be omitted from the prompt, so “cannot render” is false (`scripts/citizen-wake.js:256`). Missing identity/state should surface as unavailable data requiring repair, not be silently equated with citizen ineligibility or filled with invented canon.
- The last 100 selections are excluded from ordinary rotation whenever any other candidate exists (`citizen-wake.js:48,204-206,470`). At the proposed 1,032-person pool the fallback cannot restore those 100 while the remaining candidates exist. This is a temporary exclusion, not merely ordering, and conflicts with “any citizen ... whenever.”
- Slot order is forced → voiced → lived → posture → rotation (`citizen-wake.js:165-214`), contrary to W1's “lived slot still fires first.” Voiced priority depends on authored `citizen-voice-*` identities and a seeded 1-in-5 condition (`:146-155,175-182`); posture requires a current-Cycle change and absence from recent (`:195-200`). Higher slots can prevent ordinary citizens being selected on that invocation.
- Lived priority additionally requires event window/current-or-previous Cycle, recognized event kinds, fewer than seven lived selections per Cycle, valid BirthYear >1900 and age ≥16, unspent event, and birth-household deduplication (`wakePerception.js:655-675,761-777`). Death recipients exclude deceased/archived ledger rows upstream (`:700-705`). These constrain the lived route; W1/W2 allow those citizens to use other routes, but do not remove these rules.
- `buildPool` has NO Tier, Status, adult, or Inactive filter (`:384-453`); Tier is prompt data. An Inactive row with qualifying fields passes, as would a deceased row left in the main ledger. Do not silently add a new status exclusion under this task. The inspected snapshot has no Inactive rows (988 Active, 44 Retired).

## 2. W1/W2 at the wake call — FIX

- The two zero overrides eliminate `livedOnly` for valid dial vectors and release thin-history citizens into all slots; preserve the `include` option because it also attaches BirthYear/household fields needed by `pickLived` (`wakePerception.js:450`). No second citizen is selected in one invocation: each slot returns once.
- A voiced selection can preempt a pending lived selection without spending its event; later the same person may wake through lived despite being recent (`citizen-wake.js:175-190,473-477`; `wakePerception.js:773-777`). Repeat-person wakes are compatible with the ruling, but the plan must not claim once-per-person behavior. Lived backlog can expire under voiced preemption/seven-event cap; posture backlog can occupy all remaining slots before rotation. Removing floors does not establish fairness or guaranteed access.
- Offline count reproducing the pool predicates over `output/simulation_ledger_snapshot.jsonl:1` onward: **1,032 rows; 237 default candidates without lived inclusion; 1,028 with both floors removed but surname ban retained; 1,032 with W3 too**. Mags qualifies, deviation ≈88.79. Metadata dates this C111 snapshot to October 11 (`output/simulation_ledger_snapshot.meta.json:3-6`).

That is an observed existing-pool count, not today's expanded-pool count. No fresh ledger was fetched; today's expanded count remains unverified. Do not relabel October 11 arithmetic as today's Sheet state.

## 4. W4 interpretation — HOLD

Removing deviation weighting implements the specifically named dial-distance instruction. Retaining `1 + eventMag*2` gives quiet citizens positive probability **when they reach rotation**, but still favors eventful citizens. `eventMag` is itself derived from dial nudges, with line-position decay rather than elapsed-Cycle decay (`wakePerception.js:34-44`). It is a selection rule, though not a zero-probability pool filter. The broad “no rules” statement does not establish an exception for this weight, recent exclusion, or slot priorities. Present these residual policies explicitly for the builder's ruling; do not declare W4 or the whole selection policy compliant by inference.

## 5. M1 text boundary — FIX

Strip all leading nightly headers before truncation/scoring (`wakePerception.js:283-295`), but this only fixes that header. Discord usernames, messages, responses and wall-clock times enter the prompt (`discord-reflection.js:151-160,198-206`); Moltbook authors/titles/replies/posts do too (`:123-145,485-488`). Prior page bodies return unstripped (`:354-363`), and Supermemory context joins at `:460-470`; tool results also enter the composition loop (`:254-295`). Prompt instructions against real-world dates (`:171-174`) are not a content validator. Generated body text is persisted wholesale after header normalization (`:315-327,513`). Thus builder remarks or dates in the body can reach subsequent wake recall and the M2 excerpt.

Claude-mem here is an outgoing persistence sink (`:372-389,517`), not a direct read into this page. Do not assert a direct claude-mem → page path without separate evidence. The concrete inbound risks already exist through conversations, Moltbook, archive context and recursive page recall. Fix the text boundary for these sources without inventing a new citizen admission gate; six clean samples cannot prove arbitrary future body content safe.

## 6. M2 intake, persistence and rate — FIX

- A–K row ordering matches the reader: timestamp, POPID, Cycle, daypart, event, excerpt, applied, affect, bondTarget, tension, resolves (`citizen-wake.js:442-451`; `utilities/compressLifeHistory.js:125-133,295-312`). Classify header-stripped body, not the date-bearing wrapper. Preserve classifier failure handling and skip/retry semantics instead of promising a row even when both tags are absent (`citizen-wake.js:399,447-454`). Resolve Cycle before queuing: current nightly code permits null Cycle (`discord-reflection.js:511-513`), but petition reading rejects it while the drain does not filter by Cycle (`buildCivicOfficeSlice.js:1030-1032`; `compressLifeHistory.js:295-312`).
- **Idempotency is missing.** Page customId does not deduplicate `appendRows`; a failure after append followed by retry adds another unapplied row and another base nudge. Even the page key includes Cycle, and null Cycle removes customId entirely (`citizenPage.js:64-66`). Specify a stable source/night identity and recoverable receipt/reconciliation for uncertain append outcomes; a local success flag alone cannot close the crash window. Define which of the day's reflections supplies a one-night row rather than silently taking the first and overwriting its page later.
- **Rate correction for the builder:** the script says three runs/day (`discord-reflection.js:5`), corroborated by `docs/OPERATIONS.md:52,88-90`. Live crontab was not inspected. Under that documented schedule, the literal append-after-page proposal yields **up to 21 rows per seven-day Cycle**, not seven, before retries; quiet days skip (`discord-reflection.js:449-452`). Explicit one-night deduplication gives up to seven. Longer intervals between Cycles accumulate more; other wake/PRESS/exchange rows add separately. These are exposure calculations, not proposed caps.
- Base contribution per row/dial is **0.225 × composed tag delta × current directional room factor** (0.45 × 0.5; `compressLifeHistory.js:126-127`; `citizenMemory.js:185-196`; `citizenDialMap.js:352-361`). Seven rows give 1.575 times a repeated unit delta before room attenuation; 21 give 4.725. For repeated Anxious (composure −3), nominal totals are **−4.725 / −14.175**, respectively (`citizenDialMap.js:144-146`); actual successive movement attenuates with current base+mood and clamps at 0–100. No exact Mags outcome can be stated before her tags and starting state are known.
- **Snippet verdict:** raw excerpt is stored in Reflection_Intake F and consumed as semantic text by `nudgesForReflection_`; it is not copied into Simulation_Ledger LifeHistory/MemoryRegisters by this drain. It DOES affect persisted DialState, and potentially the derived TraitProfile (`compressLifeHistory.js:308,665,712,718`). “Moves base only” is too broad for the whole row: a real bondTarget also nudges Relationship_Bonds, and resolved action text can queue a maneuver push (`:671-691`).
- Reuse existing canonical bond loading/name matching (`citizen-wake.js:436-439`); leaving bondTarget blank deliberately forfeits that consequence. Classifier `resolves` is an index, not text (`lib/reflectionClassifier.js:322-344`): either supply/open and resolve the shared tension register as the wake does (`citizen-wake.js:415-434`) or explicitly leave resolves empty. Never persist the raw index as resolved prose. A J-column tension alone does not create the wake's persistent open-tension memory.
- Petition reader accepts Civic rows in its three-Cycle window, excludes office holders, filters district geography, includes applied rows, and displays up to six negative excerpts of 90 chars (`buildCivicOfficeSlice.js:1027-1055`). Other affects count as participation. Mags can enter this civic path; date stripping does not prevent a builder-derived complaint. Increased row volume can increase complaint counts and occupy display slots. Existing drain applied-mark and ledger writes are explicitly non-atomic (`compressLifeHistory.js:658-663`); inheriting that limitation is not new exactly-once proof.
