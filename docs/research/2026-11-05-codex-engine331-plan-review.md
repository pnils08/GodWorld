# Codex review — engine.331 sports feed trigger plan

**Target:** `docs/plans/2026-11-05-sports-feed-triggers.md` Mechanisms 1–7, Tasks 1–9, Acceptance 1–9, against the current source. This is a plan review, before a candidate diff.

**Result:** HOLD

The row-level direction is implementable, but the plan's present rules can infer a title from the wrong row, give engine.333 a trigger that engine.331 has deliberately ignored, and produce different hook and per-player results under a World_Config override. Findings below are implementation and proof gates; Q1–Q3 remain the builder's calls.

## Findings

1. **High — Mechanism 5's “raw week lens” is not the clinch game's lens.** The plan proposes `S.sportsWeek[team].lens === 'championship'` on a game week as proof of a clinch (`docs/plans/2026-11-05-sports-feed-triggers.md:74,157`). `deriveSportsWeekFromFeed_` replaces the lens on **every** row, including a later row without a game, while the accepted weekly result can come from an earlier game row (`phase02-world-state/applySportsSeason.js:320-337`). Input: a `world-series` game row followed by a `championship` season-state row. Proposed output: inferred title-won pitch despite no clinch game. The reverse ordering suppresses a real clinch. Define whether inference uses the accepted game row's own SeasonType, and test both mixed-row orders; a one-row `world-series`/`championship` test cannot settle this.

2. **High — the World_Config override makes the hook and engine.333 paths disagree.** The override returns with `S.sportsWeek = {}` and `S.sportsFeedEntries = []` (`phase02-world-state/applySportsSeason.js:25-28,36-65`), but `applySportsFeedTriggers_` independently reads `Oakland_Sports_Feed` and calls `processFeedSheet_` (`phase02-world-state/applySportsSeason.js:841-854`). Mechanisms 1 and 6 assume the two readers see the same current rows (`docs/plans/2026-11-05-sports-feed-triggers.md:70,75`); engine.333 is specifically to read `S.sportsFeedEntries[i].eventTrigger` (`docs/plans/2026-11-05-feed-triggers-to-life-history.md:89-93`). Input: an override plus a current `retirement` feed row. Proposed result: a retirement hook, but no named player's retirement line or Status change. Decide whether override suppresses authored hooks too, or supplies row entries to the named reader without changing override season state. Test the chosen contract on both entry points.

3. **High — the new row scan needs explicit positive-cycle and active-franchise gates.** `readOaklandFeedEntries_` accepts any row whose parsed Cycle equals `currentCycle`, with no positive-cycle check (`phase02-world-state/applySportsSeason.js:216-237`); the existing reducer interprets `uptoCycle = 0` as *no upper bound* (`phase02-world-state/applySportsSeason.js:1063-1072`), and the existing current-row guards only run when `currentCycle > 0` (`phase02-world-state/applySportsSeason.js:994-1005`). Team normalization returns `NFL`, while only `NBA`/`Warriors` are retired to empty (`phase02-world-state/applySportsSeason.js:458-477`); `processFeedSheet_` iterates every reduced team (`phase02-world-state/applySportsSeason.js:962-969`). Mechanism 1 only says to match Cycle (`docs/plans/2026-11-05-sports-feed-triggers.md:70`). A zero-cycle or NFL current row can therefore enter a literal row loop and make a moment pitch; an all-history reducer at zero can still process stale state. Return empty when the running Cycle is not positive; limit hook teams to A's/Oaks; test Cycle 0, NFL and retired labels in both engine entry paths.

4. **High — “typed hot/cold ignored” conflicts with the planned per-player reader.** Mechanism 4 ignores a typed `hot-streak`/`cold-streak`, while Mechanism 6 puts the canonical typed word on `S.sportsFeedEntries[i].eventTrigger` (`docs/plans/2026-11-05-sports-feed-triggers.md:73-75`). The sibling plan still routes a *named row's* `hot-streak`/`cold-streak` to a life line and explicitly accepts a hot-streak named row (`docs/plans/2026-11-05-feed-triggers-to-life-history.md:89-92,123-125`). Input: a named W2 game row with typed `hot-streak`. Engine.331 correctly emits no hot hook, yet engine.333 would write Sports-Streak-Hot for that player. Task 9's generic “routing table re-pointed” (`docs/plans/2026-11-05-sports-feed-triggers.md:148`) needs an explicit contract: reject these typed words before the named reader, or make that reader enforce the same game-week/bar rule. Add a shared cross-plan test; an automatically inferred team streak has no named feed row to attach by default.

5. **Medium — Q2's bar choice needs a defined failure and sign rule.** If Q2 chooses `sportsStreakHeadline`, the existing bar reader returns `null` and logs an Engine_Error for an unusable value (`utilities/sportsWeekRecord.js:433-445`); `applySportsSeason_` already calls it once (`phase02-world-state/applySportsSeason.js:118-125`). The existing business headline also requires the run's sign to agree with the week's signed result (`utilities/sportsWeekRecord.js:447-458`). Mechanism 4 only says “at or past the bar” and Task 2 says to read the config (`docs/plans/2026-11-05-sports-feed-triggers.md:73,141`). A second direct read can log the same invalid dial twice; a W5 week below expectation can get a hot pitch while the existing W5 business headline is false. Record whether the hook shares the sign gate, and how `null` behaves, without deciding Q2 for the builder. Pass one validated bar or a defined week signal across phases; test invalid dial and opposite-sign week.

6. **Medium — one canonicalizer is not automatically one warning, and `none` must stay outside it.** Mechanism 6 calls `canonicalFeedTrigger_` from both the exact-row reader and the hook reader, and promises one unknown-word log per Cycle (`docs/plans/2026-11-05-sports-feed-triggers.md:75`). Those are separate reads in sequence (`phase02-world-state/applySportsSeason.js:71-74,841-854`); a logging canonicalizer invoked by both can warn twice. `none` remains a literal sandbox cell (`scripts/seedSandboxFeeds.js:210-218`), so simple trim/lower/hyphen normalization returns `none`, contrary to Mechanism 3's no-moment rule (`docs/plans/2026-11-05-sports-feed-triggers.md:72`). Make canonicalization pure, handle blank/`-`/`none` before unknown-word reporting, and record one warning from a shared per-Cycle collector or one designated reader. Test unknown values on multiple rows and both readers.

7. **Medium — Task 5's seeder comment-only edit leaves false raw “trigger” text, and Task 2 misses a test file that must change.** The seeder continues to write `EventTrigger: 'none'` and its test explicitly describes this as clearing carried state (`scripts/seedSandboxFeeds.js:210-218`; `scripts/seedSandboxFeeds.test.js:112-114`). Raw readers print nonblank values as newsroom facts: `Trigger: none` in the Oaks beat slice and `trigger=none` in the media handoff (`scripts/buildOaksBeatSlice.js:53`; `phase10-persistence/compileHandoff.js:1614-1617`). Also `scripts/sportsFeedParser.test.js:77-92,117-120` asserts dash and prior-Cycle trigger carry and last-row `none` clearing, so “existing sports tests stay green” in Task 2 (`docs/plans/2026-11-05-sports-feed-triggers.md:141`) requires updating that named test. Add `sportsFeedParser.test.js`, `seedSandboxFeeds.js` **behavior**, and `seedSandboxFeeds.test.js` to the task list, or explicitly retain and filter the sentinel at every raw presentation path. The existing raw media/dashboard readers otherwise remain intentionally unchanged: `phase10-persistence/compileHandoff.js:1532-1533`, `scripts/buildOaksBeatSlice.js:53`, `scripts/buildSimonSlice.js:60`, `dashboard/src/components/SportsOverview.jsx:94-95`. The reducer fields that Mechanism 1 removes have no other direct engine reader found; game-night tone continues to use the exact row's mood (`phase05-citizens/applyGameNightMoments.js:64-71`).

8. **High — Acceptance 9 is false for the full SPORTS deck.** `storyHookEngine_` separately emits SPORTS phase hooks for playoffs, championship and late season (`phase07-evening-media/storyHook.js:518-551`) before it reads `S.sportsEventTriggers` (`phase07-evening-media/storyHook.js:554-605`); both flow into the deck (`phase07-evening-media/storyHook.js:1368-1380`). Thus a playoffs Cycle with no authored word and no streak still has a SPORTS pitch. Acceptance 9 says **all** SPORTS pitches must trace to a current row word or a bar streak (`docs/plans/2026-11-05-sports-feed-triggers.md:160`). Scope the check to moment pitches and separately account for phase hooks. The existing hook's `hookType: 'sports'` does not itself distinguish their origins (`phase07-evening-media/storyHook.js:521-550,596-603`), so a reliable live provenance proof needs a stable source field or an explicit, checked phase-hook exclusion.

9. **Medium — the two-fire recipe cannot prove all stated acceptance items.** Fire 1 plants two different Oaks words but no duplicate same-team/same-word pair (`docs/plans/2026-11-05-sports-feed-triggers.md:145`), so it does not prove Acceptance 4's “two rows, one word → one” (`:155`). Fire 2 makes the Oaks' bar streak emit `[hot-streak]` while Acceptance 1 demands no `[hot-streak]` without naming the **A's** (`:145,152-153`); the readback must compare team-qualified labels. Ripple attribution is written for triggers only when the game sentiment total is nonzero, and aftermath is a separate sports Ripple row (`phase02-world-state/applySportsSeason.js:868-904`). Therefore an absent off-season Ripple label does not prove no trigger, and a sports Ripple row does not necessarily mean a trigger. Add the duplicate-row case, assert the undeduped trigger array in a local test, and read the team-qualified hook/Ripple outcome plus aftermath separately on each fire. Keep Acceptance 7's Engine_Errors count scoped to these fires and candidate phases rather than treating a zero total as the only proof.

## Vocabulary and proof boundaries

The proposed aliases `draft` and `awards` overlap existing EventTypes, `community-outreach` is also an EventType, and `spring-training` is a SeasonType (`docs/plans/2026-11-05-sports-feed-triggers.md:122-131`; `utilities/setupSportsFeedValidation.js:57-77,96-113`). The mechanics must ensure that aliasing a value typed in **EventTrigger** does not silently treat a misfiled type/phase as proof of a moment; whether those aliases belong is Q1. The draft pitch placeholders use `team` and conditional `<hood>`; existing trigger objects have `team`, `neighborhood`, `streak`, `sentiment`, `playerMood` but no player name, transaction party, or milestone number (`phase02-world-state/applySportsSeason.js:1024-1048`). No draft pitch literally interpolates a missing field; any later pitch that names a player or specific deal needs row data added to the trigger object.

Task 3 correctly names the dropdown source, hook table, parity test, and visual fixture (`utilities/setupSportsFeedValidation.js:134-154`; `scripts/sportsFeedContract.test.js:477-493`; `scripts/visual-qa.js:157-158`). Task 8's dashboard GET checks the server list, because the route serves `SAFE_ENUMS.EventTrigger` (`dashboard/sportsRoutes.js:1035-1040`); it does not verify that the builder re-ran Sheet validation. The Sheet rule is advisory (`setAllowInvalid(true)`) and must be inspected as a separate setup receipt if Task 8 claims that dropdown changed (`utilities/setupSportsFeedValidation.js:340-358,447-455`). Task 6's story-hook and Ripple readbacks are sandbox evidence only; Task 8/Acceptance 9 require a separate first-live read. No sandbox fire, live Sheet read, deployed candidate, or changed-code test was run in this review. C114/live counts quoted by the plan were not independently verified here.
