# UNDOCKED: pilot agency and Nia reporting proposal

**Status: proposal for builder review; no build.** The game already has its rules. The proposed work changes GodWorld's invitation, evidence path, and newsroom access; it does not change SpaceMolt's rules, outcomes, or the board formula. The design aim is to let the pilot decide what to try and let Nia discover and report what actually happened. No game-server call, Sheet read/write, cron edit, model run, or deploy was made for this proposal.

## Proposed work, in order

1. **Give the pilot the show, then let the pilot play.** Replace the generated brief's fixed contract/mining route, static price claims, home-space instruction, and suggested log content (`scripts/undockedMissionBrief.js:55-121`) with identity, the cumulative-credit board rule, the episode window, the fact that the account is already logged in, and an unrestricted invitation to choose a course in the existing game. Keep the auth preflight and a clear safe end condition. Remove the additional compulsory mining loop from the commander's GodWorld-owned prompt assembly (`output/kimi/spacemolt-phase0/commander/src/commander.ts:182-195`); leave the game's command schema and guides available for a pilot who wants them. Version the brief and verify `scripts/cron-undocked-run.js:183-203` would deliver it to the next selected pilot. No particular profession, strategy, route, mission, risk appetite, or result is assigned by this change.
2. **Separate a pilot's finish from a scripted captain's log.** In the runner/commander seam, offer an explicit local “finish this episode” signal and record why the run ended. Let a pilot write any captain's log entry or none; let the pilot choose when to finish subject to the existing wall and stall caps (`scripts/undockedEpisode.js:110-159,197-249`). The signal must never call the game server or award credits. Keep the final actual game state and typed game receipts separate from the runner's own stop reason. This is a production boundary, not a new SpaceMolt rule.
3. **Carry the flight's verified causal events through approval.** Preserve the action-log IDs behind sales, mission acceptance/objectives/completion, mining yields, and system jumps in a local episode evidence projection keyed to the **approved** `EpisodeId`. Build it only after matching the gate-approved feed row, POPID, and staged source; return unavailable on mismatch or missing data. Project only in-world, typed facts with cycle/sequence and source refs: no raw commander prose, tool errors, credential fields, wall-clock timestamps, or unapproved staged paths in writer-facing text. Fix `deriveSystems` so both ends of a jump and the location of a credited action are distinguishable; do not infer location from the current `Systems` list. A Nia `undocked_episode_read(EpisodeId)` tool should expose this approved projection and let the reporter ask why a score moved. Preserve `null` versus measured zero. Historical projection needs a separate review of old approved rows before use; no automatic backfill to Sheets.
4. **Give Nia questions to pursue, not copy to recite.** Her W1 territory can be the approved current show events and board, while she chooses a question and selects sources. Keep `undocked_history`; add the approved episode evidence query and a bounded show-city query over local, cycle-stamped `Casino_Ledger` and `LifeHistory_Log`/show-audience rows, with exact `EpisodeId`/POPID/Cycle and ledger identity joins. A wager or life-history line is evidence of that citizen's action only; generic audience texture is never evidence of a specific pilot's reception. Supply actual named witnesses to W2 only when a record identifies them, and let Nia ask them her own question. Remove the hard-coded “who's up/down” opener, bag-mode quota, and hallway ending from Nia's assignment and writer prose (`docs/media/NIA_ROOK_UNDOCKED_BAG.md:27-45,62-73`; `scripts/newsroom-wake-packages.json:1244-1266`; `scripts/cron-desk-writer.js:1443-1446`). Preserve the source and quote gates. Keep the weekly cast/usage-credit path independent (`scripts/buildNiaSlice.js:222-295`) so an investigative daily piece does not erase pilot credit.

## Acceptance and limits

| Layer | Proof before calling it done |
|---|---|
| Local source and fixtures | Diff shows no mandatory game route, static payout promise, or required log text. Focused pure tests cover brief regeneration, runner stop reasons, and action-log projection using frozen Eric/Sammie/Daphne receipts. No test should merely search for new wording. |
| Evidence binding | For Eric, a read returns 6+36+128+1,000 before the jump; for Sammie it returns the Sol sale and does not claim the `remaining: 0` read forbade later yield; for Daphne it says credit unknown and identifies that the action log has session entries only. Every writer-visible fact has an approved row and typed source ID. A wrong POPID, cycle, `EpisodeId`, or staged path fails closed. |
| Newsroom | An offline handoff fixture proves W1/W2/W3 share the same episode identity (`scripts/cron-desk-run.js:261-297`), and the writer's tools can retrieve flight evidence plus an actual show-city record. A later authorized ordinary wake must show Nia choosing a question, using a source beyond the initial feed fields where one exists, and filing claims/quotes bound to those sources. A model PASS or matching draft hash alone is insufficient. |
| Flight and live world | Only a separately authorized future flight can show what a pilot actually chooses with the revised invitation. Compare its commands, mission outcome, error types, stop reason, action-log credit basis, approved feed, and standings readback. Do not use one high score, a byte-identical output, or a change in average score as proof of agency or game mastery. No game/Sheet/cron/deploy action is authorized by this proposal. |

**Builder decision requested:** approve or revise this direction before any implementation. The essential choice is whether the show should offer a goal and a time boundary while leaving the game's strategy to the pilot, and whether Nia may investigate approved flight and city records instead of receiving a prewritten recap angle. The exact game-wide causes of mining failures, the menu offered to each pilot, and the effect of a lighter brief remain unverified without a later authorized game run.
