# pipeline.93 owed wake diff review

**Verdict: HOLD for `OWED_RESERVE = 6`.** Commit `933883b6` leaves the cron default at zero. The thresholds, R=6, M=2, and per-Cycle absorption implement the builder's specified choices; this review does not reopen them. The defects below concern whether a reserved citizen actually sees the event and whether the reservation is accounted for durably.

## Findings

1. **HOLD — a hospital admission can be spent without reaching perception.** `lib/wakePerception.js:945-950` gives a hospital mark `pin: null`; `scripts/citizen-wake.js:264-268` relies on the single `livedFor` line. But `lib/wakePerception.js:830-837` selects only the newest unspent lived event, while `scripts/citizen-wake.js:432-434` spends *all* the citizen's owed marks after the page append. Input: an admission in C112 and a birth in C113 for the same citizen, woken in C113. The local pure-function check selected `birth:POP-99999:113`; the C112 hospital mark would still be receipted, with no admission line in the prompt. The same loss occurs if `loadLivedEvents` fails while the separate owed read succeeds (`scripts/citizen-wake.js:229-231,264-268`). This breaks the plan's each-class-perception check (`docs/plans/2026-10-29-owed-responses.md:52,63`).

2. **HOLD — a qualifying casino slip can pin another slip's line.** `lib/wakePerception.js:930-940` keys the owed mark by `WagerId`, but its pin is only Cycle plus a broad `Casino|Setback` / `window|slip` regex. `lifeTailOf` takes the last matching line (`lib/wakePerception.js:425-435`), and the writer emits identical generic line shapes for all slips (`phase05-citizens/casinoLedgerEngine.js:427-430,813-824`). Input: one citizen loses a 1,200 stake and then wins 100 on another slip in C113. Only the loss owes; the local check pinned the later low-stake **win** line, while the loss could be trimmed from the five-line block. The loss is then spent at `scripts/citizen-wake.js:433`. The test at `lib/wakePerception.test.js:284` checks one isolated casino line and misses this identity collision.

3. **HOLD — a Judicial_Ledger arrest need not have the line its pin requires.** `lib/wakePerception.js:953-960` treats every valid `ArrestCycle` as owed but pins only a same-Cycle `[Transgression-...]` line. `phase05-citizens/judicialLifecycle.js:606-619` can create a new arrest case by reconciling a detained citizen after a missing case write; that path does not append a Transgression life line. Input: a detained citizen with no persisted case is reconciled in C114. The case gets `ArrestCycle=114`, so the wake reserves and spends the mark (`scripts/citizen-wake.js:264-266,433`), but the pin cannot match the prior arrest's C113 line. The judicial event can be absent from the five-line block. The source-read check for `ArrestCycle` itself is correct; the line-binding claim is not universal.

4. **HOLD — more than five matching events are all spent, though one or more are unseen.** `lib/wakePerception.js:434-443` collects every matching pin and finally applies `.slice(-5)`. `scripts/citizen-wake.js:264-266,433` pins and spends every unspent event for that citizen. A local six-line, six-pin fixture returned only hits 2–6; hit 1 vanished, yet all six marks would be receipted on a landed wake. `lib/wakePerception.test.js:285` asserts only that the block length is five, not that every spent event appeared. A one-wake-per-citizen policy needs an explicit overflow rule or a receipt limited to events actually delivered.

5. **HOLD — source-read and schema failures turn reserved slots into ordinary draws.** `lib/wakePerception.js:1006-1010` uses one `Promise.all` for four tabs. If any tab read rejects, `scripts/citizen-wake.js:243-260` logs once, leaves `owed=[]`, and draws from the lottery even when the other three tabs contain valid due marks. A malformed header is quieter: `hdr` returns `-1` (`lib/wakePerception.js:726`), and `owedFrom` does not validate required columns (`lib/wakePerception.js:913-960`); for example, a Hospital_Ledger row with a missing `AdmitCycle` header yields no mark and no `skipped` reason. Input: a C113 high chaos hit plus a Judicial_Ledger read error, or a hospital row under that malformed header. Output: no reserved wake for that event in that run. Repeated failures across the two-Cycle window lose the mark. A log of the first error is useful, but nonfatal whole-list fallback is not an acceptable proof of the owed guarantee.

6. **HOLD — owed spend has no durable read-back, and ageing stops on quiet wakes.** `scripts/citizen-wake.js:87-88` swallows state-file write errors; after `recordOwedSpend` the code checks only the **lived** receipt (`scripts/citizen-wake.js:432-436`). Input: the page append lands, but `saveState` fails. Output: the next run can select and page the same citizen again, while the persisted `owedWakes[cycle]` remains below R. Separately, `recordOwedSpend` returns before ageing when `events=[]` (`lib/wakePerception.js:995-1003`): a quiet C115 run leaves C113 owed receipts and counts in the file, contrary to the claimed window cleanup. These are new owed-state consequences of the existing best-effort state writer.

The failures above limit what those classifications deliver.
