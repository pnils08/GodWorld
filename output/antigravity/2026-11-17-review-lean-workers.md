### A. Which Records Exceed 8,000 Characters at Cycle 116, and Which Rows Are Dropped

In `buildWake` ([workerWake.js:588-589](file:///root/GodWorld/scripts/workerWake.js#L588-L589)), `whole` is built by calling `FILLS[o.officeId].build(Number(o.cycle), { deps: o.deps, nameOf: who.nameOf, cache })` without `window`. `recordKit` reads each tab via `sheets.getSheetAsObjects(tab)` in **raw sheet order** (oldest Cycle first on append-only sheets; `BIZ-00001` first on `Business_Ledger`). When `toolExecutor` handles `record_read` ([workerWake.js:731-735](file:///root/GodWorld/scripts/workerWake.js#L731-L735)), it calls:
```js
const capTo = (s, n) => (s.length > n ? s.slice(0, n) + '\n(cut at ' + n + ' characters)' : s);
```
Because `s.slice(0, 8000)` slices from the start of the string, **it keeps the oldest rows and drops the newest rows** on every by-Cycle sheet (the exact opposite of `sheetRead` at [workerWake.js:697](file:///root/GodWorld/scripts/workerWake.js#L697), which sorts newest Cycle first).

### B. Does the Worker Learn It Was Cut? (The Double-Truncation Bug)

- **Finding 3.1 ([workerWake.js:680](file:///root/GodWorld/scripts/workerWake.js#L680), [:734](file:///root/GodWorld/scripts/workerWake.js#L734) and [cron-desk-writer.js:357-360](file:///root/GodWorld/scripts/cron-desk-writer.js#L357-L360), [:991](file:///root/GodWorld/scripts/cron-desk-writer.js#L991), [:1021](file:///root/GodWorld/scripts/cron-desk-writer.js#L1021)) — `openRouterToolLoop` slices off `capTo`'s `\n(cut at 8000 characters)` footer and replaces it with `\n…[truncated 25 chars]`:**
  1. When `toolExecutor` runs `capTo(key + ':\n' + recs[key], 8000)` ([workerWake.js:680](file:///root/GodWorld/scripts/workerWake.js#L680)), it slices the string to `8,000` chars and appends `\n(cut at 8000 characters)` (`25` chars), returning a string of length **`8,025`**.
  2. In `runWorkerDatawake` ([cron-civic-run.js:3717-3719](file:///root/GodWorld/scripts/cron-civic-run.js#L3717-L3719)), `dw.openRouterToolLoop` is called without `resultCap`. In `openRouterToolLoop` ([cron-desk-writer.js:991](file:///root/GodWorld/scripts/cron-desk-writer.js#L991), [:1021](file:///root/GodWorld/scripts/cron-desk-writer.js#L1021)), `resultCap` defaults to `8000`, so line 1021 pushes:
     ```js
     messages.push({ role: 'tool', tool_call_id: tc.id, content: cap(result, resultCap) });
     ```
  3. `cap(result, 8000)` ([cron-desk-writer.js:357-360](file:///root/GodWorld/scripts/cron-desk-writer.js#L357-L360)) checks `result.length > 8000` (`8025 > 8000`), slices `result.slice(0, 8000)` — **removing `\n(cut at 8000 characters)` completely** — and appends `\n…[truncated ' + (result.length - 8000) + ' chars]'`, which evaluates to:
     ```
     …[truncated 25 chars]
     ```
  4. **Result:** The worker does **not** see `(cut at 8000 characters)` and is never told that 12,984 to 36,272 characters (61 to 237 rows) were dropped; instead, the tool message tells the model that only **`25 chars`** were truncated! And `record_read` ([workerWake.js:642](file:///root/GodWorld/scripts/workerWake.js#L642)) has no parameters other than `{ record }`, so even if the worker notices the cut, `record_read` provides no way to page to the dropped rows.

- **Finding 3.2 ([workerWake.js:588-589](file:///root/GodWorld/scripts/workerWake.js#L588-L589), [:642](file:///root/GodWorld/scripts/workerWake.js#L642)) — `w.records` and `record_read`'s enum include non-Cycle and single-Cycle blocks that are already handed in full in `w.user`:**
  `buildWake` puts every block of `whole.blocks` into `w.records` ([workerWake.js:589](file:///root/GodWorld/scripts/workerWake.js#L589)), even blocks that were not cut by `window: 1` (e.g., `Your initiative on the city's tracker (INIT-001)`, `Housing pressure, rent and income on the neighborhood map, Cycle 116`, `Transit by station and corridor, Cycle 116`, `Crisis arcs open now`, `The city's shock and pattern flags this Cycle`). `LEAN_TOOLS` ([workerWake.js:642](file:///root/GodWorld/scripts/workerWake.js#L642)) advertises all of them under `"Open one of your records in full, every Cycle on it: ..."`. Calling `record_read` on any of those blocks spends a tool call from the 6-call budget to return the exact text already in `w.user`.
