# Mara M1 design — source review

Scope: `docs/plans/2026-10-31-civic-autonomy.md:238-273` at `b78ced264`, current source, and saved local C114 files. This is a design review, not a judgment about which civic conditions deserve Mara's attention. No model, civic run, Sheet, Drive, or Supermemory operation was executed.

## Findings

1. **HIGH — A director's Mara block has no guaranteed Sunday delivery or answer.** The design says project blocks reach directors through `buildInitiativePackets.js` and that Mara reads their next projects-stage output (`docs/plans/2026-10-31-civic-autonomy.md:256`). That builder copies the full previous directive into `output/initiative-packets/*.json` (`scripts/buildInitiativePackets.js:140-152,565-569,638-654`), but the cron projects stage reads `output/cron-civic/packets/<agent>_pending_decisions_c<N>.md` (`scripts/cron-civic-run.js:1497-1499,2085-2104`); it never reads the initiative packet. Prep writes a project packet only when `assignments[dir]` exists (`scripts/cron-civic-run.js:654-668,680-684`), and the projects stage skips the director unless a layer-1/2 statement touches that initiative (`:1540-1555,2065-2072`). **Input → wrong output:** Mara addresses OARI after C114, but no C115 mayor/council statement touches INIT-002; OARI gets no cron project turn, no answer, and no readable project output for Mara next week. The directive must itself route a project packet and trigger a project turn, or the design must define another answer path.

2. **HIGH — A raw-file substring does not establish an office promise or a truthful status.** The proposed validator checks `said` against *any substring of a cited file* and matches office to speaker (`docs/plans/2026-10-31-civic-autonomy.md:249,263`). Sunday files carry `office`, a **person-name** `speaker`, `cascadeSummary`, and `statements[]` with distinct `decision`, `quote`, `fullStatement`, and `trackerUpdates` (`output/civic-voice/council_d4_c114.json:2-15`); mayor open and gavel are separate files for one speaker (`output/civic-voice/mayor_gavel_c114.json:2-14`). Weekday files instead carry `agentDir`, `holder`, `statement`, and `moves[]` (`output/cron-civic/datawake/civic-office-council-d4_2026-11-02.json:2-18`). **Input → wrong output:** a quote from a `trackerUpdates` field, an answer payload, or a cited source's other text passes a raw substring check as if the office publicly promised it; a later row can mark the promise `kept` with no evidence that it was kept. `source` is model supplied, so unrestricted path reads can also reach unrelated local files. The plan needs an allowlisted path/cycle/office mapping, typed statement-field extraction, immutable original-promise identity, and independent evidence for `kept|dropped|changed`; it must specify JSON string normalization rather than testing the serialized file bytes.

3. **HIGH — Parsing `Not directing` out before validation does not make every downstream reader ignore it.** The parse-out-first rule fixes `filterDirectiveBlocks` (`docs/plans/2026-10-31-civic-autonomy.md:248`; `scripts/cron-civic-run.js:978-993`), and the weekday reader requires an Agent line so it ignores a section with none (`scripts/buildCivicOfficeSlice.js:1138-1151`). Sunday prep, however, selects the first `## ` section containing a seat's *bare directory id anywhere* (`scripts/cron-civic-run.js:762-768`); `buildInitiativePackets.js` copies the entire directive without parsing (`scripts/buildInitiativePackets.js:495,638-644`). **Input → wrong output:** `## Not directing` containing a plain `civic-project-oari` office id but no Agent line/path is accepted as an abstention, yet prep may present that section to OARI as a “Directive from Mara”; the initiative packet always carries it as unfiltered directive prose. Require exact Agent-line section matching in prep and a specified handling rule for the full-copy packet, including a zero-block week.

4. **HIGH — The immediate C114 transition is misstated, and the latest-directive rule must preserve history.** The design says each seat has its C114 block between deploy and C115 (`docs/plans/2026-10-31-civic-autonomy.md:255`). The C114 AUTO has seven elected addressees (`output/mara-directives/mara_directive_c114_AUTO.txt:8-59`), not every seat. A folded local C114 move already has D4's C114 answer pending (`output/cron-civic/moves/moves_c114.jsonl:5`); `loadConfrontations` counts pending, applied, and failed answers as answered (`scripts/buildCivicOfficeSlice.js:1153-1159`). **Input → wrong output:** on this snapshot D4 has no open C114 item; D6/D7/D9 and the project directors have none because C114 has no block for them. A latest-*per-seat* implementation would also resurrect old blocks for unaddressed seats after a no-directive C115 week. Select the latest directive cycle globally for `open`, including a valid zero-block AUTO; retain historical `all` and `answeredIds`, because `loadProblemContinuity` passes `confrontations.all` (`scripts/buildCivicOfficeSlice.js:1275-1290`) and `civicProblemContinuity.js:24-34` needs an old answer's source text to infer its hood. Also specify how a same-cycle manual directive relates to the weekday AUTO reader, which currently reads only AUTO files (`scripts/cron-civic-run.js:507-516`; `scripts/buildCivicOfficeSlice.js:1138-1141`).

5. **MEDIUM — The “no must-act frame” acceptance does not cover the surviving consumers.** M1 removes Mara's forced wording and makes Silence consequence optional (`docs/plans/2026-10-31-civic-autonomy.md:246-248,272`). The weekday prompt still says an answer is “expected” whenever `game.confrontation` is present (`scripts/cron-civic-run.js:2438`), and project RULES still interpret Mara as political pressure and require forward movement every cycle (`.claude/agents/civic-project-oari/RULES.md:147-165`; `.claude/agents/civic-project-health-center/RULES.md:165-183`; `.claude/agents/civic-project-stabilization-fund/RULES.md:217-233`). `readPersonaDir` loads those RULES for project calls (`scripts/cron-civic-run.js:1254-1265`). **Input → wrong output:** a neutral record question can be recast as pressure to move a phase or make a decision, and an elected seat still sees a must-answer instruction despite a quiet-week design. The M1 acceptance/test boundary should include the prompts and RULES actually shown to those seats; protected-file changes need the Claude lane.

6. **MEDIUM — The memory write and isolated proof paths are unspecified.** `lib/supermemory.js:38-83,105` offers `search` and `searchContext` only; errors, bad JSON, and a missing key return `[]` (`:11-14,73-80`). The design requires a screened `mara-world` copy and one append per run but lists no write implementation or verification (`docs/plans/2026-10-31-civic-autonomy.md:252,268,270`). `memory_note` on POP-00507 is a real `/v3/documents` write through `lib/citizenPage.js:146-180`; the desk loop's `dryNote` interception exists only when the executor receives that flag (`scripts/cron-desk-writer.js:928-941`). **Input → wrong output:** a failed `mara-world` search is presented as empty institutional memory, or a C114 “isolated” proof writes to Mara's live citizen page while only the new container is redirected to scratch. An explicit writer/readback, no-fallback-to-`mara` rule, screened copy receipt, and interception of *both* memory writes are needed before proof. Otherwise an Owner entry copied from the manual `mara` container could enter a cron prompt; the current plan's “screened” adjective is not a testable gate.

7. **MEDIUM — The reused tool loop needs a bounded transport and side-effect contract.** The loop hardwires its executor and sends each tool result through `cap(result, 8000)` (`scripts/cron-desk-writer.js:951-985`); its raw HTTPS request has no timeout (`:578-605`). It records token totals and a tool trace, not price or per-request finish state (`:959-991`); the local rate table lacks `openai/gpt-6.1-sol` and defaults to `$0.50/$1.50` per million (`:251-264`). The plan's tool loop, full-text promise, timeout increase, fallback, and cost manifest (`docs/plans/2026-10-31-civic-autonomy.md:250-253,270-272`) therefore need explicit changes beyond injecting an executor. **Input → wrong output:** a slow Sol request can hang instead of reaching the one-retry/Gemini path; a long Sheet or memory result is silently truncated despite “no character caps”; a successful `promise_record` or `memory_note` in an earlier turn can be duplicated by a whole-run retry after a later transport failure. A manifest cost computed from the existing default rate underreports Sol. Require per-request timeout, explicit result-size policy, retry/idempotence boundaries for write tools, and Sol-specific metering.

## Model, cost, and bounded checks

- **Model/gate:** OpenRouter currently lists [`openai/gpt-6.1-sol`](https://openrouter.ai/openai/gpt-6.1-sol) with tools and reasoning support at **$2/M input, $10/M output** before cache effects. The current friction check compares provider family to the mayor's model (`scripts/cron-civic-run.js:1007-1013`); the gate gathers writer families and selects Anthropic Haiku 5.5 first (`scripts/cron-civic-gate.js:83-110`). The Sol choice itself fits these two rules. `--model` overrides must continue through the friction check, and a Gemini fallback must be recorded as the actual writer model.
- **C114 cost envelope:** The local selected fields measure **220,976 characters** before prompts, move-ledger answers, open promises, edition, and tool results: Sunday statements 105,471; weekday `statement+moves` 16,745; world summary 47,909; HIGH patterns 3,206; tracker 24,166; three directives 19,114; persona 4,365. `editions/cycle_pulse_c114.txt` is absent. At a rough four characters/token this is **~55k input tokens**, or **~$0.11 per request** at the listed Sol input price. One response is about **$0.12-$0.14** if it uses 1k-3k output tokens. Eight sequential tool calls cause nine model requests (`scripts/cron-desk-writer.js:961-989`), about **$0.99 input** for the unchanged prefix and **~$1.08-$1.26 total** if each response uses 1k-3k output tokens. Tool outputs and accumulated conversation add input cost; retries, larger reasoning output, and cache behavior can move the bill materially. These are estimates from measured local bytes, not tokenizer or billing receipts; the plan's `$0.50-$2/week` is not a one-pass estimate for this input.
- **Confrontation/hood check:** The planned test should prove both that a C115 zero-block directive clears C114 `open` and that historical accepted answers still resolve their recorded `sourceText` in `civicProblemContinuity.js:24-34`. A new Why/Address can mention more than one neighborhood, so a new-format answer may touch every named hood, regardless of what the seat actually answered; that inference is current behavior and should be visible in the fixture.

Disposition: settle findings 1-4 before treating M1 as build-ready. Findings 5-7 define additional implementation and proof gates. Source and saved-output review only; no live behavior or provider bill was verified.
