# pipeline.73 lived wake and mint flags — implementation review

**HOLD the live wake change and the mint-flag path.** This is a source review of `4681760d` and `8d449968`, not a live Sheet or cron readback. The existing targeted tests pass, but they do not exercise the failure paths below. In particular, the active media intake writer can queue `CIV=pending`, which the new mint validator throws on when that row takes the new-citizen branch.

1. **FIX — seven card findings, as built.** (1) **Mostly landed:** birth uses the parent's line, held promotions are excluded, hospital uses the stay ledger, and death routes to a survivor (`lib/wakePerception.js:669-729`); distinct same-kind events in one Cycle still share an id (`:683`, `:691-692`). (2) **Partly landed:** the include branch preserves the old floor for ordinary rows and marks added rows `livedOnly` (`:403-450`); the existing LifeHistory-length gate still excludes some event recipients (`:416-420`). (3) **Partly landed:** spend is keyed by event id and a two-Cycle window exists (`:655-658`, `:752-768`), but id collisions, stale local Cycle/year, and unsynchronized crons remain (`scripts/citizen-wake.js:294-305`, `lib/getCurrentCycle.js:74-99`, `lib/citizenDerivation.js:32-41`). (4) **Partly landed:** dry-run exits before spend and the save is checked after the page append (`scripts/citizen-wake.js:387-390`, `:401-409`, `:469-484`); a crash or concurrent wake can still repeat it. (5) **Partly landed:** blank household IDs stay separate and BirthYear is checked (`lib/wakePerception.js:763-767`), but the household dedupe set exists only for one call and age uses a separately resolved year (`:758`, `scripts/citizen-wake.js:304-305`). (6) **Landed in the mint branch:** CIV/MED/UNI now map to ledger yes/no cells, blank remains blank, and bad values throw (`phase05-citizens/processAdvancementIntake.js:647-650`, `:831-849`); other queue writers were not reconciled (hunt 6). (7) **Partly landed:** lived sits after voiced and before posture, with a cap of seven (`scripts/citizen-wake.js:174-204`, `lib/wakePerception.js:655-656`); the cap/window can still expire wanted events (hunt 3). The plan's “Step 1 as built” states stronger guarantees than these paths prove (`docs/plans/2026-10-11-media-extension.md:253`).

2. **FIX (medium) — `buildPool({include})` is additive at the shape floor, but not a full news-grade bypass.** The old checks for valid dials, LifeHistory of at least 25 characters, name, and hood still run (`lib/wakePerception.js:403-421`). A previously accepted row is not dropped by the changed shape predicate: a row at or above `shapedMin` takes the same path, whether included or not (`:407-413`). A non-included row below that floor cannot enter; a non-included row above it correctly remains an ordinary pool member. An *included* under-floor patient with a short/blank LifeHistory still fails at `:416-417`, despite a Hospital_Ledger event. The no-option pool remains old-shaped; passing `include` intentionally adds fields to its objects (`:450`), so the reported live JSON equality for no option does not establish equality for the wake's include call. Keep the minimum non-shape requirements explicit, or allow the qualifying event itself to satisfy the history requirement.

3. **HOLD (high) — once-per-event and retention are not guaranteed.** Forced selection bypasses the lived pick and can choose an included `livedOnly` row; voiced selection can choose a normally shaped event recipient. Neither spends its event, and the later lived pick ignores `state.recent`, so the same person can be awakened again for it (`scripts/citizen-wake.js:165-190`, `:304-307`, `:469-477`). `birth:POPID:Cycle`, `promotion:POPID:Cycle`, and `hospital:POPID:Cycle:phase` collapse separate same-kind events in a Cycle; a second admission or birth cannot get its own receipt (`lib/wakePerception.js:679-692`). Birth household dedupe is ineffective across wakes because `seenHh` is recreated on each `pickLived` call, then the function returns after its first event (`:758-768`). The page write precedes the local state save; a crash, failed save, or two crons reading the same state can select the same event again (`scripts/citizen-wake.js:82-83`, `:401-409`, `:469-484`). Page `customId` deduplicates only a *person/Cycle/daypart*, not an event across dayparts (`lib/citizenPage.js:57-66`); the after-save readback logs failure but does not recover it. Seven lived wakes per Cycle plus a current/prior-Cycle window means an eighth event can be carried to the next Cycle, then expire when that window closes if capacity/voiced slots still prevent selection (`lib/wakePerception.js:655-656`, `:668`, `:755-756`; `scripts/citizen-wake.js:165-190`). Use a durable receipt keyed to the actual source event, serialize/claim wakes or reconcile page receipts on retry, and make backlog expiry an explicit policy.

4. **FIX (high) — survivor priority can discard a death wake.** The code chooses spouse, then lexicographically first household resident, then child, parent, bond *before* `pickLived` checks age and pool eligibility (`lib/wakePerception.js:709-729`, `:762-765`). A 10-year-old spouse/household member or a person outside the wake pool wins the priority, after which `pickLived` skips the death event without trying an adult child, parent, or bond. The living map excludes `Status=Deceased/Archived` rows, which is good, but it does not explicitly exclude the deceased POPID itself; a contradictory still-active ledger row can select self as household member or bond (`:697-725`). It also does not cross-check the archive for other chosen recipients. Build an ordered list of eligible, distinct, living adult recipients and try the next candidate when one fails; test minor-first, out-of-pool-first, self, and archived cases.

5. **FIX (high) — raw event text reaches the voice, including a real numeric promotion.** Birth's writer says “welcomed a new child into their family” (`phase04-events/generationalEventsEngine.js:1112`); `renderLivedLine` prefixes that unchanged text with “in your own life”, producing the wrong person for a first-person prompt (`lib/wakePerception.js:746`, `scripts/citizen-wake.js:236-237`). The completed promotion writer constructs `verb + ' after ' + Math.round(years) + ' years...'` and logs that text (`phase05-citizens/educationCareerEngine.js:367-382`), so a normal promotion can already put a number in the voice. The same raw path can carry an id if a future writer includes one; the no-number test uses only curated fixtures (`lib/wakePerception.test.js:90-103`, `:130-132`). Hospital `Cause` is copied verbatim after “after” (`lib/wakePerception.js:686-692`, `:743-745`). Current generated admission causes are human prose (`phase04-events/generationalEventsEngine.js:1489-1514`), but Hospital_Ledger also receives raw `HealthCause` from ledger reconciliation and event backfill (`phase10-persistence/buildCyclePacket.js:872-885`, `:945-949`, `:1061-1065`); no renderer sanitization or type check makes arbitrary cause text safe. Render from bounded event templates and scrub/validate dynamic text before prompt injection.

6. **HOLD (high) — an active intake writer emits an invalid flag.** Blank stays blank and `y/yes`, `n/no` fold as intended; the throw applies only to the *new-citizen* branch (`phase05-citizens/processAdvancementIntake.js:799-849`), and a bad value aborts the pass before queue clear (`:1020-1043`). `flagCitizenForTierReview_` is called for profiled/featured usages (`phase07-evening-media/mediaRoomIntake.js:329-332`) and appends `[citizenName, '', '', '', '', '', 'pending', 'Media ...']`: `pending` is positional G/CIV under the canonical schema (`:686-706`, `schemas/SCHEMA_HEADERS.md:24-40`). Because it puts the full name in First and leaves Last blank, ordinary split-name ledger matching can fail, taking the new-citizen branch and throwing on CIV. This row already had a malformed name/notes layout; the new validator turns it into a whole-pass failure. The other inspected writers use blank flags or `yes`: media usage routes blanks at `mediaRoomIntake.js:443-457`, category entries use yes at `:1105-1124`, emergence/family/owner/household queues initialize full header-width blank rows at `processAdvancementIntake.js:1706-1723`, `:1913-1926`, `:2108-2121`, `:2330-2341`; `scripts/seedBusinessOwners.js:76-83`, `:90-109` forwards the owner door's rows. Reconcile the `pending` writer before treating all queue cells as y/n; inspect actual queued G/H/I values before the next mint.
