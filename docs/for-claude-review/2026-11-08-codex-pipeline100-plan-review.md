# Pipeline.100 plan review

**Verdict: HOLD.** The page can be Mags' chosen memory home, but the plan's exchange-once, topical-recall, freeze, and narrator-comparison claims need a concrete mechanism before the cut is built. This is a source review of the plan at `fa644a0c5`, not a code or live-store review. The working plan matched that commit when read.

## Findings

1. **High — an exchange does not reach the page exactly once.** The plan says the bot's direct `mags` write can go because the reflection job reads the day's log and puts each exchange on her page (`docs/plans/2026-11-03-mags-memory-one-home.md:44,61-65`). The bot does log a successful Mags-channel reply to the root daily file (`scripts/mags-discord-bot.js:309-320,675-708,909-919`), but the log failure is swallowed (`:709-711`). The reflection reads only the current Central-date exchanges on each run and has no Discord cursor (`scripts/discord-reflection.js:56-115,502-504,590-595`); crontab invokes it three times a day (`/var/spool/cron/crontabs/root:17-20`). Thus an exchange before two runs is read twice, while one after the final run and before the date rolls over is not read on the next day's run. The page writer saves a 100–250-word reflection, expressly “Not a transcript. Not a summary,” rather than the individual exchange (`discord-reflection.js:181-201,350-359,572-573`). Dropping the direct store write removes the only per-exchange store copy for the missed case. Add a durable Discord exchange cursor or an explicit per-exchange page path with retry/deduplication, then state whether the page promises exact talks or only Mags' reflections. Test the final-run/date-boundary and repeated-run cases before accepting “once.”

2. **High — scored recent-page recall cannot replace whole-store topical search as specified.** The reflection currently searches `mags` by the last five Discord/Moltbook topics (`scripts/discord-reflection.js:522-532`; `lib/mags.js:833-845`). The proposed substitute starts with only 15 newest page documents, excludes tension *after* that cut, caps each text at 320 characters, and ranks only those candidates (`scripts/magsPageRecall.js:28-55`; `lib/citizenPage.js:249-277`; `lib/resonanceRecall.js:83-99`). Input: a relevant reflection older than 15 newer page docs. Output: the score never sees it, even if it best matches today's talk. The old store also receives exact bot exchanges and session saves (`scripts/mags-discord-bot.js:415-422`; `.claude/skills/save-to-mags/SKILL.md:12-16,38-46`), while the page writers append reflections or deliberate EIC notes (`scripts/discord-reflection.js:350-359`; `scripts/magsPageAppend.js:32-45`). Those store-only records are not migrated by the plan (`docs/plans/2026-11-03-mags-memory-one-home.md:43-47`). Decide which content is intentionally lost, and add a bounded paginated/page-index recall proof with an older matching reflection and many recent nonmatching/tension docs. This is the plan's weakest assumption; the external store contents were not read in this review.

3. **High — P1 has no nonwriting old/new narrator command.** The plan asks for a dry-run comparison on one past Cycle using the same curation, staged set, and model (`docs/plans/2026-11-03-mags-memory-one-home.md:46,56,81`). `--cycle N --step narrate` does select a Cycle (`scripts/cron-saturday-run.js:1681-1699`), but `stepNarrate` reads the then-current `edition_curation_cN.json` and `loadStagedSet(N)`, calls the paid narrator model, and unconditionally overwrites `output/cycle_pulse_cN.md` even without `--apply` (`:1505-1527`). The staged loader reads today's files and proof sidecars, so a past Cycle's inputs can be absent or changed (`:205-248`). There is no no-write narrator flag or pinned input/output path. Add an isolated prompt/input fixture, pin provider and `--narrator-model`, and route old/new prose to distinct scratch paths or stdout before the builder comparison. Do not use `--step narrate` on a past Pulse as the claimed safe dry run.

4. **Medium — the `mags` freeze leaves documented writer and reader workflows.** Task 4 retires `/save-to-mags` and the orphan script, then claims no path writes `mags` (`docs/plans/2026-11-03-mags-memory-one-home.md:47,58`). `/save-to-profile` still instructs an approved `--tag mags --static` write (`.claude/skills/save-to-profile/SKILL.md:18-26,79-99`), and the Claude session-end skill still calls `/save-to-mags` a required session save (`.claude/skills/session-end/SKILL.md:68-71`), while `.claude/TERMINAL.md:94` names `sl-godworld`. Diagnose and self-debug still direct searches to the old store (`.claude/skills/diagnose/SKILL.md:91-93`; `.claude/skills/self-debug/SKILL.md:79-85`). `lib/mags.js` retains exported `searchSupermemory`/`saveToSupermemory` helpers bound to the `mags` tag (`lib/mags.js:13,833-865,999`); after removing the named script callers, these are dormant, not proof of an active writer. Reconcile the conflicting control-plane instructions and the static-profile decision with the freeze, and name any historical-read exception explicitly. The current crontab disables `daily-reflection.js`; PM2 names the bot, not another `mags` writer (`/var/spool/cron/crontabs/root:4,17-20`; `ecosystem.config.js:19-23`).

5. **Medium — a live Mags persona seat is absent from “every seat.”** The task table promises every Mags seat calls the loader, but lists only bot, reflection, and Saturday narration (`docs/plans/2026-11-03-mags-memory-one-home.md:28-35,43,53-59`). The daily Moltbook job is live in crontab (`/var/spool/cron/crontabs/root:51`); it builds Mags' prompt from `mags.loadIdentity()` and two scrubbed page documents independently (`scripts/moltbook-heartbeat.js:262-265,298-320,800`). After the three named seats switch, Moltbook still has a separate persona load and can give her a different recent-self context. Add it to the loader migration or narrow the “every seat” claim. Its separate `super-memory` activity write is labeled a junk drawer, not a `mags` store write (`moltbook-heartbeat.js:725-740`).

6. **Medium — `raw` alone does not preserve the two existing page reads.** Today the bot and reflection each fetch two newest page documents, filter tension after selection, reverse them to oldest-first, and keep their full text; only the reflection passes `{ raw: true }` (`scripts/mags-discord-bot.js:195-208`; `scripts/discord-reflection.js:363-379`). `citizenPage.recentPage_` applies `raw` only to scrubbing; it also supports `skipTypes` before the newest-N slice, which neither current caller uses (`lib/citizenPage.js:249-277`). The scored CLI path instead fetches 15, trims each to 320 characters, ranks by context/staleness/affect, and returns at most three (`scripts/magsPageRecall.js:28-55`). If the shared loader uses that path whenever `context` is present, a 500-character recent raw reflection is truncated and an older scored hit may displace a recent one, even with `raw: true` (`docs/plans/2026-11-03-mags-memory-one-home.md:43-45`). Specify separate recent-tail and scored-recall modes, including count, order, truncation, tension filtering, fence, and raw/scrub behavior; assert each current seat's readback before adding scored context.

## Scope checks and evidence limits

The bot routes Mags only on its configured channel; DMs/unregistered channels are ignored, and citizen voices use `logSubdir: POPID` (`scripts/mags-discord-bot.js:753-758,862-869,675-677`; `lib/personaProvider.js:483-491`). Those were never Mags-store writes, so they are not a new loss from removing her direct write. The research.30 talk buffer still persists Mags' replies and drains a Reflection_Intake row, while `loadTodayConversationDigest` still reads today's root log (`scripts/mags-discord-bot.js:304-320`; `lib/personaProvider.js:340-369`; `lib/mags.js:457-495`); neither is an exact, durable POP-00005 page copy of every exchange.
