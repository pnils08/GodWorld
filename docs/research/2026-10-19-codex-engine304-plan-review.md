# engine.304 — plan review

Source review only, current checkout. No Cycle, test, model, cron, Sheet, bench, canon, or live read. Verdict is on the design in plan lines 472–507, not on an implementation. **Final gate: HOLD cut 1 and cut 2 as written; revise D9 and the identity/arrival and usage contracts below, then review the diffs.** R13–R19 remain fixed.

## 3. D2–D3 — draw and fit — FIX

- `Σ min(1,Dw/Σw) ≤ D`, with equality only if no citizen saturates; so D2’s “expected draws D” and test `Σp = D` need the unsaturated precondition. At the cited C112 weights no saturation is apparent. One draw per eligible citizen plus seeded shuffle is reproducible only if all use `safeRand_(ctx)` in stable ledger order; the existing family door excludes manual runs without `ctx.rng`/seed (`processAdvancementIntake.js:1760-1764`). Document this and test replay. The tier/heritage weights change *who* draws, not the 1% expected citywide count.
- D2 must reserve one spouse link, each missing child count, and each missing parent count; the existing slot tests are only one Boolean per type (`processAdvancementIntake.js:1818-1850`). D3’s age/sex/BirthYear/near filters cover the stated rules. `bondProximity_` is already used by courtship (`bondEngine.js:2679-2689`). `ctx.civicGcTaken` is needed because civic mint flips at Phase 10 (`updateCivicApprovalRatings.js:1710-1717`); wave and bond wedding flip GC directly before advancement (`checkForPromotions.js:510`, `bondEngine.js:2634`), so a fresh GC read sees them gone.
- Name admission cannot be settled only at link time. `processAdvancementRows_` checks ledger names when a queued row mints, then skips a colliding family row (`processAdvancementIntake.js:689,722-749`); another citizen may take the surname before a linked GC emerges. `markAsEmergedInGeneric_` currently flips the first matching GC row regardless of Status (`:2651-2674`). D3 must check normalized ledger *and all GC aliases*, plus pending intake names, then D6 must recheck at arrival and identify the exact linked GC row (or fail closed); a First+Last then First+MaidenName fallback alone can flip a different row.
