## 3. D11c arrival — **FIX**

- The emergence door and immediate pre-mint check both currently require Active (`phase05-citizens/processAdvancementIntake.js:1817-1826,837-861`). Both must use the *same* ledger-first/deceased-archive resolver as D11a. Route dead anchors to the new one-row writer, never to `wireFamilyMatch_`, which mutates both sides (`:2678-2780`).
- The plan says blank HouseholdId lets “the household pass form one” (`docs/plans/2026-10-08-engine-286-game-of-life-events.md:537`). That is false for a childless widow or a newly arrived parent of a deceased child: `formCriteriaHouseholds_` admits married adults, adults with *living on-ledger children*, orphan minors, or a chance-based high-income solo (`phase05-citizens/householdFormationEngine.js:389-421`). A widowed adult is not married; the dead child is absent from the active `byPop`/`onKids` test (`:362-403`). Specify that they may remain without a HouseholdId, or add a separately ruled formation door; test widow, child, and parent with no active housemate.
- Parent arrival needs `NumChildren >= 1` as well as ChildrenIds: the existing live writer sets it (`phase05-citizens/processAdvancementIntake.js:2724-2730`); D11c specifies only ChildrenIds (`plan:537`). Otherwise the new row can say it has no children even while naming its dead child. Preserve a greater credible count from mint if present.
- One-sided history has real reader limits. Heritage resolves archived parents/spouses from the arriving row (`phase05-citizens/generationalWealthEngine.js:2720-2721,2753-2777`); inheritance already ran at death (`:1320-1353`). The wake's `loadFamily` resolves names only against the live ledger, so an archived spouse becomes unnamed “You're widowed” and an archived parent disappears from the named parent line (`lib/wakePerception.js:214-232,253-284`). `livedEventsFrom` uses the *dead archive snapshot's* spouse/child/parent IDs to route death (`:728-752`), so later one-sided arrivals are absent from those recipients unless they share the recorded household. Archived citizen cards also render the frozen archive snapshot (`scripts/buildCitizenCards.js:828-852`); the arriving card does show its own ParentIds/ChildrenIds (`:650-667`). These are limitations to state explicitly; no reader shown throws solely because an ID points to the archive. `Family_Relationships` is appended only when criteria forms a household (`householdFormationEngine.js:461-483`), so the unformed widow/parent has no registry row through this path.
