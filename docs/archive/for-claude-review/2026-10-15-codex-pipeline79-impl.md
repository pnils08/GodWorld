# pipeline.79 implementation review — Codex

**Target:** `47531b52` on `734db7cd`. **Overall gate: HOLD.** Source and local artifact review only; no cron, model, Sheet, or canon run. The C111 backfill hashes pass, but the Saturday path can award publication credit without a completed publish, and the selected list does not always favor graded work.

## 1. Grade binding — FIX

`loadStagedSet` loads the Article bytes, checks a passing proof against their SHA-256, rejects duplicates, and passes that SHA to `stagedGrade` (`scripts/cron-saturday-run.js:193-239`). A failed/flagged proof or a root verdict from a rerun with different Article bytes cannot directly supply a grade: both candidates must have `pass === true` and the outer `draftSha256` must match (`scripts/cron-saturday-run.js:127-133,136-143`). The sidecar proof is tried before the mutable root verdict.

The binding stops one level too early. `stagedGrade` accepts any integer `proof.contractScore.score` without checking the score's own `draftSha256` or its 0–4 range (`scripts/cron-saturday-run.js:127-132`). The live gate's score has no inner hash (`scripts/cron-rhea-gate.js:845-856`); staging and reconciliation copy it unchanged (`scripts/cron-desk-run.js:98-109`; `scripts/reconcileRheaDisposition.js:243-250`). Thus a passing outer proof for Article B can carry a score produced for A, and a malformed integer can lead the sort. Bind the score to the staged bytes at creation and verify it at ranking; constrain the score to 0–4. This is a missing invariant, not evidence that the current 12 backfills are mismatched.

## 2. Curation order — FIX

The initial ranked array sorts integer grades ahead of `null`, then uses the prior curation score as a tie breaker; explicit `canon-violation` scorecard entries are removed (`scripts/cron-saturday-run.js:894-908`). The two-pass selection changes the effective order: it fills all `--top` slots with unique storyline slugs before admitting any second article from one slug (`scripts/cron-saturday-run.js:909-920`). For `--top 2`, grade-4 A and grade-3 B on one slug plus ungraded C on another select A,C; B is excluded. The output log prints `ranked.slice(0, top)`, which can differ from `selected` (`scripts/cron-saturday-run.js:921-925`). If “best-graded” governs selection, this needs an explicit grade floor/ordering rule for the diversity pass.

The audit filter is also incomplete: a staged stem absent from the scorecard gets verdict `unaudited` and remains eligible (`scripts/cron-saturday-run.js:897-905`). The sweep's corresponding helper excludes only listed violations (`scripts/cron-saturday-run.js:315-320`). A newly staged or renamed item after audit can enter curation without an EIC verdict. Require scorecard coverage of the exact staged set before selection. `stepPublish` and `stepSweep` both read `curation.selected` (`scripts/cron-saturday-run.js:329-332,981-993`); that is consistent when the staged set stays fixed, though neither pins its Article bytes across steps.

## 3. `byline-published` rows — HOLD

`bylinePublishedRows` treats membership in `edition_curation_cN.json.selected` as “printed” (`scripts/cron-saturday-run.js:379-390`). `stepSheets` writes those rows from the staged set and deduplicates on exact `(CitizenName, UsageType, Context)` (`scripts/cron-saturday-run.js:392-435`). The full runner catches a failed `stepPublish` and still runs sweep and Sheets; a standalone `--step sheets --apply` also has no publication check (`scripts/cron-saturday-run.js:1114-1126,1131-1163`). `stepPublish` can fail at `ingestEdition` or NotebookLM after assembling the local edition (`scripts/cron-saturday-run.js:1011-1032`). Consequently a curated Article can earn MEDIA publication credit before the canon door completes. Gate the row on durable publication evidence for the exact selected edition, including recovery/retry.

`bylinePopid` is included in the transient row but never written or validated against the ledger (`scripts/cron-saturday-run.js:387-389,421-430`). The engine resolves by normalized name, not POPID: one leading honorific is stripped, so the literal forms `Sgt. Rachel Torres` and `Dr. Lila Mezran` are parseable; `Jordan Velez` is already a two-token name (`phase05-citizens/processAdvancementIntake.js:279-302`; `output/cron-compare/staged/business_c111_business-desk_packet-v2_anthropic-claude-opus-5-5.staged.json:5-8`). Actual unique matches require a ledger read, which this review did not perform. A zero/ambiguous match is marked processed and counted skipped; zero-match has no specific log and cannot be retried from that row (`phase05-citizens/processAdvancementIntake.js:403-441,475-499`). `earnedCitationsByKey_` and MEDIA promotion use the same name key, so an unresolved or misresolved row does not reliably credit its intended POPID (`phase05-citizens/processAdvancementIntake.js:1214-1239,1293-1310`). Resolve uniquely before append and fail loud with the sidecar POPID as a check.

The other writer only acts on an edition with an ARTICLE TABLE (`scripts/ingestPublishedEntities.js:973-989`). Saturday's assembled edition has byline blocks but no such table (`scripts/cron-saturday-run.js:988-1012`), so this scheduled path does not itself double-write through that writer. If the ARTICLE TABLE writer is later run for the same article, its `E<cycle> <slot/headline>` context differs from Saturday's stem context (`scripts/ingestPublishedEntities.js:980-987,1020-1044`), and their exact-key dedup will allow double credit. A shared publication/article identity is needed across both writers.

## 4. All-seat reward loop — FIX

All 25 package entries now have `rewardLoop: true`; a read-only JSON inspection found no missing assignment POPID, purpose, opening, closing, or target words. Ten word targets say `evidence-bounded`, one has two ranges, and the remainder have other targets (`scripts/newsroom-wake-packages.json:131-168,1175-1212,1245-1282`). The gate intentionally lets the judge handle evidence-bounded and two-range length while code counts a single range (`scripts/cron-rhea-gate.js:325-375`). `SOURCE_BRIEF` changes Packet writing mode (`scripts/livedExperiencePacketV2.js:272-281`), and the writer prints the Packet contract rubric (`scripts/cron-desk-writer.js:434-446`). These shapes have a score path; the review does not establish live model success.

There is a concrete same-rubric break for Luis Navarro. In a `RECORDS_BRIEF` Packet, `buildWritePacket` replaces his two-range contract with a 400–700 target and different opening/closing (`scripts/livedExperiencePacketV2.js:249-268`; `scripts/newsroom-wake-packages.json:159-168`). The writer sees that Packet rubric, while `loadReviewContext` chooses the original wake package profile over the Packet profile and checks only profile ID (`scripts/cron-rhea-gate.js:402-425`). The judge therefore grades against different length/opening/closing instructions from the ones shown to the writer. Use the exact validated Packet profile for scoring, including contract fields, or keep one immutable contract through W3 and gate.

The daily and weekly Nia packages share `POP-01076` but have different review profiles and word ranges (`scripts/newsroom-wake-packages.json:1175-1212,1245-1282`). W1 reads the newest generic `graded:` line from that POPID's page, with no package or article identity, so either seat can learn from the other's grade (`scripts/cron-desk-run.js:1505-1511,2083-2094`). Grade writes use the same `popid/cycle/PRESS/graded` custom ID for both seats; a same-Cycle pair collides at the page store (`scripts/cron-desk-run.js:3168-3180`; `scripts/citizenVoice.js:195-204`; `lib/citizenPage.js:57-66`). Key and retrieve feedback by package/article.

A reporter without a page is not inherently blocked: W1 sees an empty recent-page result and logs no grade; the later grade write calls `ensurePagePointer_`, which creates and verifies a ledger pointer if the POPID exists (`scripts/cron-desk-run.js:2083-2094,3172-3180`; `lib/citizenPage.js:132-160,164-192`). That path requires external Sheet/Supermemory operations and was not exercised here. A failed write is nonfatal and leaves the feedback loop unproven for that seat (`scripts/cron-desk-run.js:3174-3180`).
