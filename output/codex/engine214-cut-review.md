**Recommended ruling:** retain fail-loud validation of malformed graph/anchor inputs, but validate them before a live Cycle can proceed; an unrecoverable graph error should prevent dependent simulation writes, rather than merely return false inside this wrapper. Do not invent a cluster or quietly restore the twelve-hood literal. For a provisional tie, continue the synchronous flood first as described above (`phase02-world-state/applyCityDynamics.js:661-705`).

If the owner instead chooses runtime degradation, it must be a **named, tested policy**: log the unresolved hoods, preserve valid dynamics, identify exactly what unresolved hoods receive, and prove downstream behavior. A bare Logger message plus early return still produces the same missing-output cascade; simply changing `throw` to `return` is not a fix (`phase02-world-state/applyCityDynamics.js:1845-1886`; fallback consumers above). This review does not authorize a control-plane or sim-policy change.
