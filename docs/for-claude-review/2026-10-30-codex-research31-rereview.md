## Findings

1. **HOLD — F1's readback does not require the copies to exist.** `planPointsRescore` only marks an intake or pack stale when that copy is found (`scripts/undockedEpisodeAdapter.js:830-838`); `applyPointsRescore` reports an approved but absent tab row separately from mismatches (`:900-913`), then checks only stale *existing* copies (`:936-945`). The CLI exits 1 only for `mismatched`, even when `noFeedRow` is nonempty (`:1025-1033`). Input: an approved archived night has a valid derived 5 points, its staged file already says 5, and its feed-pack event or approved tab row is absent. Output: the missing representation is not repaired, and `--apply` can print “every copy agrees” with exit 0. The same applies to an absent intake file: there is no `Applied`/EpisodeId to bind the tab check. The revised stale-list mechanism does repair a failed write to a copy that still exists; it does not prove four-copy completeness.

2. **HOLD — F2 still converts blank summary points into a measured zero.** `num` calls `Number(v)` (`scripts/undockedEpisodeAdapter.js:138-140`), and `accountFrom` applies it to `summary.points` without the blank/null guard used for earned achievement points (`:740-754`). Input: `{summary:{points:''},achievements:[]}` or `points:null`. Output: `accountFrom` returns `{total:0,invalid:null}` and `derivePoints` emits measured 0 for a night (`:259-279`). I ran both pure local calls; an `undefined` summary point correctly returned invalid/unknown. A malformed blank account total therefore passes the reconciliation and can overwrite a genuinely unknown night with 0.

3. **HOLD — F6 engine and sidecar leaders are not equal for a feed containing an upcoming row.** `undockedStandings.compute` includes every valid `TargetCycle` in its cumulative Rank 1 (`scripts/undockedStandings.js:72-106,132-141`); `loadUndockedFeed_` admits only `TargetCycle <= S.cycle` to `S.undockedBoard` (`phase02-world-state/loadEventContentLedger.js:363-375,396-407`). The ordinary cron pushes `TargetCycle=next fire` and immediately recomputes standings (`scripts/cron-undocked-run.js:361-374`). Input at C114: aired A has 5 points and next-cycle B has 10. Output: a pure local `compute` call ranks B first, while phase02 still names A, so Nia's sidecar leader (`scripts/buildNiaSlice.js:55-68`) and `$LEADER` (`phase05-citizens/generateCitizensEvents.js:604-615`) can disagree before the next fire. For malformed rows, the boundaries also differ: standings rejects blank TargetCycle or EpisodeId (`scripts/undockedStandings.js:75-87`), while phase02 converts blank TargetCycle to 0 and does not require EpisodeId for the board (`phase02-world-state/loadEventContentLedger.js:363-375`). For valid aired rows, including blank PointsDelta, pilots with only blanks, ties, and a missing PointsDelta column, the source comparators both reduce to points, credits, lower POPID; I found no other reader of `S.undockedBoard.totals` that assumes its old membership.

4. **HOLD — `night_winner` can settle permanently before pending points are known.** The engine and Node mirror convert a blank `pointsDelta` to 0 for an eligible positive-credits row (`phase05-citizens/casinoLedgerEngine.js:189-217`; `scripts/casinoLedger.js:220-243`); the focused test explicitly accepts this (`scripts/casinoLedgerEngine.test.js:318-321`). Input: A's account read failed, so A's feed has blank points and +50 credits; B has measured 0 points and +20 credits; C has blank points and -5 credits. The night crowns A now. If C's pending unlock later settles to 5 points, the points-first winner becomes C after A's slip was written as win/loss. The daily points settle may fail while the flight continues (`scripts/cron-undocked-run.js:320-329`); casino processes only OPEN slips and writes a settled status/payout (`phase05-citizens/casinoLedgerEngine.js:324-329,694-695,868-875`). The same pending state can cause a premature void when no positive credits are present. This is a timing/data-completeness gate, not a request to change the builder's points-first or no-gain rule. The `credits_sign` and `mishap` branches remain on their prior fields and predicates (`phase05-citizens/casinoLedgerEngine.js:265-288`).

5. **Conditional F7 attribution gap — account activity outside flights is assigned to the last show night.** `derivePoints` uses `[startedAt,nextNightStart)` and leaves the latest night's end unbounded (`scripts/undockedEpisodeAdapter.js:250-279,826-829`). Input: a reconciled account earns 5 points in independent gameplay after its latest flight and before another flight. Output: the previous show night gets +5 despite no show action earning it. This depends on the source comment's invariant that a pilot account acts only in its flights (`:250-258`); no provenance or end-bound check enforces it here. A valid read account with no unlock in an interval now yields measured 0 by explicit design, and an unreadable interval yields unknown (`:259-279`).
