# codex review — engine.270 Review 1 build

**Target:** commit `2086e0d8`; D1, D2, and Task 7 step 1 as ruled in `docs/plans/2026-09-28-storylines-keyed-to-engine-events.md:199-205`. The build notes at the end of that plan are claims under review, not the acceptance contract.

**Result:** **HOLD** the first unattended `--apply` attach pass (Sat 2026-10-31 16:00). Findings 1–3 can give `Storyline_Ledger` false or duplicate coverage, and finding 4 can make the attach pass falsely succeed. The source path for a successful full run does keep curation ahead of attachment; that narrower print-pick claim holds, subject to finding 5.

**Evidence boundary:** Read-only source review of the commit, current source, local C110/C113 audit and registry files, and C110 staged articles. No Node tests, Sheets calls, model calls, network calls, deployment, or live Cycle. Local JSON is a saved snapshot, not a live Sheet readback. No code or plan was changed.

## Findings

1. **HOLD — one printed initiative name can attach two different stage IDs.** `storylineAttachNames` strips ` — <stage>` from each initiative entry; `attachStorylines` iterates every matching entry without a stage or status discriminator (`scripts/cron-saturday-run.js:778-821`). The saved C113 registry has both `INIT-010:operational` and `INIT-010:vote-scheduled`, with the same base name and West Oakland hood (`output/desk_signal_c113.json:1513-1587`). Therefore an otherwise untagged West Oakland article that prints only “West Oakland Tenant Defense Fund” receives **two** `referenced` attaches, including the closed vote stage, whether or not it reports that transition. `aggregateStorylineSignals` counts each into its separate row and `mergeStorylineLedger` increments `Referenced` and `Articles`, changes `LastCycle`, and merges article metadata (`scripts/cron-saturday-run.js:631-660,680-735`). C113 is a concrete registry collision; this review did not observe a C113 article that took the double attach. Gate: make a same-initiative open/closed stage collision resolve only with stage-specific evidence, or leave it unattached for the later residue pass; test the actual C113 pair. The matcher also has no closed-window check: a crisis resolved at C109 remains in the C110 registry (`scripts/buildWorldSummary.js:796-797,871-873`; `output/desk_signal_c110.json:2035-2042`). That inclusion serves the known Firebrand C110 ending, but a generic later mention can still accrue coverage to a closed row.

2. **HOLD — attach recovery replays every already-counted signal.** A full-run `stepAttach` error is caught, then publish, sweep, sheets, and `stepSignals` still execute before the saved error is thrown (`scripts/cron-saturday-run.js:1630-1680`). The printed recovery instruction tells the operator to run `--step attach --apply` **then `--step signals --apply`** (`scripts/cron-saturday-run.js:1635-1638`). `mergeStorylineLedger` adds each week's `Advanced`, `Opened`, `Closed`, `Referenced`, and `Articles` counts to the existing row with no same-Cycle receipt or deduplication (`scripts/cron-saturday-run.js:704-735`); `stepSignals` calls that merge on every apply invocation (`scripts/cron-saturday-run.js:866-903`). If attach fails after zero or some sidecar writes, the full run still counts the then-visible signals once; the advised rerun counts all of those signals a second time, plus any newly attached signals. The `stepAttach` comment's “re-runs are no-ops” applies only to adding sidecar slugs, not to ledger values. Gate: make the signal upsert idempotent by Cycle or replace the recovery instruction with a receipt-backed, row-specific repair that cannot replay prior totals; test partial attach failure and retry.

3. **HOLD — sidecar writes are neither atomic nor protected from the other sidecar writer.** `stepAttach` reads each sidecar again, mutates `intake.storylines`, and truncates/writes the original JSON path directly; it does not recheck the staged proof, Article hash, cycle, status, or existing assignment against the hit computed from the earlier `loadStagedSet` snapshot, and it has no atomic replace or post-write readback (`scripts/cron-saturday-run.js:831-862`). `loadStagedSet` silently skips malformed JSON (`scripts/cron-saturday-run.js:205-229`). A failed or interrupted write can therefore remove a previously curated Article from the later publish/sweep/signals reads; `stepPublish` silently drops a selected stem absent from its reloaded set (`scripts/cron-saturday-run.js:1464-1481`). The separate `reconcileRheaDisposition` stage path rebuilds the same staged sidecar from the draft and preserves only `approval` from a prior sidecar, then atomically replaces the file; a later reconciliation drops any `attachedBy` entry (`scripts/reconcileRheaDisposition.js:223-270`). Rhea's exact hash proves Article bytes, not the new sidecar metadata (`scripts/cron-saturday-run.js:148-170`). Gate: atomic sidecar replacement, a current proof/identity check before commit, typed readback, and preservation or explicit invalidation of attaches across reconciliation. Test the on-disk step, not only the pure matcher.

4. **FIX — a missing or malformed registry is a successful zero-attach run.** `loadStorylineRegistry` returns `[]` on read/parse failure and on wrong shape (`scripts/cron-saturday-run.js:771-776`). `stepAttach` logs “nothing to attach to” and returns `{attached: 0, written: 0}` (`scripts/cron-saturday-run.js:831-837`), so the full chain sees no error. `stepSignals` only warns and can still write coverage rows without engine status (`scripts/cron-saturday-run.js:866-903`). An unavailable `desk_signal_c<N>.json` therefore silently defeats Task 7 on the first unattended run. Gate: distinguish a valid empty registry from unavailable/malformed input, fail the attach step and full run on the latter, and prevent a statusless signal merge.

5. **FIX — “prints the name” currently includes the unpublished INTAKE tail.** `loadStagedSet` loads the whole `.staged.md` as `entry.text`, and the matcher searches that entire string (`scripts/cron-saturday-run.js:221-248,811-820`). The article's `## INTAKE` block contains HOOD and CLAIM/source-reference lines (`scripts/cron-desk-run.js:1175-1187`), while the published/reader copy removes that block (`lib/articleIntake.js:230-242`). A name that occurs only in a claim or source reference can pass the attach match even though no reader sees it in the Article; a declared hood supplies the other half of the join. The new attach tests use short prose strings without an INTAKE tail (`scripts/cronSaturdayRun.test.js:219-250`). Gate: match against the same reader copy used for published prose, then test “name only in INTAKE” as a negative case.

6. **FIX / source-of-clock proof — D2 still turns a first-observed Cycle into a claimed start for later stages.** The ruling says there is no true initiative phase-start source and asks that `mergeStorylineLedger` stop feeding `FirstCycle` back as `startCycle` (`docs/plans/2026-09-28-storylines-keyed-to-engine-events.md:201-202`). The new `stageClock` calls a start “known” whenever *any* earlier row for that initiative exists, then sets `startCycle` to this stage's observed `FirstCycle` and prints a week count (`scripts/buildWorldSummary.js:843-853,902-917,929-944`; `scripts/cron-desk-run.js:1221-1236`). Yet the Saturday writer still records `FirstCycle` from the registry's `startCycle` or the current Cycle at first append, not from an engine stage-change event (`scripts/cron-saturday-run.js:719-727,748-758`). An earlier stage row proves that a different stage once existed; it does not date the move into the current stage. The accepted one-Cycle registry lag in the plan's D3 makes this material: a move after a fire can first enter the registry/ledger a Cycle later, and the packet then prints a week count based on that observation. Gate: keep such entries ageless until a sourced transition Cycle exists, or document and obtain a new ruling that explicitly accepts observation-based ages; test a transition between registry builds.

## Checks that do hold, and test limits

- **D1 targeted mechanism:** the C110 audit pattern names `INIT-003` in `affectedEntities.initiatives`, and the snapshot gives `design-phase` (`output/engine_audit_c110.json:27-53,3013-3037`). `patternStorylineTag` maps that ID to a tagged ref and leaves a pattern with no ID untagged (`scripts/buildWorldSummary.js:812-822,1189-1220`). I found no false D1 tag in the saved C110 case. The added test uses a synthetic `INIT-005` pattern, not the actual C110 pattern or a wake-3 sidecar (`scripts/buildWorldSummary.test.js:831-865`), so the production handoff is not proven by that test.
- **Print-pick ordering:** in the full chain, `stepCurate` runs before `stepAttach` (`scripts/cron-saturday-run.js:1625-1635`). On a later curate rerun, both tie-break score and primary slug filter out `attachedBy` entries (`scripts/cron-saturday-run.js:1254-1274,1357-1398`). This supports unchanged ranking when all sidecars stay readable. The new test checks only `curationScore`, not `primarySlug`, the selected list, or publish after a failed sidecar write (`scripts/cronSaturdayRun.test.js:247-251`).
- **D2 display guard:** a supplied `firstSeen: true` entry prints no week count, open or closed (`scripts/cron-desk-run.js:1221-1236`; `scripts/cronDeskStoryTemplate.test.js:159-173`). Finding 6 concerns how the builder sets that flag and its age, not this string formatter.
