# Care and justice Task 4 cut — adversarial review

**Scope:** Read-only review of commit `6a620209`, §Task 4 cut. This is a draft review, not implementation or live-sheet proof. No source files or Sheets were changed. The proposed `scripts/careJusticeIntake.test.js` does not yet exist; the eight items are a test plan, not passing tests.

## Findings for engine-sheet

1. **Block integration: `admission` is not an accounting receipt kind.** The cut proposes `kind: 'admission'` for three existing sites and chaos (`docs/plans/2026-09-21-care-and-justice-system.md:290-306`). The already installed fold accepts `intake`, `transition`, `transfer-in`, `transfer-out`, `exit`, and `correction`; it throws on `admission` (`utilities/careJusticeAccounting.js:46-53,75-95`). Its tests use `kind: 'intake'` (`scripts/careJusticeAccounting.test.js:73-78,100-107`). Either name the event `intake` now or explicitly require Task 8 to translate and test `admission` to `intake` at the ledger-to-census seam. The eight proposed Task 4 tests do not exercise that seam. Separately, Task 4's promise of *typed* receipts is only in memory: the current writer reads `popId`, `to`, `cause`, and `cycle`, builds an 11-cell row, and ignores all four proposed fields (`phase10-persistence/buildCyclePacket.js:877-915`). Typed ledger rows depend on Task 8.

2. **`recovering` produces a new `admission` receipt for an existing open case.** The chaos guard explicitly permits `recovering` (`phase04-events/chaosCarsEngine.js:341-351`). `recovering` is an open Hospital_Ledger state (`phase10-persistence/buildCyclePacket.js:811,867-873`); when that citizen gets an ambulance hit, the current writer updates the open row rather than admitting (`phase10-persistence/buildCyclePacket.js:882-900`). The plan's own invariant E says a second receipt while a row is open is a transition, not an intake (`docs/plans/2026-09-21-care-and-justice-system.md:255`). A later census that folds the new receipt as an intake will count one intake with zero new rows. Add a `recovering` + open-row test, then specify whether this hit is a transition or a new case with an explicit close/reopen. Preserve the current Status guard until that semantic choice is made.

3. **The stated chaos `cause` equality fails when HealthCause is already set.** The plan says the receipt cause is the prose written to HealthCause (`docs/plans/2026-09-21-care-and-justice-system.md:308`), but chaos only writes that prose if HealthCause is blank (`phase04-events/chaosCarsEngine.js:352-357`). Recovery retains the prior HealthCause until Status becomes `active` (`phase04-events/generationalEventsEngine.js:421-423`), so the `recovering` case above naturally has a nonblank prior cause. A hardcoded ambulance receipt would say the new emergency while the citizen row and possible death prose still say the old cause; the hospital writer copies the receipt cause into column E on a new row (`phase10-persistence/buildCyclePacket.js:893-896`). Test nonblank HealthCause, especially `recovering`, and specify which cause is authoritative. This is a provenance decision, not a reason to clear history silently.

4. **A post-push exception can leave an unkeyed receipt; a post-stamp exception can leave a receipt with no Chaos_Cars source row.** The proposed receipt is pushed inside `writeCitizenEvent_`, returned, and stamped only after the call (`docs/plans/2026-09-21-care-and-justice-system.md:309`). That function currently queues `LifeHistory_Log` after the Status flip (`phase04-events/chaosCarsEngine.js:349-390`); the caller then draws `eventId`, queues the Chaos_Cars row, and adds the payload (`phase04-events/chaosCarsEngine.js:559-587`). `safePhaseCall_` catches and continues after a thrown phase error (`phase01-config/godWorldEngine2.js:159-169`). If the first queue throws after the proposed push, Phase 10 can receive an unstamped admission. If the Chaos_Cars queue throws after stamping, the hospital receipt can persist while its named source row never does. Normal synchronous object mutation is sound, and drawing the id earlier would move eight rng draws (`phase04-events/chaosCarsEngine.js:44-48,573`); the missing requirement is failure behavior across these queued writes. Add fault-injection tests at both queue calls, and make the incomplete source/receipt set fail visibly instead of treating it as a complete intake.

5. **Existing ordinary-health code can mint an admission after a same-row death and can change a retiree's Status.** The regular milestone loop is reached by non-health statuses including `retired` (`phase04-events/generationalEventsEngine.js:371-447`). It runs the death check and writes `deceased`, but does not stop before the health check (`phase04-events/generationalEventsEngine.js:582-596`); a severe/moderate health result can then overwrite Status and emit the proposed admission receipt (`phase04-events/generationalEventsEngine.js:598-646`). `checkHealthEvent_` takes no Status argument (`phase04-events/generationalEventsEngine.js:1310-1315`). This is existing eligibility drift, not introduced by the four receipt fields, but the cut would label it as a valid intake. Proposed test 5 protects only a **chaos** retiree, and test 3 protects only an ordinary active injury. Add ordinary-health retired and death-then-health cases; route any behavior change as a separate engine ruling if preserving current behavior is required.

6. **The cluster side effect is broader than “one more admission.”** Phase 9 carries the first 12 hospital event objects with a neighborhood, discarding `kind`, `from`, and `to` (`phase09-digest/finalizeCycleState.js:295-303`). Phase 3 counts each carried object, with no POPID dedup (`phase03-population/generateCrisisBuckets.js:263-271,309-311`). A chaos admission plus same-Cycle lifecycle transition can therefore count twice for one citizen; adding the early chaos object can also consume one of 12 slots and drop a later admission. The cut notes the new cluster effect (`docs/plans/2026-09-21-care-and-justice-system.md:313`) but does not capture these two consequences. Task 9 can own the measure, but record these as expected interim behavior and add a targeted carry/cluster test if activation precedes Task 9.

7. **The sports writer citation does not prove a current source.** The cited `buildCyclePacket.js:964-988` is a reconciliation comment and reader, not a sports Status writer. The current `applySportsFeedTriggers_` shown at `phase02-world-state/applySportsSeason.js:673-750` writes summary sports effects, not citizen Status. I found no `StatusStartCycle` write outside chaos/generational in current `phase*/` JavaScript (the other matches are reads). Keep the missed-admission reconcile as a real fallback (`phase10-persistence/buildCyclePacket.js:824-853,963-988`), but cite the actual sports writer or qualify “sports roster injuries” as a historical observed case, not a verified current pathway.

## Correction — 2026-09-29

The source-check row about the three pre-cut ledger outcomes overstates the `active` exit. For a **new** ambulance flip to `critical` or `hospitalized`, the immediate Phase-5 lifecycle has no `active` branch (`phase04-events/generationalEventsEngine.js:106-117,718-765`). The supported no-record path is same-Cycle `critical` → `deceased`. The plan's `deceased`/`active` wording at `docs/plans/2026-09-21-care-and-justice-system.md:288` should be narrowed for this ambulance case.
