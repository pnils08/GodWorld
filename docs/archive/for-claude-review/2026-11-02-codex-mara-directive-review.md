# Mara directive — Codex source and saved-output review

Scope: the current `runDirective` path, the C111–C114 saved AUTO directives and target manifests, the C113/C114 local tracker snapshots and seat boards, and the named downstream consumers. This is a review of the mechanism and its text; it does not choose Mara's future policy. The builder direction is recorded in `docs/plans/2026-10-31-civic-autonomy.md:305`: civic life can include a crisis, but an initiative need not be a crisis response.

## Findings

1. **HIGH — Blank and failed tracker rows become false stall-clock targets.** `scripts/cron-civic-run.js:937-942,1145-1152` converts `NextActionCycle` with `Number(row.NextActionCycle)`. A blank string becomes zero, which passes `<= cycle + 1`; the predicate also never checks `Status`. **Input → wrong output:** at C114, `output/beats/Initiative_Tracker.jsonl:7,10-12` has blank `NextActionCycle` and `Status:failed` for INIT-008 and INIT-011–013. All four appear in the mayor's C115 stall-clock reason (`output/cron-civic/directive_c114.json:8-13`); D4 is targeted *only* by the three blank failed rows (`:33-37`). The C113 snapshot already had blank dates on these rows (`output/beats/prev/Initiative_Tracker.jsonl:7-12`). The saved C113/C114 mayor boards omit `nextActionCycle` for every row because `boardRowsFor` does not copy it (`scripts/buildCivicOfficeSlice.js:887-905`), so Mara's clock claim also relies on data absent from the seat's board (`output/cron-civic/packs/MAYOR-01_c113.json`, `MAYOR-01_c114.json`, `game.board`). C114 has seven of ten elected targets, all with a stall-clock reason, across 11 distinct initiatives; six of those 11 have `Status:failed` in the C114 tracker. The C114 output then asserts that INIT-011–013 “face C115 stall clocks” (`output/mara-directives/mara_directive_c114_AUTO.txt:27-30`) and that INIT-008 faces C115 expiration (`:11-14`), neither supported by those tracker dates. The remaining dated rows include C115 scheduled steps (`output/beats/Initiative_Tracker.jsonl:1-3,5-6,8-9`), but `NextActionCycle` is the *due cycle of the next step* (`docs/mara-vance/INITIATIVE_TRACKER_CONTRACT.md:60-61`), not by itself proof of a stall or default. This is a data and predicate artifact, not evidence that seven seats failed.

2. **HIGH — The directive prompt requires a crisis and an action-shaped confrontation.** `scripts/cron-civic-run.js:1023-1050` defines Mara as someone who confronts elected seats that “owe” an answer, demands an action this cycle, requires an account of what breaks on silence, and restricts traceable subjects to a hood moving the wrong way, complaints with no proposal, or a stall clock. The user prompt at `:1187-1193` tells her to press offices on “the crisis and the success” and says seats “must fight for their constituents.” **Input → wrong output:** even a normal scheduled C115 step is framed as an impending default; C114 output tells D8 to force a vote and warns of expiration (`output/mara-directives/mara_directive_c114_AUTO.txt:19-22`). The saved C114 Sunday packet carries the earlier directive as a command to answer, with a silence penalty (`output/cron-civic/packets/civic-office-council-d4_pending_decisions_c114.md:24-31`). That saved heading includes an older “charged for” suffix; current source at `scripts/cron-civic-run.js:762-768` has removed the suffix, so it is historical output, not a claim about the current heading. Mara's persona instead describes a planning director who supplies process and timeline assessments rather than shaping elected officials' political positions (`docs/mara-vance/IN_WORLD_CHARACTER.md:17-20,24-44`).

3. **MEDIUM — The petition rule turns a count into a mandatory proposal and the model calls it charter law.** `scripts/cron-civic-run.js:923-935,1135-1142` treats three complaints and no *pending* proposal as an unanswered demand; it does not inspect an applied proposal, a response, or the content of those complaints. The comment calls three a default the builder may overrule. **Input → wrong output:** C114's mayoral target has seven complaints and no pending proposal (`output/cron-civic/directive_c114.json:8-13`), and the generated text calls the number a “charter visibility line” and threatens “executive default under municipal petition rules” (`output/mara-directives/mara_directive_c114_AUTO.txt:35-38`). The threshold can justify a review, but the cited source does not make a proposal compulsory or establish a charter breach.

4. **MEDIUM — Five mandatory fields and a nonempty-block halt make a neutral no-directive judgment hard to express.** `scripts/cron-civic-run.js:982-993,1032-1046,1185-1192` requires Address, Why, Acceptance, and Silence consequence for every block. If seats are selected but Mara produces no valid blocks, `scripts/cron-civic-run.js:1225-1237` exits with a raw artifact instead of writing a no-directive result. **Input → wrong output:** the false C114 stall targets above compel the model either to invent a consequence or to halt the post-close stage; the saved C114 AUTO contains seven consequence lines (`output/mara-directives/mara_directive_c114_AUTO.txt:8-62`). `output/cron-civic/close_c114.json:22` has no pending voices, so this was not caused by a missing-voice escalation. The earlier C112 output shows the distinct missing-voice path for D1 (`output/cron-civic/directive_c112.json`), which should be judged on its own evidence.

## Downstream contract

- `runDirective` writes the AUTO text and `directive_c<N>.json` manifest (`scripts/cron-civic-run.js:1091-1116`). C<N+1> prep selects the prior AUTO unless a same-cycle manual file wins, then includes only each seat's section in its Sunday packet (`:507-516,762-790`). The week carry inserts wall lines and a pack pointer without parsing directive fields (`:426-485`); changing Mara's brief does not require changing the week-carry format. `scripts/buildInitiativePackets.js:140-152,469-499,565-569,638-644` also copies the prior full directive into project packets.
- The weekday reader parses each AUTO block by `**Agent:**`, requires a nonblank `**Address:**`, and makes `CONF-<directive cycle>-<seat>` IDs (`scripts/buildCivicOfficeSlice.js:1138-1151`). It retains all historical AUTO files through the current cycle, excluding an ID only after a pending/applied/failed answer (`:1153-1159`). The saved C114 mayor pack contains eight open IDs, C103–C114 (`output/cron-civic/packs/MAYOR-01_c114.json`, `game.confrontations.open`); D4 has five. The prompt exposes the oldest demand and all open IDs and says an answer is expected (`scripts/buildCivicOfficeSlice.js:1246-1252`; `scripts/cron-civic-run.js:2403-2419,2428,2438`). These saved packs demonstrate backlog behavior; they do not prove which messages a live model actually followed.
- An answer is checked against the open seat-bound ID, then lands in the move ledger (`scripts/cron-civic-run.js:2664-2674,2729-2735,2741-2760,3443-3453`). `scripts/civicProblemContinuity.js:24-34,56-84` uses the directive's full `sourceText` to infer which hoods an answer touched, so rewriting the body can change later reading-continuity accounting even if the ID stays stable. The apply gate does not parse the Silence consequence; it reads the directive manifest for model-family independence (`scripts/cron-civic-gate.js:90-105`). The stage machine marks directive completion by that manifest's existence (`scripts/cron-civic-run.js:3792-3799`).
- Dropping `**Silence consequence:**` from the brief alone breaks `filterDirectiveBlocks`: every otherwise valid block is rejected, and a nonempty target set then halts without a new AUTO/manifest (`scripts/cron-civic-run.js:982-989,1225-1237`). Dropping or renaming `**Agent:**` or `**Address:**` additionally breaks the weekday block reader. A change to the brief's prose that preserves those two fields and the ID format can leave answer routing intact, but changed `sourceText` still changes the answer-to-hood inference.

## Smallest change options for the builder

1. **Correct target evidence first.** Require a nonblank, finite integer `NextActionCycle`, exclude terminal/failed tracker rows, and distinguish a scheduled C115 step from an overdue C114 failure in `seatUnansweredDemands` and the duplicated seat-material predicate (`scripts/cron-civic-run.js:937-942,1145-1152`). Update the target tests and re-evaluate the C113–C114 manifests. This removes the measured false stall reasons but leaves the confrontation format in place.
2. **Make Mara a planning adviser.** Revise `DIRECTIVE_BRIEF` and the user prompt (`scripts/cron-civic-run.js:1023-1050,1184-1220`) to permit procedural progress, small opportunities, and a reasoned no-directive result; change `filterDirectiveBlocks` and the zero-block path (`:978-993,1120-1124,1225-1237`) if Silence consequence becomes optional. Keep Agent and Address if weekday confrontation IDs and answer moves should remain. Recheck the Sunday and project packet text consumers.
3. **Keep a narrower confrontation lane.** Reserve mandatory Address/Acceptance/Silence consequence for independently verified, consequential deadlines, and publish ordinary planning observations in a separate neutral section. This touches target selection, Mara's brief and validator, Sunday packet rendering, weekday `loadConfrontations`/prompt exposure, and any answer-to-hood rule that uses `sourceText`. It preserves a real escalation path while letting a flourishing week produce no confrontation.
