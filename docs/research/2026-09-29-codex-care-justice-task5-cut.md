# Care and justice Task 5 cut — adversarial review

**Scope:** Read-only review of the owning plan's `Task 5 read-before`, `Task 5 cut`, and `Judicial_Ledger` schema against current source and the intake plan. No code or plan edits. The five advisor fixes listed in the request were treated as settled.

**Verdict:** Revise the cut before engine-sheet builds Task 5. The in-memory arrest receipt is a bounded step, but the proposed lifecycle and its Task 6/8 handoff do not yet specify replay, multiple-arrest, or civil-case behavior tightly enough to meet the stated contract.

## Findings

1. **High — one citizen can produce multiple open arrest cases before the one-open rule exists.** The chaos loop can select the same citizen on separate events in one Cycle, and target selection does not exclude `detained`; the arrest outcome gate checks age alone. The cut emits a fresh `intake` for every eligible arrest but defers one-open-case enforcement to Task 8. Distinct chaos event IDs defeat the fold's `SourceEventId` dedup, and the proposed `J-C<OpenCycle>-<POPID>` identity collides for two cases opened in one Cycle. Define a receipt/case rule for an arrest while a case is already open, including two hits in one Cycle and a later hit while held; test that it preserves one open case and one custody entry without losing the second hit's history. Evidence: `phase04-events/chaosCarsEngine.js:91-94,156-173,541-548,584-606`; `docs/plans/2026-09-21-care-and-justice-system.md:155-160,183-205,370-384,410,419`; `utilities/careJusticeAccounting.js:75-95`; `docs/research/2026-09-28-codex-care-justice-intake-plan.md:130,135`.

2. **High — the proposed ledger-only replay carrier cannot infer receipt kinds from `SourceEventId` alone.** The plan says Task 8 rebuilds seen keys from the judicial ledger's `SourceEventId`, but the fold's identity is `system|kind|SourceEventId`. An investigation row already stores that ID before arrest and has no census intake; later conversion must admit exactly one `intake` under the same ID. A blanket seen-ID reconstruction would suppress it; ignoring the investigation row could duplicate it on replay. Specify kind-aware reconstruction from `ArrestCycle`, status, and persisted movements, or another durable representation, before relying on the fold. Test investigation open → conversion → replay and direct arrest → exit → replay. Evidence: `docs/plans/2026-09-21-care-and-justice-system.md:155-161,189-205,225,244,388-389,406`; `utilities/careJusticeAccounting.js:65-95`; `docs/research/2026-09-28-codex-care-justice-intake-plan.md:79-81,103-105,175`.

3. **High — a missed advancement can strand `pending` or `held`, and repeat calls can emit a second event.** The cut says a pending case draws *at* `DecisionCycle` and held closes *at* `HeldUntilCycle`, but gives no `cycle >= due` catch-up rule or `LastTransitionCycle` idempotence rule even though that column is in the schema. Its same-Cycle replay test checks a deterministic outcome, not that a second call leaves the case and movement unchanged. A partially persisted or skipped Cycle can therefore leave a case open forever if implemented with equality; duplicate advancement can replay an exit. Specify monotone advancement for overdue cases and at most one transition per case per Cycle, including persisted replay. Evidence: `docs/plans/2026-09-21-care-and-justice-system.md:193-198,388-389,393,412-416`; `docs/research/2026-09-28-codex-care-justice-intake-plan.md:81,104-105,123,175,194-195`; `utilities/cycleModes.js:82-85`.

4. **High — “new civil type = one table row” is not true under the current schema and census.** The planned state `pending` is counted as custody, `DecisionCycle` is defined as arrest + 1, and the judicial census accepts only `arrest`; `careJusticeIntakeType_` throws on any other type. The ledger's `SourceSystem` and `Outcome` lists also cover only criminal/investigative paths. A no-arrest divorce or lawsuit needs its own non-custodial open state, decision clock, source/outcome vocabulary, and explicit census treatment before the promised table-only extension works. Revise the genericity claim or reserve those hooks now; add a synthetic civil case test that opens, advances, closes, and never moves custody. Evidence: `docs/plans/2026-09-21-care-and-justice-system.md:119-120,177-205,224-227,386-389,410`; `utilities/careJusticeAccounting.js:22-33,55-62,182-189,220-232`.

5. **Medium — the adult gate is fail-open on missing birth year or missing life-state derivation.** `deriveLifeState_` maps an invalid/missing birth year to `age = null` and `isMinor = false`; `rollOutcome_` applies the arrest gate only when `target.lifeState` exists. Thus “adult (existing gate)” is not proof of known adulthood. Decide whether an arrest case requires a known adult age (while retaining the already-ruled hook/history behavior), and test unknown BirthYear plus absent life-state derivation separately from a known minor. Evidence: `docs/plans/2026-09-21-care-and-justice-system.md:362,384,419`; `phase04-events/chaosCarsEngine.js:91-94,102-113,177-195`; `phase05-citizens/citizenContextBuilder.js:60-67,84-87`; `docs/research/2026-09-28-codex-care-justice-intake-plan.md:174`.

6. **Medium — rate validation omits probability bounds and the repeat-arrest floor.** The spec rejects missing, non-numeric, negative, and a bad outcome sum, but does not require `0 <= investigationArrestRate <= 1` or a finite `judicialRepeatHeldMultiplier >= 1`. An investigation rate above 1 makes every case an arrest; a multiplier below 1 lowers held odds despite R3. Validate all five keys as finite values in their domains, and test boundary, over-1, Infinity, and multiplier-below-1 cases. Evidence: `docs/plans/2026-09-21-care-and-justice-system.md:391,394,400-405,417`; `docs/research/2026-09-28-codex-care-justice-intake-plan.md:123,125,175`.

7. **Medium — arrest mutation precedes the source-row write, but the test list lacks that failure path.** `writeCitizenEvent_` mutates LifeHistory/dials and queues its log before `writeChaosCarsRow_`; the caller pushes a receipt only after that writer returns. A thrown source-row write leaves the in-memory arrest effects without a judicial receipt. Task 4 explicitly tested this fault for care and left reconciliation to the writer; Task 5 must either name the equivalent judicial reconciliation in Task 8 or prove a safe retry. Add an injected write failure and next-Cycle reconcile/replay test; do not count a missing receipt as known-zero intake. Evidence: `phase04-events/chaosCarsEngine.js:303-325,377-401,571-606`; `docs/plans/2026-09-21-care-and-justice-system.md:228-229,327-339,410,412-422`; `docs/research/2026-09-28-codex-care-justice-intake-plan.md:104-105,136`.

8. **Low — read-before wording and two pointers are inaccurate.** `runConductEngine_` *does* read `dialBands.crimeReachable`; the measured cohort currently has no reachable citizens, which is the supported explanation for zero committed transgressions. `utilities/safeRand.js:33` calls `mulberry32_` rather than defining it; definitions are `phase02-world-state/applyWeatherModel.js:50` and `phase07-evening-media/textureTriggers.js:25`, as the cut later correctly states. The LifeHistory count in read-before is an arrest-outcome count, not yet a count of case-eligible receipts because the proposed health-state filter has not run. Correct the wording and pointer; label the count's denominator. Evidence: `docs/plans/2026-09-21-care-and-justice-system.md:345-350,362-368,384,393`; `phase05-citizens/runConductEngine.js:231-245`; `utilities/compressLifeHistory.js:1183-1186`; `utilities/safeRand.js:28-34`; `phase04-events/chaosCarsEngine.js:377-401`.

## Test additions to the listed Task 5 suite

The proposed tests cover forced outcomes, gravity bounds, RNG isolation, invalid outcome totals, and the current fold kinds (`docs/plans/2026-09-21-care-and-justice-system.md:412-422`). Add paired fixtures for: same-POPID double arrest and held re-arrest (finding 1); investigation conversion and replay with a ledger-derived seen set (finding 2); overdue and twice-in-one-Cycle advancement (finding 3); no-custody civil lifecycle extension (finding 4); unknown age (finding 5); invalid rate domains (finding 6); and injected source-row failure followed by reconciliation (finding 7). These are synthetic local cases only.
