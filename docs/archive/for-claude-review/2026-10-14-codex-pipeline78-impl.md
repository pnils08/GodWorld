## 3. Suffixed filing proof and Packet — FIX, exact hash passes but Packet can drift

The inline `side.rhea` proof is tried before the root fallback; either must have `pass=true` and a SHA-256 equal to the **loaded staged article bytes** (`scripts/cron-saturday-run.js:117-125,188-194`). A later root verdict for different bytes cannot prove an earlier suffixed article. The fallback can prove identical bytes if the inline proof is absent or wrong; it does not itself bind the filing's Packet or manifest. The router is stricter on this point and requires inline proof with the staged article hash (`scripts/notebooklmDailyRouter.js:91-104`).

The Saturday contamination re-scan does not use the matched proof's Packet. `stagedWritePacket` removes the suffix and loads `output/cron-compare/<base>.state.json` (`scripts/cron-saturday-run.js:102-126`). That root state is overwritten by later writes; current C111 Nia root state has manifest `AM-c226d21b7f41` (`output/cron-compare/undocked_c111_nia-rook_packet-v2_x-ai-grok-4-3.state.json:159`), while the earlier plain and `-2316` sidecars carry `AM-711e4f13cb62` and `AM-2db04e6da6d9` (`output/cron-compare/staged/undocked_c111_nia-rook_packet-v2_x-ai-grok-4-3.staged.json:29`; `...staged-2316.json:28`). `articleContamination` uses Packet text to admit grounded phrases and named speech (`scripts/articleContamination.js:105-110,198-224`). Thus an earlier filing can be falsely blocked or falsely cleared on a later assignment's evidence. Bind and retain the actual W3 Packet/manifest for each staged filing, or fail closed when it cannot be recovered; the current filename-only root lookup is not that binding. The regex also handles four-digit suffixes only, while the shared matcher accepts three digits (`scripts/cron-saturday-run.js:110`; `lib/articleIntake.js:244`).

Preserve genuinely distinct Nia recaps, but reconcile budget and Saturday identity on a proved filing key and leave semantic duplicate decisions to editorial review. `uniqueDest` also fails to check whether its generated `-HHMM` destination already exists, so multiple reruns in one minute can overwrite that pair (`scripts/cron-desk-run.js:1395-1399`).
