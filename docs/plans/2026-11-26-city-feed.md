## The approved vision (2026-11-26, "This is all correct copy this as the plan")

1. **A city feed.** Each non-sports beat gets entries shaped like the sports entries: one event, its history from canon with cycle numbers, the people, the open questions. The reporter wakes with that and chooses how to cover it.
2. **Written unattended.** After the engine and city hall finish on Sunday, the week's raw events are read, canon is searched for each one picked, and the entries are written — the job the duet does on sports. A workflow step, not a persona voice ("mags is giving a tidy story, it's just a part of the workflow").
3. **A sheet tab, not a file.** Entries live on a tab like the sports feed; the builder can add his own rows and questions the same way.
4. **Shared storylines.** One storyline goes to two seats only when their approach differs and their models differ (the council's accountability on one seat, how citizens are taking it on another).
5. **Daily follow-ups.** The Cycle is weekly; reflections and published pieces change daily. A short weekday pass reads those and adds follow-up entries, so a storyline moves midweek and seats react to each other.
6. **Free seats stay free.** Farrah, Jax, P Slayer and Ines get no entries; "keep them as the pressure".

Named conflict, accepted by the approval: the 2026-07-10 ruling ("As long as you control everything it's going to always [be a] tidy story"). Built-in difference: the writer reads raw events and citizens' pages, never a pre-digested summary; the free seats stay.

## Design

**Tab `City_Feed`** — the sports feed's shape, so one mold reads both:

| Column | Holds |
|---|---|
| Cycle | the Cycle the event belongs to |
| Beat | faith, health, economy, transit, schools, safety, arts, food, neighborhoods, lifestyle, trends, environment, civic, investigations |
| EventType | event, follow-up, prompt (a builder's own row is `prompt`: public, read by the seat like any entry. Not the sports feed's `EventTrigger = question`, which `lib/feedPrivacy.js` keeps private) |
| NamesUsed | people and places, "Name (role)" |
| Notes | the entry: the event, then its history with cycle numbers, then the open questions |
| StoryAngle | one of the entry's open questions, one line; code refuses a line that does not end in a question mark |
| Storyline | engine storyline id when one exists (`CRISIS-…`, `INIT-…:stage`), else a slug the writer mints and reuses week to week |
| Refs | one ref per history sentence, to the exact unit it came from: a canon_recall hit (doc id + the returned chunk) or a sheet row (tab + row). Never a staged file, never a whole edition |
| Seats | seat slug(s) only — no approach text; each seat's own seat file is its lens |
| WrittenBy | `city-desk` or `builder` |
| EntryId | `CF-<cycle>-<n>` |

**The writer (`scripts/cityFeedWriter.js`), a workflow:**

1. Inputs, raw only: `output/beats/*.jsonl` + `prev/` (the week's rows and what moved) **without** `Story_Hook_Deck` / `Story_Seed_Deck` (both carry `SuggestedAngle`, hook and voice text); the LifeHistory window; citizens' pages for the week; live reads the dump lacks or holds stale — `Ripple_Ledger` (not in the dump) and `Initiative_Tracker` (the dump is taken before the chain applies); the chain's decisions (`output/cron-civic/decisions_lane_c<N>.json`); `desk_signal` storyline registry (ids and stages only); the feed's own prior rows (open storylines). The writer is a script and reads tabs directly — it is not held to the reporters' `sheet_read` list. Never `world_summary` prose, never a lane `handle.angle` / `hookLine`.
2. Candidates per beat in code (what moved, what is new, what a prior entry left open). The model picks which to carry and why; no score picks for it.
3. Per pick, a tool loop on `canon_recall`, `canon_search`, `citizen_lookup`, `sheet_read` (through `openRouterToolLoop`, `keepResults` on). It returns the entry as parts: the event sentence(s) (from the candidate rows), history sentences each naming the unit it came from, people, open questions. `ask_worker` is not in phase 1: a worker's answer has no unit a script can check.
4. **Ref check in code before any write (agy #1):** a history sentence passes only if every number, every `C<N>` and every proper name in it appears inside the one unit it cites — one returned canon_recall hit or one sheet row, never the whole document — and it carries no causal connector (because, caused, due to, led to, triggered, after … so) that the unit does not itself carry. A failing sentence is dropped and logged with its reason. An event sentence is checked the same way against its candidate row. No cause on the record → an open question, never a reason.
5. Seats: one seat by beat. A second seat only when the two packages' `models.write` differ (`scripts/newsroom-wake-packages.json`; no per-day variants exist — agy #6), checked in code. Never Farrah, Jax, P Slayer, Ines.
6. Append rows (read back), then `regenSchemaHeaders.js`. Idempotent per Cycle (`output/city-feed-state.json`): a second run adds nothing.

**Trigger (agy #3):** the writer's own readiness check, not the chain's flag alone: `beats/meta.json` at exactly Cycle N, `desk_signal_c<N>.json` on disk, the civic week state for N with the chain applied and its directive stage done. `engineFireInfo` does not look at the desk signal, and the dump predates the apply — hence the live `Initiative_Tracker` read above. The writer adds no CLI step. What it waits on is written by `/run-cycle` Steps 4–5.56 through `scripts/runCycle.js`; taking the CLI out of those steps is its own job, named to the builder, not built here.

**The record (`scripts/cityRecord.js`, `withCityFeed(SEAT, build)`) — a wrap, not a swap (agy #4):** the seat's present builder still runs and still supplies what the day depends on: its people (`slice.citizens` — the `named` pool for Graye, Lila, Kai), its businesses and `BIZ-` refs (the `workplace` pool for Trevor, Jordan, Mason, Angela), its scrubbed rows (`foundedAgo`, closed hospital stays, the 22-hood census), `sitsOutWhenEmpty`. The wrap puts the seat's entries for C and C−1 first, whole, newest first, adds the people each entry names to the pool, and writes each entry's `INIT-` / `BIZ-` id into its fact ref so the `offices` and `workplace` pools resolve on an entry-led story. Its own pieces already filed this Cycle open the record; colleagues' pieces on the same Storyline ride as "Filed this Cycle by …" (the filed-piece pattern keyed by the seat's desk, not `sports_`). `seat.live = true` so a midweek row reaches the seat (the slice cache otherwise serves Sunday's copy all week). The feed's morning copy missing or over 20 h old → the seat sits the day out, as on sports; a fresh copy with no entry for the seat → its present record, unchanged. How much of the flat record still rides behind the entries is set at Task 5's read of the piece, not here. No "ASSIGNED ANGLE / HOOK / the angle is fixed" text: that branch is unreachable for a seat-file seat (`cron-desk-run.js:2268` `!persona`; agy #5) and stays so.

**Weekday pass (after the builder's read of phase 1):** Mon–Fri before 06:15, the same writer in `--follow-up` mode reads the prior day's citizens' pages and the pieces the 18:50 daily ingest sent to canon and adds `follow-up` entries on open Storylines. A seat's refusal or own pitch (item 5 of the second message) is designed after the first live read.

**Canon:** the tab is not an ingest source; canon is what gate-passed pieces carry. `dumpBeatTabs.js` reads an explicit tab list and `backupSpreadsheet.js` copies every tab — neither breaks on a new tab; `preMortemScan` tab parity warns (not fails) until the bench resyncs; `SCHEMA_HEADERS.md` is regenerated in the same task. Engine phases do not read it. `City_Feed` joins the reporters' `sheet_read` list with the first seat.

## Acceptance

1. An entry reads like a sports row: one event, at least two history sentences with cycle numbers, named people, at least two open questions — proven by Task 4's print.
2. No history sentence reaches the tab without a ref that resolves — proven by the suite and by opening every ref in Task 4 by hand.
3. An event with no cause on the record yields a question, not a reason — proven on the three C117 Faith_Ledger crisis rows.
4. A seat on the city record opens on a person or an event, not on the record — proven by Task 5's piece beside the C117 piece, and the grade's opening line.
5. Two seats share a Storyline only with different write models — proven by the suite against the package file.
6. A fire with `/run-cycle` complete produces the week's entries with no further command — proven by the first Sunday log.
7. Farrah, Jax, P Slayer and Ines receive no entry — proven by the suite.
