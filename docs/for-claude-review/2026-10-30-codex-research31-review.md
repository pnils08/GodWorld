## Findings

1. **HOLD — the changed filter can strand a partial points back-score.** `planPointsRescore` compares only the archive's `facts.points_delta.value` to the derived value (`scripts/undockedEpisodeAdapter.js:780-790`); `applyPointsRescore` then filters solely on `changed` (`:821-825`). It writes the tab first (`:838-848`), then archive (`:849-852`), intake (`:854-858`), and feed pack (`:859-865`). Input: the archive write succeeds, then the intake or feed-pack write fails. Output: the next `--apply` sees the archive's new value, makes `todo=[]`, and leaves the intake/feed pack on the old score indefinitely. The same filter cannot detect a tab row that failed to persist or was later changed. Compare and read back all four representations by EpisodeId, or keep a durable per-row completion state until every copy agrees. Do not call tab-then-disk alone a replay guarantee.

2. **SHIP-WITH-FIXES — an unreadable earned unlock can become a measured zero.** `readAccount` coerces a missing/non-numeric achievement `points` to `0` and accepts a missing `earned_at` (`scripts/undockedEpisodeAdapter.js:719-727`). `derivePoints` silently excludes an invalid timestamp and, if the night's saved log has any non-session event, emits FACT `0` (`:256-270`). Input: account summary says 5, an earned achievement has `earned_at: null` (or a malformed `points`), and the night has a navigation event. Output: the night becomes measured zero despite an account score that was not attributable; the back-score can write that zero to the tab (`:839-842`). A local pure call also showed an invalid `startedAt` plus gameplay producing measured zero. `planPointsRescore` reports malformed timestamps as “earned before” (`:774-776`, `:815-817`) but does not stop apply. Validate finite points and parseable times, and require reconciliation with `summary.points` before replacing known values. For valid, ordered timestamps, the `[startedAt, nextStartedAt)` intervals are disjoint; I found no double-count path in that case.

3. **SHIP-WITH-FIXES — the header guard accepts a column the readers cannot name.** `ensureFeedHeader` trims every header before comparison and readback (`scripts/undockedShowGate.js:250-263`), then `pushFeed` appends in positional order (`:289-301`). Input: the actual M header is `PointsDelta ` (trailing space) while `EpisodeId` is exact. The guard returns success without a write; a local pure mock call confirmed this. Output: the new points value is placed under that padded header, but `scripts/undockedStandings.js:55-58,73-74` treats the points column as absent and ranks from credits; `scripts/undockedEpisodeAdapter.js:829-831` refuses the back-score. Demand byte-exact header equality after any repair. There is no evidence here that the live tab has this shape; no Sheet read was allowed.

4. **SHIP-WITH-FIXES — eight idle turns can end a flight that resumes play.** The tracker marks a run complete at eight `turn_end` events with no successful command (`scripts/undockedEpisode.js:124-141`) and sends SIGINT immediately (`:191-203`). In the saved Merkin Jumper flight, turns 21–28 ended without a successful command (`output/spacemolt-show/episodes/undocked-pop00688-2026-09-03T01-30-07.log:77-172`), then turn 30 successfully called `spacemolt/get_missions` and turn 31 called `spacemolt/accept_mission` (`:192-197`). The saved 2026-09-28 flight similarly has turns 36–43 idle followed by `undock` and `get_poi` at turns 46–47 (`output/spacemolt-show/episodes/undocked-pop00300-2026-09-28T01-30-05.log:201-390`). Replay under the new tracker cuts both before those later calls. A genuinely dead narrator still stops after eight turns; the current signal cannot distinguish one from a pilot who resumes. This is a mechanism question for the approved agency rule, not a request to restore the captain's-log stop.

5. **SHIP-WITH-FIXES — the direct runner still defaults to ten minutes.** `scripts/undockedMissionBrief.js:49-65` promises a 20-minute night, and the cron passes that value explicitly (`scripts/cron-undocked-run.js:248-255,299-303`). But `scripts/undockedEpisode.js:44-53,207-211` defaults `minutes` to `10`. Input: invoke the runner with a valid mission and no `--minutes`, as its usage permits (`:22-25`). Output: the flight is interrupted at ten minutes while the brief says twenty. A malformed `--minutes` also becomes `NaN` and schedules an immediate timeout; validate the bound in the runner.

6. **HOLD — the held standings and the engine's `$LEADER` disagree in source.** The held recompute ranks cumulative points, credits, POPID (`scripts/undockedStandings.js:81-96,99-126`) and tests the order with synthetic rows (`scripts/undockedStandings.test.js:18-35,57-67`). The current phase02 source still accumulates only `CreditsDelta` and selects the credits leader (`phase02-world-state/loadEventContentLedger.js:316-322,360-397`); phase05 reads that POPID for `$LEADER` (`phase05-citizens/generateCitizensEvents.js:604-615`). Input: pilot A has 10 points/5 credits and pilot B 5 points/1,000 credits. Output: the held board says A is first while citizen lines using `$LEADER` name B if this source runs. This is the planned second commit, so hold the board's landing until that reader and the three named Event_Content_Ledger objective lines are updated and checked. I did not read the live ledger lines or verify deployment.

7. **SHIP-WITH-FIXES — unknown points are displayed as zero in the held board.** `compute` initializes every pilot's `points` to `0` and adds only present deltas (`scripts/undockedStandings.js:73-91`); replay also adds `0` for absent deltas (`:107-113`). Input: a pilot has only blank `PointsDelta` because `get_achievements` failed (`scripts/undockedEpisodeAdapter.js:511-514`). Output: `PointsTotal` is numeric `0`, and a known five-point pilot can lead despite the first pilot's score being unknown. The old-header test explicitly accepts all pilots at zero (`scripts/undockedStandings.test.js:47-55`). Keep unknown distinguishable from measured zero through ranking and sidecar publication, or gate board release on complete typed points for every ranked pilot.

8. **SHIP-WITH-FIXES — `--recent N` silently loses its bound on bad input.** The CLI converts the next token with `Number` without validation (`scripts/undockedEpisodeAdapter.js:916-927`); `readAccounts` uses `recentDays ? ... : -Infinity` (`:871-879`). Input: `--recent 0`, a missing value, or a non-number. Output: every archived pilot account is queried and the plan may update all of that pilot's nights instead of a bounded set. With valid `7`, the documented scope is **pilots with a night in the last seven wall-clock days**, then all archived nights of those pilots (`:758-794`), not just seven days of rows. Validate positive finite `N` and state that scope in the CLI output.
