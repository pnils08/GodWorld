# pipeline.97 every page review

**Verdict: HOLD.** The DEBATE admission is sound at the customId/slot boundary, but the proposed switch does not preserve the stated MEDIA exclusion in every path and can serve a same-day old-rule cache. Keep `EVERY_PAGE` off until the findings are settled. This is source inspection only; no tests, scripts, network calls, or live runs were made.

## Findings

1. **F1 — a MEDIA citizen's filing can enter Tamsin's page voices.** The MEDIA guard in `scripts/buildLivesSlice.js:260-261` applies to supplemental `take()` paths, not the primary `Lived_Events` batch: `:236-237,251-257` selects an event for any subject, `:383-403` adds that subject to `people`, and `:443-447` then takes every admitted page for those people. With `EVERY_PAGE=true`, `pageSlot` accepts PRESS and `pageText` runs `citizenText` (`:83-90,149-161`); that cleaner strips TENSION tags and one JSON quote wrapper, but leaves `filed:` unchanged (`scripts/scanCitizenPages.js:125-132`). Input: a synthetic MEDIA-profile reporter has a current-Cycle promotion in `Lived_Events` and an indexed `PRESS` reflection `filed: Sample headline`. Wrong output: Tamsin's slice names the MEDIA reporter as a subject and emits `own page (to a reporter, C<N>): “filed: Sample headline”` to her writer, although section 6 says MEDIA citizens stay out (`docs/plans/2026-10-03-citizen-pages-drive-canon.md:122`). Before this switch, the PRESS page was excluded even for a selected person. The MEDIA fixture covers a household and wager, but no primary lived event or PRESS filing (`scripts/buildLivesSlice.test.js:33,41-48,72-85,108-110,156,184-185`).

2. **F2 — Ines's final page resolver does not enforce the roster's MEDIA rule.** Her roster excludes MEDIA profiles at `scripts/buildVoicesSlice.js:90-95`, but `pagesForPicks` checks only the requested POPID, slot, and nonempty text (`:155-170`); `scripts/cron-desk-run.js:3046-3055` inserts every resolved page as a W3 `FACT`. Input: a stored W3 angle target names a synthetic MEDIA reporter whose only indexed page is `PRESS` content `filed: Sample headline`, with `EVERY_PAGE=true`. Wrong output: `pagesForPicks` returns that filing and W3 injects it as a citizen page fact, despite the roster excluding that reporter. Normal W1 validation constrains targets to supplied candidates (`scripts/livedExperiencePacket.js:583-603`), and the present Voices roster should keep this target out of an unaltered W1; W3 validates handoff metadata but does not recheck target membership or current MEDIA status (`scripts/cron-desk-run.js:261-297,3046-3055`). The existing test explicitly accepts a direct MEDIA pick under the old rule and has no true-rule MEDIA pick assertion (`scripts/buildVoicesSlice.test.js:90,118-135`). This is a final-write guard gap, not a claim that a normal unaltered W1 currently picks reporters.

3. **F3 — flipping the switch can return the old rule's slice from the same-day cache.** Both `loadSlice` functions accept a cached nonempty slice when version and local day match; neither key records `EVERY_PAGE` (`scripts/buildLivesSlice.js:478-485`; `scripts/buildVoicesSlice.js:29-34,194-199`). Input: the C113 Lives or Voices slice was built earlier today with `EVERY_PAGE=false`; the source switch is then changed to `true` and the same day's angle or write stage calls `loadSlice(C113)` through `cron-desk-run.js:917,1784,1813` or `newsroom-fanout.js:460-461`. Wrong output: the cache returns the old self-slot-only slice, so PRESS/INTERVIEW/DEBATE/tension pages are absent even though the running code has the switch on. Direct `buildVoicesSlice` and `ownPageLines` fixtures do not exercise a preexisting cache across the flag change (`scripts/buildVoicesSlice.test.js:117-135`; `scripts/buildLivesSlice.test.js:113-124`). A new version or an explicit rule marker in the cache check is needed for an immediate same-day flip.

4. **F4 — the true-rule fixture accepts a false-rule approach.** `scripts/buildVoicesSlice.js:34` constructs `SEAT.approach` from the module-level `lives.EVERY_PAGE`, while `:84,91-95` lets a caller build with `everyPage:true`. Input: the committed switch remains false and `buildVoicesSlice(C111, { everyPage: true, ... })` is called, as in `scripts/buildVoicesSlice.test.js:117`. Wrong output: the roster includes PRESS, debate, and tension pages, but `slice.approach` still tells the writer the roster contains only “self-initiated” pages. The assertion at `scripts/buildVoicesSlice.test.js:125` chooses its expected regex from `L.EVERY_PAGE` rather than the `everyPage:true` input, so it passes this mismatch. Production with the module flag flipped at process start would have the right approach; the stated two-rule test does not prove that correspondence.

## Other seams checked

With a fixed input index and `EVERY_PAGE=false`, the selected slots, text trim, roster wording, empty reason, ref, and page-voice labels follow the pre-commit expressions (`scripts/buildLivesSlice.js:86-90,149-161,443-447`; `scripts/buildVoicesSlice.js:34,40-41,71,84-95,108-111,121-149,155-170`). The helper `ownPageLines` adds a `where` property, but the slice prints the same old slot value while off. A live re-dump can add DEBATE rows even while the switch is off; that changes the index input and its `counted.index`, rather than the off-branch selection rule.

The scanner accepts both old `DEBATE` and weekday `DEBATE-fri` IDs, splits the weekday, and keeps `slot='DEBATE'` (`scripts/scanCitizenPages.js:56-84`; `scripts/scanCitizenPages.test.js:24-31`). An exchange page contains only that participant's own turns, while tension pages are separately typed (`scripts/citizen-exchange.js:173-194,403-408`). Letter citations accept the DEBATE letters and reject typed tension as a stance (`scripts/checkLetterEligibility.js:133,153-166`). Pulse counts indexed debate pages like other docs and quotes reflections only (`scripts/buildPulseSlice.js:99-125,147-162`); Rhea resolves customIds and checks recent reflection stances (`scripts/cron-rhea-gate.js:392-412,650-670`); street sourcing requires a reflection and matches a sentence from that citizen's page (`scripts/newsroomSourcing.js:341-373`). I found no DEBATE-specific break, extra count of one page, or cross-citizen attribution in those readers. Their runtime behavior remains unverified by this review.

**Gate:** enforce the MEDIA rule on primary Lives events/page lookup and at Ines's final page resolution, invalidate or distinguish old-rule caches when the switch flips, and make the true-rule approach assertion depend on its actual input. The collector's live DEBATE admission is a separate source-level SHIP; it does not settle the seat switch.
