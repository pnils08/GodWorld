## Findings that still affect the build

1. **HIGH — A Mara-only project turn still has no answer-shaped prompt.** The fold adds a prior-directive trigger and packet for a director with no touching mayor/council decision (`docs/plans/2026-10-31-civic-autonomy.md:264,278,282`). The named project call path still builds `frame` only from `touches`, then tells the director that city hall's political frame is locked and asks what happens next operationally; its output schema requires `statements[].decision`, `quote`, and `fullStatement` (`scripts/cron-civic-run.js:2088-2105,1288-1305,1312-1315`). The fold's file list names a project *trigger*, not this no-touch prompt/output contract (`docs/plans/2026-10-31-civic-autonomy.md:278`). **Input → wrong output:** Mara asks OARI a record question, and no C115 mayor/council statement touches INIT-002. The new trigger runs OARI with an empty political frame and a required operational decision; it can publish invented movement without answering Mara, yet the next Mara run treats that project JSON as satisfaction evidence. A Mara-only turn needs an explicit question/response route that permits a factual answer or an honest deferral without manufacturing an initiative decision.

2. **HIGH — The allowlisted Sunday source key cannot uniquely resolve the mayor's two statements.** The proposed key is `{kind, office (agentDir), cycle, date?, field, index?}` and resolves Sunday to `<slug>_c<N>.json`, while saying mayor open and gavel are distinct sources (`docs/plans/2026-10-31-civic-autonomy.md:249-251`). `voiceSlug('civic-office-mayor')` is `mayor` (`scripts/cron-civic-run.js:1254`), but the saved files are `output/civic-voice/mayor_open_c114.json` and `mayor_gavel_c114.json`, whose `office` fields are `mayor_open` and `mayor_gavel` (`output/civic-voice/mayor_open_c114.json:2-4`; `output/civic-voice/mayor_gavel_c114.json:2-4`). **Input → wrong output:** a valid C114 gavel promise citing the mayor's agentDir and `statements[0].fullStatement` has no source discriminator, so a resolver either looks for absent `mayor_c114.json` or chooses one of two files without authority; a genuine promise is rejected or attached to the wrong statement. The source key needs a bounded open/gavel identifier and an explicit slug-to-office check.

3. **HIGH — A sourced status row can still close an unrelated promise.** The fold fixes raw-file matching and immutable original identity, but a later `kept|dropped|changed` row is accepted if its evidence is *any* later public statement from the same office or an exactly quoted tracker field (`docs/plans/2026-10-31-civic-autonomy.md:251-253,272`). It does not require that evidence address the original promise. **Input → wrong output:** D4's C114 statement promises a committee referral (`output/civic-voice/council_d4_c114.json:10-15`); a later D4 statement about another topic validates as same-office public evidence, so `promise_record` can mark the referral `kept` and omit it from next week's open promises although no referral is shown. The status check needs a relation to the original promise and its claimed outcome, not provenance alone; the tracker alternative needs the same relation.

4. **MEDIUM — The no-write-on-failure guarantee stops at model validation.** The fold stages writes until final text validates and gives the Supermemory entries stable customIds (`docs/plans/2026-10-31-civic-autonomy.md:255,258,276,280,282`). Its commit then crosses a local append-only JSONL and remote `/v3/documents` writes/readbacks (`lib/citizenPage.js:146-195`); no transaction, commit order, durable receipt, or partial-failure reconciliation is specified. The promise hash identifies the original promise, but later status rows reuse `promiseId` (`docs/plans/2026-10-31-civic-autonomy.md:252`) and have no separate event id to deduplicate an append. **Input → wrong output:** validated text appends a promise status; the page or `mara-world` write then succeeds remotely but its readback fails and the run is marked errored. The promised “writes nothing ... when the run fails” is false, and a retry can append the same status again or lose track of the remote result. State the post-validation partial-commit behavior and give every persisted row a stable event identity/reconciliation path before using that acceptance claim.
