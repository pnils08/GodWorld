# engine.333 — independent read-before

**Verdict: HOLD on the read-before/design as written.** Claims 1, 2, 3 and 5 in the brief pass with the qualifications below. Claim 4 misses an active Phase-5 writer that changes the proposed retirement result. This is a source review of the current checkout, not a review of a candidate cut or a Cycle result. The builder's C1–C3 calls remain open.

## Ranked findings

1. **P1 — Retirement on a UNI GAME row is immediately rewritten by the existing Universe phase.** `phase01-config/godWorldEngine2.js:623,635` runs GameNight before Universe. If GameNight sets `Status=Retired`, `phase05-citizens/runAsUniversePipeline.js:416-420,433-456` sees `UNI=y`, `Status=retired`, `ClockMode=GAME`, changes `ClockMode` to `ENGINE`, appends an untagged post-career LifeHistory note, and appends a second bare `Retirement` LifeHistory_Log row at `:445-452`. It marks the ledger dirty and directly appends the log at `:579-587`. The local, dirty `output/simulation_ledger_snapshot.jsonl:1` has Vinnie as UNI=yes, GAME, Active, Tier 1, BIZ-00005; that snapshot is not live proof. Input: a retirement feed row for such a player → output: ENGINE clock and two retirement log events if the new GameNight path also logs its required bare event. `lib/wakePerception.js:745-761` gives same-kind/same-Cycle log rows distinct `#2` IDs, and `:840-860` spends them independently, so a later wake can perceive retirement twice. The plan's GAME-clock ripple analysis, C2 staff-line choice after that Cycle, and single-event acceptance need to account for this writer. Decide explicitly whether the existing conversion remains; if it remains, make one component own the retirement receipt.

2. **P1 — A Status guard alone cannot make a re-fired feed row idempotent.** The named loop's `seenThisRow` exists only for one invocation; every resolving row calls `write()` regardless of prior LifeHistory or log rows (`phase05-citizens/applyGameNightMoments.js:217-232`). `living()` admits `Retired` at `:189`, and `write()` appends to both the in-memory ledger and log at `:207-214,284-286`. Input: fire the same Cycle and retirement feed row again after the player is already Retired → output: at least another EventType texture line and log row, even if a proposed milestone branch skips its second Status change. This refutes the plan's `:77,93,123` whole-row “second fire changes nothing” acceptance. The log append is direct in Phase 5 while the ledger is queued at `phase01-config/godWorldEngine2.js:859,869` through `phase10-persistence/commitSimulationLedger.js:25-37`; a failure between them can also leave a log receipt without the Status change. Define a durable per-feed-row/player receipt and a replay rule covering both writes before claiming idempotence.

3. **P2 — The trigger label is not guaranteed to reach a ripple, seed Why, or What Moved.** On a non-game press-conference row, `feedTeamShare_` returns zero without a played week (`phase02-world-state/applySportsSeason.js:1110-1120`). The only trigger-bearing sports ripple is guarded by `totalSentiment !== 0` at `:866-884`. GameNight's own ripple says only how many citizens were touched and contains no trigger at `phase05-citizens/applyGameNightMoments.js:288-302`. `phase07-evening-media/buildContractSeeds.js:461-465` and `scripts/buildWorldSummary.js:270-286` inherit the ripple's CauseDetail; neither can recover the missing label. The current `TRIGGER_HOOKS` table has no `retirement` key (`phase07-evening-media/storyHook.js:565-594`). Input: a retirement-only feed row with no game week → output: the retirement label is absent from those ripple/seed/summary paths. The plan's `:67` automatic seed/summary claim is a HOLD; feed-to-handoff prose at `phase10-persistence/compileHandoff.js:1511-1533,1614-1617` is a separate raw-sheet read, not this attribution path.

4. **P2 — Adding a retirement hook merely to satisfy the vocabulary pin would re-fire team stories.** `reduceFeedTeamState_` retains the last nonblank trigger across rows (`phase02-world-state/applySportsSeason.js:1063-1104`), and a new current-Cycle row with blank EventTrigger passes the team gate then emits that retained value at `:994-1005,1014-1050`. `phase07-evening-media/storyHook.js:590-604` would turn a new `retirement` hook entry into another story hook. Input: retirement on one Cycle, then a blank-trigger row for that team on a later Cycle → output: another retirement hook despite no new retirement row. This does not infect the proposed named milestone, which would read the row's own `entry.eventTrigger`; it does infect the suggested “add a hook entry” side of the engine.331 vocabulary choice until carry is fixed. Prefer a pin that distinguishes life-history milestone words from team-hook words, or sequence the team carry repair with the hook.

5. **P2 — “Next wake speaks from you retired” is not a guaranteed acceptance.** `lib/wakePerception.js:731-734,747-761` accepts a retirement log only in its own Cycle and the next. Lived events do not reserve a wake slot (`:720-723`); `:870-895` selects from the pool by a seeded draw unless a separate forced/show/owed condition applies. `scripts/citizen-wake.js:315-327` calls `livedFor` only *after* a citizen was picked. Input: a valid retirement log for a player who is not picked during that window → output: no retirement lived line on that player's next later page entry. The source supports “you retired” **if drawn in the window** (`lib/wakePerception.js:758,828`), not the plan's unconditional `:27,126` live-wake promise. Make the proof conditional on an actual qualifying wake or add an authorized selection mechanism.

6. **P2 — The plan's Status-writer inventory and “no engine path writes Retired” wording are too broad.** `phase04-events/chaosCarsEngine.js:524-542` is another direct Status writer omitted from the plan's `:51` inventory. More narrowly, no inspected engine path *initiates* retirement; the health discharge path can write the prior `Retired` value to Status (`phase04-events/generationalEventsEngine.js:436-445`), and judicial release can restore `c.PriorStatus` through `judicialSetStatus_` (`phase05-citizens/judicialLifecycle.js:527-533,666-669`) for an eligible non-GAME row. Input: a retired citizen who enters care or eligible custody and later exits → output: Status becomes `Retired` through an engine writer. Keep “no retirement initiation” distinct from “no Retired write” when deciding how the new feed path interacts with existing state restoration.
