## Evidence

Build locally, initialize absent/empty safely, and publish only on successful phase completion. No current reader/name collision was found in scoped code; checkpoint summary omits this transient field (`phase10-persistence/cycleCheckpoint.js:30-35,186-203`).
2. **Chaos source.** Vehicle events carry `cycleId`, `targetScope`, business `targetId`, and `diceOutcome` before entering `S.chaosCarsEvents` (`phase04-events/chaosCarsEngine.js:765-787`); the port event shares the array but has `targetScope:'port'` (`:1112-1119`). A chaos-phase failure's partial array is still possible because `safePhaseCall_` continues; the Cycle/scope filter prevents stale or port entries, not partial-phase provenance.
3. **Pick calculation.** I applied the specified unsigned FNV-1a/fmix32 highest-score rule to `output/beats/Business_Ledger.jsonl:1` and `output/simulation_ledger_snapshot.jsonl:1` (180 businesses, 1,044 POPIDs; snapshot, not a fresh Sheet read). The result is 81 canon-hood spots (49 food, 32 retail), all 22 hoods covered, all 81 selected at least once, 0 rank ties, and 1,044 assigned snapshot citizens. Ivy Hill's three spots have 4/3/2 holders; Lake Merritt's sole spot has 99; Temescal's sole spot has 64. A synthetic added ID moves 288/1,044 to itself, removing an unchosen ID moves none, and removing a chosen ID moves every holder in a hood with another option (881); the 163 single-spot holders have no replacement. This checks the proposed hash, not an unbuilt implementation or draw. `resolveHoodOrChild_` is already invoked in this generator's Phase-5 flow (`generateCitizensEvents.js:2391`); it throws only if canon hoods were not seeded and returns null for unmapped labels (`phase01-config/canonNeighborhoodLoader.js:434-453`). The dump's Telegraph corridor row is `Business_Ledger.jsonl:62`; it has no exact canon/child match in the proposed source, so no fallback to a guessed hood.
4. **Reach arithmetic.** `streak` resets at nonnegative growth (`applyBusinessDynamics.js:478-485`), and open-row shed requires streak >4 (`:690-694`; `engine94SheetContract.js:89`), so shed implies quiet. Quiet weight is 2 at streak 2, 3 at 3, 5 at 5; shed adds 2, each chaos outcome 3, recovery 2, lift 1.5 (`TASK.md:34-42`; `generateCitizensEvents.js:1746-1749`). The TASK's carried C112 facts give three Ivy Hill quiet spots plus one Baylight spot, one shed spot, zero recent recoveries, and two eligible business chaos hits in eight Cycles across 180 businesses (`TASK.md:17-20`); the offline pick has only 9 Ivy holders and 4/6 holders on Baylight's two spots (`Business_Ledger.jsonl:144-145,151,95,99`). That is roughly 13–15 snapshot holders for today's quiet state before age/status/participation and draw filters, not 1,044 opportunities. The code excludes minors and some statuses, then rolls participation (`generateCitizensEvents.js:2534-2573,2712-2719`).
5. **Game-week ceiling and missing denominator.** The offline pick gives 726/1,044 food-spot holders; this is an upper bound for a hypothetical week in which every food spot has positive lift, not an expected draw count. All food classes pass `bizIsBar_`, but `sportsBarTerm_` requires a played franchise, a signed result, and venue/nightlife share (`applyBusinessDynamics.js:281-285,535-536,597-603`; `utilities/sportsWeekRecord.js:344-360`). C113 Oaks game-result rows exist in `output/beats/Oakland_Sports_Feed.jsonl:249-250`, but this dump alone does not establish positive `barTerm` for every hood. For `k` available draws and competing effective mass `T`, a single lift line's approximate draw probability is `1-(T/(T+1.5))^k` before filters; `T` is not in the current receipts (`output/engine-sheet/2026-10-20-e214b-receipt-B-c113.json:6`). The generator takes 1–4 draw slots, filters recent text, may reserve grief, and balances ledger rows (`generateCitizensEvents.js:3421-3465,50-86`). Thus no defensible numeric expected C113 lift count exists yet; the planned real-generator probe must measure `T`, participation, availability and actual draws rather than multiply 726 by an assumed rate.
6. **Grade, prose, and 8b.** `source:nbhdState` without retail/community routes to `Neighborhood` (`generateCitizensEvents.js:1061-1067`); a valid explicit `dial:outabout:up|down` wins over fact inference and the bare kind gets graded (`:1155-1178,3593-3623`; `utilities/citizenDialMap.js:83,303-333`). The lowercased text also hits `/opened a/|venture` or `/shop closed|business closed|shut its doors/` independently of the grade (`neighborhoodPulseMap.js:78-113`); current proposed lines avoid those substrings, including with `Shop`/`Business` as the final name word, but future rendered names need tests. `recentTexts` stores normalized text; duplicate prose is excluded per Cycle and usually across recent draws (`generateCitizensEvents.js:701-707,3430-3453`).
