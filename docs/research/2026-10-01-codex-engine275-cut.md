# engine.275 cut — adversarial code review

**Verdict: HOLD.** This is a review of the design at `docs/plans/2026-09-21-care-and-justice-system.md:624-640`, not a review of an implementation. The proposed 60-minute comparison can reject an ordinary sequential retry when `lastRun` is a valid, visible timestamp. It does not establish the builder's invariant that one live fire cannot run two Cycles. No code, deployment, or live Sheet was changed or exercised for this review.

## Findings

1. **CRITICAL — Two entry paths can run concurrently over the same starting Cycle.** `doGet` alone holds a script lock (`utilities/webTrigger.js:36-57`); the menu calls `runWorldCycle` directly (`utilities/godWorldMenu.js:25-28`), and `runWorldCycle` acquires no lock (`phase01-config/godWorldEngine2.js:212-242`). Two menu fires, or a menu fire overlapping a web fire, can load the same old `cycleCount`/`lastRun` (`godWorldEngine2.js:645-661`), both pass the proposed guard, and both queue the same counter bump (`:670-703`) while doing world work. The web `expect` comparison under **its** lock cannot serialize the menu. **Fix:** put one script lock around the entire production entry, before the first Sheet read/contract write, for every caller; remove or coordinate the web wrapper lock so it cannot deadlock. Re-read both guard inputs under that lock, and keep it through persistence/read-back and `SpreadsheetApp.flush()` before release. [Google's Lock documentation](https://developers.google.com/apps-script/reference/lock/lock) explicitly calls for flushing pending Sheet changes before releasing the lock.

2. **CRITICAL — `lastRun` is neither a durable admission marker nor verified on close.** `advanceWorldTime_` only queues `cycleCount` and `lastRun` as separate writes, and silently omits `lastRun` if its key is absent (`godWorldEngine2.js:677-700`). `sheetCache.flush()` isolates individual write failures and continues (`utilities/sheetCache.js:189-206,243-265`). The closeout verifies and may repair **only** `cycleCount` (`godWorldEngine2.js:601-620,724-800`); it never reads back or repairs `lastRun`. Thus a partial flush can leave advanced world/counter with an old or absent timestamp. The next fire passes the time guard. A termination before the finally block has the same unproven marker. **Fix:** make a persistent, verified fire admission record under the common lock before world mutation; refuse an unresolved prior admission until reconciled. At minimum, require `lastRun` to exist and verify its write together with `cycleCount` at close, but an end-only timestamp still cannot protect a concurrent or abruptly terminated run.

3. **HIGH — The proposed string parser will not see date strings.** `loadConfig_` applies `parseFloat` to *every* string value before putting it in `ctx.config` (`godWorldEngine2.js:645-661`). For example, `2026-09-28T...` becomes `2026`, and `9/28/2026` becomes `9`; the planned `new Date(string)` branch at plan line 632 cannot recover the original value. Treated as a Sheets serial, either number is an ancient date, so a recent fire is accepted. A plain numeric string remains a valid dial, so this needs key-specific handling. **Fix:** preserve raw `lastRun` during config loading, or read that cell separately; parse only a strict timestamp format, actual `Date`, or a validated Sheets serial. Add end-to-end tests through real `loadConfig_`, not only direct tests of `assertNotDoubleFire_`.

4. **HIGH — A Sheets serial contains wall time, not a UTC instant.** The resync reads `UNFORMATTED_VALUE` with `SERIAL_NUMBER` (`scripts/syncSandboxFromLive.js:63-75`) and writes those values with `RAW` without copying formats (`:114-133`); an unformatted bench cell can therefore reach Apps Script as a number. [Google defines a serial](https://developers.google.com/workspace/sheets/api/reference/rest/v4/DateTimeRenderOption) as days since 1899-12-30 plus a fraction of a **day**, with no timezone offset. [Apps Script `getValues()`](https://developers.google.com/apps-script/reference/spreadsheet/range) may return `Number`, `Date`, or `String` according to the cell. Interpreting the numeric day fraction as UTC while comparing it with `ctx.now` (`godWorldEngine2.js:239`) shifts the apparent start by the spreadsheet's UTC offset: for a west-of-UTC sheet it can look hours older and admit an immediate second fire; for an east-of-UTC sheet it can look future and block a legitimate fire. DST changes the offset. **Fix:** use the spreadsheet timezone when converting a serial, or store a timezone-independent epoch/ISO instant in a dedicated text cell. Test the actual resync-to-`getValues()` path with both date-formatted and unformatted cells, including a DST boundary.

5. **HIGH — Fail-open removes the guard exactly when its input is bad.** The plan explicitly allows an unreadable/missing `lastRun` on any established Cycle (`docs/plans/2026-09-21-care-and-justice-system.md:632`); `advanceWorldTime_` does not create the row if absent (`godWorldEngine2.js:677-700`). Further, `Phase1-LoadConfig` is wrapped in `safePhaseCall_`, which logs and returns false rather than aborting (`godWorldEngine2.js:159-169,273`); the next unwrapped carry check treats a missing `cycleCount` as zero and skips (`phase01-config/loadPreviousEvening.js:205-209`). An unreadable config can therefore continue toward `AdvanceTime`, which may use zero as its starting count (`godWorldEngine2.js:686-703`). This contradicts the live invariant. **Fix:** make config-load success, a unique valid `cycleCount`, a present valid `lastRun` for established worlds, and a valid guard dial mandatory before admission. Permit an absent marker only for a verified first Cycle or a separately authorized reconciliation path. Diagnostic logging can still report the refusal.

6. **HIGH — The web bypass and 60-minute window do not identify one intent.** The plan makes `backtoback=1` skip the time test while `expect` is optional (`docs/plans/2026-09-21-care-and-justice-system.md:633-636`). A token-holder sending `backtoback=1` without `expect` can fire repeated sequential Cycles. A repeated ordinary GET after the hour, or after a Cycle longer than the hour, also passes by design. Even with `expect`, if a run writes world data but fails before the counter persists, the repeated request sees the old count; `verifyCycleCountPersisted_` can fail to repair it (`godWorldEngine2.js:724-800`). The present token gate only authenticates the caller (`utilities/webTrigger.js:27-42`); it does not make a request one-shot. **Fix:** require a strict `expect` for every web fire, especially any back-to-back bypass, and persist a unique fire-intent/admission key under the common lock. Do not expose the bypass on a live target. An operator retry after a partial Cycle must reconcile its outcome first; a time limit alone cannot provide idempotency.

7. **MEDIUM — “Zero world writes” is too strong at the proposed throw site.** The engine runs fourteen `ensure*` functions before cache creation and the proposed guard (`godWorldEngine2.js:215-233,269-279`). Their contract pattern can directly append `World_Config` rows (`phase01-config/engine94SheetContract.js:513-546,573-584`) and can add civic columns/headers (`:530-538`); the proposed `ensureEngine275Config_` would do the same. Before the guard, `assertCarryForwardPresent_` may delete a one-shot property or restore carry state from the Sheet (`phase01-config/loadPreviousEvening.js:210-225,159-185`). A guard throw enters `FATAL-CycleError`; `logEngineError_` directly appends an `Engine_Errors` row (`godWorldEngine2.js:78-129,597-620`). The cache flush should have no queued **Cycle counter** write because `AdvanceTime` has not run, and read-back returns when `summary.cycleId` is unset (`:728-729`); this does not make the Sheet or script properties byte-identical. **Fix:** state the narrower promise precisely, or move guard admission ahead of all mutating preflight work and use a separate non-world diagnostic channel. Test direct writes and script properties as well as queued writes on refusal.

8. **MEDIUM — The proposed override can remain armed and also blocks a justified repair by default.** The plan uses persistent `World_Config.fireGuardMinutes = 0` as the re-fire override (`docs/plans/2026-09-21-care-and-justice-system.md:631,636,640`). If the operator or a failed run does not restore 60, future live fires have no time barrier. Conversely, a failed run can have set `lastRun` despite no completed world commit because `AdvanceTime` queues it before later phases (`godWorldEngine2.js:279,696-700,597-620`), so an immediate legitimate repair is refused until the manual edit. **Fix:** use a one-shot, target-Cycle override that is consumed under the common lock after a read-back/reconciliation decision; retain a bounded nonzero live guard setting. Make the override's result explicit in `Engine_Errors`.

## Claim checks and remaining evidence

- **Confirmed with a scope limit:** the only source references to `runWorldCycle()` as a call are `utilities/webTrigger.js:42` and the menu binding at `utilities/godWorldMenu.js:27`; no repository call or `ScriptApp.newTrigger('runWorldCycle')` was found. Installed time-based triggers and manual Apps Script editor executions are deployment state and cannot be established from the repository. Any installed trigger that directly invokes `runWorldCycle` would have no lock today. Inventory project triggers before claiming complete entry-point coverage.
- **Confirmed:** `lastRun` is written by `advanceWorldTime_` at `godWorldEngine2.js:700` and has no current reader found in source; the proposed unwrapped placement is before `AdvanceTime`. The plan's `assertCarryForwardPresent_` call pointer `:278` has drifted to `:277`; `:278` is now `Phase1-CanonHoods` (`godWorldEngine2.js:273-280`). `assertCarryForwardPresent_` skips dry-run/replay (`loadPreviousEvening.js:205-206`). `runCyclePhases_` is a separate dry-run/replay path (`godWorldEngine2.js:1953-1971`), invoked by `runDryRunCycle`/`replayCycle`; it is not a third production fire entry in the current source. `initializeModeFlags_` only initializes context flags (`utilities/cycleModes.js:128-137`).
- **Web flag:** the run-scoped `backtoback` global is design only, so its actual initialization and clearing cannot yet be verified. A `doGet` `try/finally` can clear it, as the current lock is cleared at `utilities/webTrigger.js:40-58`; no persistent cross-request state should be inferred from a JavaScript global. Prefer passing an explicit option into `runWorldCycle`/`ctx` rather than using a mutable project global, and test clearing on early throw. The flag's main risk is its authorization to bypass the live guard, finding 6.
- **`expect` race:** a future direct Sheet read under the `doGet` lock can serialize two web calls only if the first run has committed its counter before release. Today the wrapper releases at `webTrigger.js:56-57` without `SpreadsheetApp.flush()`. It cannot serialize a menu fire, and no implementation of `expect` exists yet. Test the real Sheet persistence/read-back ordering, not only a VM stub that increments its counter synchronously.
- **Unverified live assertions:** this review did not read the live `lastRun`, its cell format, spreadsheet timezone, installed triggers, or a deployed version. The plan's C110 and date-specific deploy prediction at `docs/plans/2026-09-21-care-and-justice-system.md:640` remains a plan claim, not code proof.

No local or API-backed tests were run: the review is source inspection plus official Apps Script/Sheets API type and lock contracts. The named review file is the only artifact of this pass.
