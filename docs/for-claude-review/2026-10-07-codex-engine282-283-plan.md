# engine.282 and engine.283 plan review

**Verdict: HOLD as written.** The two writer fixes are source-supported, but the C112 fixture cannot validate the rest of that Cycle, existing tests would fail under the proposed case change, and the PROD stage gate treats a broad delta as proved by one bench Cycle. This is source review only; no scripts, tests, Sheets, deployments, or live version comparisons were run.

## Numbered findings

1. **High — the Status-reader inventory is inaccurate and misses a live eligibility gate.** `phase05-citizens/casinoLedgerEngine.js:435-443` requires exact `Active` for `Simulation_Ledger` citizens in the Undocked draw. The same exact gate exists in the offline draw at `scripts/undockedDraw.js:88-96`; changing a lower-case recovery or release to `Active` makes that citizen eligible. `phase05-citizens/runCareerEngine.js:278,1389,1429,1761` has the exact ledger gates the plan names. Conversely `phase05-citizens/checkForPromotions.js:309-316,638` gates `Generic_Citizens`, and `phase05-citizens/processAdvancementIntake.js:400-411` also gates `Generic_Citizens`; they do not establish a ledger Status effect. The direct ledger readers checked that compare to lowercase `active` first normalize the cell (examples: `phase05-citizens/generationalWealthEngine.js:415`, `phase04-events/generationalEventsEngine.js:390-394`, `phase10-persistence/buildCyclePacket.js:1025-1035`). No direct ledger reader needing *raw* lowercase `active` was found in the searched engine and script surfaces. Correct the reader map and test the Undocked eligibility change explicitly.

2. **High — the proposed test additions leave existing tests red.** The plan proposes a new release-to-blank-prior assertion, but `scripts/judicialLifecycle.test.js:548-554` currently requires a reconcile exit to write lowercase `active`; `scripts/hospitalIncomePersistence.test.js:473-483` requires the no-carrier discharge to write lowercase `active`. Both must assert canonical `Active` after the respective writer changes. The current health test at `scripts/hospitalIncomePersistence.test.js:454-473` checks the Retired status and Hospital_Ledger closure, but not cleared `HealthCause` or the recovery counter. Update those existing assertions and add the missing state assertions before claiming a green full suite.

3. **High — the discharge flag fixes a real Retired/custody case, but its meaning needs a precise test.** `phase04-events/generationalEventsEngine.js:433-436` replaces the health engine's `active` result with Hospital_Ledger `PriorStatus`; `:471` and `:481` then miss cause clearing and the count when that prior is `Retired` or `Active`. Capturing `discharged` before the override, then using it at `:465,471,481`, resolves that defect. A detained admission carries the underlying judicial prior, not `detained`, at `phase04-events/generationalEventsEngine.js:679-705` and `phase05-citizens/judicialLifecycle.js:325-340`; the Hospital writer rejects detained prior at `phase10-persistence/buildCyclePacket.js:970-973`. Assert both a Retired prior and a detained-to-care case whose judicial prior is Retired: final Status Retired, empty HealthCause/StatusStartCycle, one recovery, and an unchanged Retired `hospitalEvents.to`. Also assert the no-carrier path writes ledger `Active` while its event `to` stays lowercase `active`.

4. **Medium — keep the event payload separate from the canonical cell.** The proposed cell-only normalization is the correct boundary: `phase04-events/generationalEventsEngine.js:455,475-481,1745` sends `healthResult.newStatus` into Hospital_Ledger and generational event payloads; `phase10-persistence/buildCyclePacket.js:993-1007` closes a hospital row for a non-health `to`, with only deceased receiving a special outcome. Canonicalizing the variable as well would change the no-carrier event value and defeat case-sensitive `active` checks at `phase04-events/generationalEventsEngine.js:465,471,481`. Verify the event `to` and `newStatus` shapes in the focused health tests. For carried `Retired`, the event already says Retired; the new flag must supply the missing cleanup/count independently of event casing.

5. **Medium — engine.282's mechanism is correct, but the new assertion must inspect the raw cell.** `phase05-citizens/generationalWealthEngine.js:422,510-531` converts a blank NetWorth to numeric zero for calculation, sets `nwNew=0` on default, then skips the cell write because `nwNew === nw`; an unconditional zero write inside the default branch addresses this exact gap. `scripts/debtLean.test.js:64-65` accepts `nw: ''`, while `:95`'s `nwOf` coerces a blank to zero and `:278-282` therefore cannot detect the defect. Add a strict `row[col('NetWorth')] === 0` assertion after a forced blank-cell default, plus the ordinary numeric/default and non-default cases already covered by section 8. This proves the cell shape locally; the plan's reported live row counts remain unverified here.

6. **Blocking — the C112 bench fixture contaminates the other C112 checks.** `debtDefaultCycles` is read once from World_Config for the *whole* money loop (`phase05-citizens/generationalWealthEngine.js:375-387`) and the default gate runs for every eligible top-debt adult, not only POP-00963 (`:415-430,503-521`). Changing that dial to 1 can default any other qualifying adult, alter NetWorth, WealthLevel, DialState, LifeHistory, hooks and subsequent home eligibility (`:511-521,540-550,1992,2027-2039`). The default-roll gate still draws once for each eligible adult at either positive dial value (`:507-510`); the contamination is changed outcomes and downstream state, not an automatic change in the current Cycle's draw count. C112 results from this modified world cannot be used as clean evidence for the eight queued builds or for PROD readiness; resync *after* the fire cannot repair the already interpreted C112 evidence. Use a separate, freshly synced fixture Cycle and a clean C112 run, or explicitly label the fixture run as engine.282-only mechanism proof and withhold all other C112 acceptance claims.

7. **Blocking — the planned C112 observations do not guarantee either changed path fires.** The plan itself says no blank-NetWorth citizen naturally sits at the default threshold and says a skipped fixture leaves unit tests as proof. The Status fix likewise needs an actual discharge/release: `phase04-events/generationalEventsEngine.js:420-433` only writes on a health transition, and `phase05-citizens/judicialLifecycle.js:657-667` only restores on a resolving case. A C112 scan showing no new lowercase `active` is a negative observation, not a writer proof. Require focused local tests for both writers and either a controlled bench transition/read-back or a clear statement that bench proved only no regression. Do not count a clean C112 as proof of an unexercised writer.

8. **Blocking — the PROD delta and attribution claim need a separate gate.** The repository runbook identifies PROD at `e59e89f8` and SANDBOX 1004 at `2e9f3c63`, with one C111 fire on the broad bench build (`docs/reference/DEPLOY.md:59,66`); the plan describes a 54-file engine delta and several other cuts. A C111 clean run does not establish that every changed path fired, nor that a later HEAD stage is byte-identical to what the bench ran. The claim that 282/283 have disjoint columns is not sufficient: judicial restore precedes Phase5 wealth (`phase01-config/godWorldEngine2.js:607,628`), and the Undocked draw consumes exact-`Active` ledger eligibility **before** the money loop (`phase05-citizens/generationalWealthEngine.js:158-173`, `phase05-citizens/casinoLedgerEngine.js:442,490-523`). Newly eligible citizens can change the cast and downstream outputs; a changed cast need not change draw count, but can change selected identities. Inventory the exact staged engine-file delta against a fresh PROD pull, identify each queued cut's bench evidence and any unexercised trigger, and compare the final bench artifact to the proposed PROD artifact before calling the combined stage safe. The civic.43 claim is conditional on current Initiative_Tracker content: the code routes any education-domain vote or renewal to the board (`phase05-citizens/civicInitiativeEngine.js:125-138,413-434,662-666`), so today's reported absence of education rows is not a permanent inertness guarantee.

9. **Medium — the three-cell live repair is a distinct, guarded operation.** Canonical writers do not rewrite old lowercase cells. The plan's three POPIDs and status counts come from its stated live read, not from this source review; `docs/engine/ROLLOUT_PLAN.md:86-87` records the same work item, not current cell truth. Before any separately authorized repair, resolve each POPID to exactly one current `Simulation_Ledger` row, require the present raw Status to be `active`, bind `lib/sheets.updateRange` to the intended live Sheet, and read back exactly those cells. Keep the repair's evidence and authorization separate from the source fix and bench result.

## Disposition

Fold findings 1-9 into the plan before implementation and the C112/PROD gates. The source supports the narrow writer changes and the discharge flag, subject to the tests and proof boundaries above. No source file, Sheet, deployment, script, or Git history was changed for this review.
