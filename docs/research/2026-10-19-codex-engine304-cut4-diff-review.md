## 2. One-sided arrival — FIX

- `famDeadAnchor` resets to `null` on each new queue row (`processAdvancementIntake.js:831-836`); the recheck sets it only for the current surviving dead match (`:857-869`), then the branch selects `wireFamilyToDeceased_` (`:1090-1095`). It cannot leak to the next new row. The writer mutates `newRow` only (`:2826-2873`): widow status/SpouseId/children, child ParentIds, parent ChildrenIds/NumChildren; dead HouseholdId transfers only if another Active ledger member holds it (`:2861-2873`). With no holder it leaves the minted row unhoused, as the folded plan now states (`docs/plans/2026-10-08-engine-286-game-of-life-events.md:544`).
- **Failure path:** the minor-spouse guard is inside the writer, after `ledgerRows.push(newRow)` and the GC Emerged flip (`processAdvancementIntake.js:1070-1095,2840-2843`). A Family spouse row with a minor BirthYear can therefore mint, lose its Family status, and return unwired. The normal lottery fits adults, but the guard is supposed to protect this recheck against changed or malformed input. Reject the minor *before* mint/GC flip, or keep the Family row for a safe release; test the negative path. C9 tests only an adult widow (`scripts/engine304FamilyLottery.test.js:588-604`).

## 3. Households — **HOLD**

- `deadParentSet_` correctly counts ledger deceased and archive deaths, excluding traded-away from salary subtraction (`phase05-citizens/householdFormationEngine.js:327-341`). But orphan admission does **not** use that set: it tests only `byPop`, populated from formation statuses Active/retired/recovering (`:359-385,423-425`). A minor with a `ParentIds` pointing to a ledger `Traded`, hospitalized/critical, or archived traded-away parent and blank HouseholdId now forms an “orphan” family; the pre-cut rule required no ParentIds (`householdFormationEngine.js` at `6cfd1555^:403`). D11 explicitly says a traded-away parent is alive and unchanged (`docs/plans/2026-10-08-engine-286-game-of-life-events.md:540`). Make orphan eligibility depend on confirmed death for recorded parents, while preserving the existing no-ParentIds case; test each exit/status. Already housed minors skip via `liveHH`/membership adoption (`householdFormationEngine.js:401-415`), so the drift hits unhoused rows/new arrivals.
- The income pass uses the maximum living-parent slots among minor members, capped at two (`:1284-1295`), matching the D11 review fold for mixed families (`plan:544`). `deadParentSet_` is lazy in formation and income (`householdFormationEngine.js:399-400,465-468,1247-1250,1287-1293`); the first call reads Citizen_Archive once through the per-ctx cache, later calls reuse it (`utilities/archiveCitizenExits.js:69-93`). The new criteria row's seed income is calculated in formation; the income pass iterates the previously loaded household array (`householdFormationEngine.js:184-209,227-229`), so full-path tests must cover seed now and income next Cycle.
