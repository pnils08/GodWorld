# pipeline.95 show wake review

**Verdict: HOLD.** The switch is off (`scripts/undockedShowRecord.js:11-14`). The source paths support a distinct show reserve and an applied-night page stage, but the guarantee, page retry, and attribution contracts have the failures below. This is source inspection only: no tests, network calls, or live runs were made. The wiring card required by `AGENTS.md` is not attached because the current task prohibits network calls.

## Findings

1. **F1 — two pilot-Cycle marks can be spent by one wake.** `owedFromShow` creates distinct IDs for each flown Cycle (`lib/wakePerception.js:1071-1082`), and `showCandidates` deliberately keeps one ready entry per pilot (`:1087-1095`). On a selected pilot, `scripts/citizen-wake.js:327-331` calls the generic `owedFor`, which returns *all* that pilot's unspent show marks (`lib/wakePerception.js:1058-1062`), then journals all of them in the same page receipt (`scripts/citizen-wake.js:434-438`). Input: synthetic POP-90001 flew in C112 and C113, has neither mark spent, and is selected once in C113. Wrong output: the one wake receipts both `undocked:POP-90001:c112` and `undocked:POP-90001:c113`; no second wake is guaranteed for the second flown Cycle. This contradicts the stated one-wake-per-pilot-per-flown-Cycle contract (`lib/wakePerception.js:1066-1068`; plan §6.2, `docs/plans/2026-10-16-undocked-crossover-the-city-knows-its-pilots.md:153`). The new fixture has two nights in one Cycle, but no one pilot with nights in two Cycles (`lib/wakePerception.test.js:655-671`).

2. **F2 — the first-run backlog can lapse despite the “sure wake” claim.** `showCandidates` sorts current-Cycle marks before prior-Cycle marks (`lib/wakePerception.js:1087-1095`); only three show slots are available (`:1069`, `scripts/citizen-wake.js:53-57,310-315`). `owedFromShow` drops marks older than the two-Cycle window (`lib/wakePerception.js:1074-1077`). Input: at the flip, three distinct C112 pilots and three distinct C113 pilots have open marks, none is otherwise drawn, and C113's three show slots serve the C113 pilots as the test explicitly expects (`lib/wakePerception.test.js:677-681`). Wrong output: the three C112 marks are never reserved in C113 and disappear from eligibility in C114; those pilots have no guaranteed wake for their flights. This is the concrete consequence of the chosen 3-slot/newest-first rule, not a request to change the builder's reserve count. The guarantee needs an explicit disposition for the backfill backlog.

3. **F3 — a landed show page can be appended twice, and a torn receipt can stop all retries.** `pageNights` checks only `paged.json`, sends the page, then writes the receipt (`scripts/cron-undocked-run.js:272-285`). The page store appends content on a repeated customId rather than refusing it (`lib/citizenPage.js:61-67,139-177`). Input: `appendReflection_` lands night E, then the process dies or `fs.writeFileSync` fails before E's receipt is durable. Wrong output on the next run: E has no receipt and is sent again under the same key; its page becomes `night E text --- night E text`, not one night record. A crash during the in-place `paged.json` write can also leave invalid JSON; the next `JSON.parse` throws before any night is retried (`scripts/cron-undocked-run.js:273-274,283-284`). The stage catch prevents unwinding the already aired show (`:376-381`), but it cannot make those page records correct. The test covers a failed page response and an already saved receipt, not the landed-page/unreceipted interval (`scripts/cron-undocked-run.test.js:92-114`).

4. **F4 — a show doc reaches another citizen-memory reader as if it were a reflection.** The new page carries `metadata.type='show'` (`scripts/cron-undocked-run.js:278-280`), and the newsroom index rejects that type (`scripts/scanCitizenPages.js:63-81`); `loadOwnPageReadback` now rejects it too (`lib/wakePerception.js:328-334`). But the persona recall path asks for six recent page docs and joins their content without a type check (`lib/personaProvider.js:429-453`; `lib/citizenPage.js:244-269`). Input: a pilot's recent six docs include `UNDOCKED, Tuesday night, Cycle 113...` with type `show`, then that citizen receives a persona message. Wrong output: the non-reflection show record appears under “Your own memory (things you have reflected on)” and may displace an actual reflection from the six-doc read. This is a separate live reader from the wake and interview recall paths.

5. **F5 — an empty feed systems list is treated as proof that the ship never moved when the archive is missing.** `nightClauses` treats *any* array as sufficient to leave the unknown-details branch (`scripts/undockedShowRecord.js:89-94`), then with no archive and no systems/counts derives `moved=false` and says “never got the ship moving” (`:127-130`). The feed contract constructs `Systems` as an array, including `[]` (`scripts/undockedShowContract.js:82-96`). Input: an applied intake row has `FeedEvent.Systems=[]` and its staged archive is missing. Wrong output: the pilot's page and block assert they never moved (`scripts/undockedShowRecord.js:153-165`) even though this record has no movement evidence either way. The missing-archive fixture tests no `FeedEvent`, and the feed fallback fixture tests a nonempty list; neither covers the empty-array case (`scripts/undockedShowRecord.test.js:42,66-69`).

6. **F6 — the captain's-log cleaner does not enforce the no-identifier/no-runner-note claim.** The filter rejects only `session handoff`, `next step`, and `active goal`; the cleaner removes Markdown marks and caps length, but neither removes dates, POPIDs, episode IDs, nor other handoff phrasing (`scripts/undockedShowRecord.js:17-18,138-146`). Both the page and the show block copy that surviving text (`:153-165`). Input: a windowed captain-log entry reads `Handoff to the next session: POP-90001, episode undocked-pop90001-a, 2026-10-30`. Wrong output: it is printed as the pilot's captain's log on their page and in their wake/interview block, exposing a runner note and the identifiers the plan says never appear (`docs/plans/2026-10-16-undocked-crossover-the-city-knows-its-pilots.md:142-143`). The “no ids or dates” assertion only inspects fixture logs without those strings (`scripts/undockedShowRecord.test.js:38,70,89`).

7. **F7 — an unreadable journal can show the block without spending its mark.** A journal parse failure sets `held`, but the wake still loads nights and may select a pilot by lottery (`scripts/citizen-wake.js:274-283,303-317`). `held` makes `showOwed=[]`, while `showBlockFor` still puts the record into the prompt; thus `shownShow=[]` (`:306,327-331,372-375`). Input: the journal contains one malformed line, and a pilot with an applied C113 night wins the ordinary draw. Wrong output: the pilot sees the show block and can answer about the flight, but the pending/shown journal lines carry no show ID (`:430-438`); the mark remains unspent, and the malformed line prevents later reads too. The plan's “unreadable journal means no show slot” is true, but its “mark is spent whenever the block is in front of the pilot” is not (`docs/plans/2026-10-16-undocked-crossover-the-city-knows-its-pilots.md:153-156`).

## Other boundaries checked

With `ON=false` and no existing `show` docs, the flight stage is skipped (`scripts/cron-undocked-run.js:376-379`), the wake uses its prior owed reserve and adds no show prompt/log suffix (`scripts/citizen-wake.js:54-57,263-268,303-315,327-331,401`), and the interview returns an empty show block (`scripts/citizenVoice.js:122-129,161-170`). The new journal counter tracks `slot='show'` separately from `slot='owed'` (`lib/wakePerception.js:1116-1123`); when one pilot holds both kinds of mark, one wake can receipt both IDs while only the selected slot's reserve counter rises (`scripts/citizen-wake.js:434-438`). A taken page key uses `slot='repeat'` and receipts neither kind (`:432-437`). A switch-off *after* show docs exist is not fully parent-equivalent because the new recall filter excludes type `show` unconditionally (`lib/wakePerception.js:328-334`).

The collector's type gate keeps `show` out of the newsroom index (`scripts/scanCitizenPages.js:63-81`), and the page writer's own-words/family gate requires type `reflection` (`lib/citizenPage.js:91-95,178-185`). The source test assertions on reserve ordering, the page key, and fixed fixture text can fail, but they do not exercise the inputs in F1–F7. The known `snippet capped at 180` failure was not investigated or rerun.

**Gate:** settle F1–F3 before flipping the switch; resolve the reader and text claims in F4–F7 or narrow them explicitly. No source-only finding here is a claim of live deployment or Sheet/canon behavior.
