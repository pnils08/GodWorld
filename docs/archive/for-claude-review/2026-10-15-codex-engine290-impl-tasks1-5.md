## 1. Write boundary — FIX

**Finding (medium):** `transitMetricsRow_` correctly blanks station `TrafficIndex` and corridor ridership/OTP in both writers (`utilities/ensureTransitMetrics.js:425-438,447-477`). But `getTransitMetrics_` converts those blanks to numeric zero, and `getTransitSummary_` divides *both* metric sums by all 18 rows (`utilities/ensureTransitMetrics.js:357-367,380-409`). With eight stations and ten corridors, a true 0.85 station OTP averages to about 0.38; corridor traffic 50 averages to about 28. `stationsReported` also reports 18. Repository search found no active caller of `getTransitSummary_`, so this is a latent API regression rather than a proven live output. Fix the reader to average OTP over station rows and traffic over corridor rows, with row-kind counts.

**Presentation lie:** `/api/transit` turns each station's blank traffic into `0` and each corridor's blank OTP into `0` (`dashboard/server.js:1590-1602`). Civic packets do the same for station traffic (`scripts/buildCivicVoicePackets.js:403-413`); their station filter prevents corridor OTP from entering that packet. These values mean unavailable, not measured zero. The slice handles blanks as null (`scripts/buildTransitSlice.js:39-60`; `scripts/beatSliceKit.js:32-36`). The dashboard/packet consumers should preserve N/A where their contracts permit it.

## 3. Ledger shares, corridor base, rebase — FIX

**Finding (medium):** The switch *from* ledger share base to table fallback is not marked as a rebase. `baseVersion` becomes 1 when `transitStationShares_` returns null, but `rebased` is true only when the **new** base is 2 (`phase02-world-state/updateTransitMetrics.js:432-436`). `buildTransitSlice` suppresses prior-Cycle comparisons only when a row says `rebased` (`scripts/buildTransitSlice.js:27-31,43-69,72-101`). Thus a Cycle with an unavailable/zero-total demographics read after a ledger-base Cycle prints a false ridership delta against the authored table. The recovery Cycle back to base 2 *is* suppressed. Mark either direction of a base change and carry the marker into Factors. This is reachable through `transitStationShares_` returning null for no demographics, no stations, or nonpositive total (`updateTransitMetrics.js:241-243,312-317`). The zero-total case also violates the plan's claim that table fallback is only for an absent demographics tab (`docs/plans/2026-10-15-engine-290-transit-rides-the-sim.md:48`); decide whether a populated but zero-weight tab should fail loud or use a separately labeled fallback.

**Finding (low, partial-data path):** `transitCorridorBase_` divides by the mean of only present positive `neighborhoodDynamics` rows, while `transitCorridorBaseFor_` substitutes 1.0 for each absent corridor hood (`updateTransitMetrics.js:325-346`). If dynamics is partial, e.g. one present hood at traffic 3 and the rest missing, city mean is 3 but missing hoods enter corridors at 1; the whole city then appears artificially quiet. Use the same canonical hood set and missing-value rule in both numerator and denominator, or reject partial dynamics. Normal full-coverage dynamics avoids this path.

**Verified source path:** Adults and inbound workers are normalized separately before mixing (`updateTransitMetrics.js:246-272`); a hood with zero Adults and zero workers contributes zero without division by zero. Retail is a bounded multiplier; the missing neighborhood-state path gives zero retail lift (`:253-271`). A stable base-2 carry does not suppress deltas; base-2 after any other version does.
