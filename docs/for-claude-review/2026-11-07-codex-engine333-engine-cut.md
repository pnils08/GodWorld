# engine.333 Task 2b — engine cut at `f1b53151f`

**Verdict: HOLD on this deploy candidate.** The source-visible injury path can emit a `PriorStatus=detained` intake that Phase 10 rejects while the changed Status remains eligible for the later ledger commit (F1). The named C114 snapshot also contains three ENGINE/SPORTS_OVERRIDE rows that defeat the flip's asserted off-layer guard (F2). The two-fire bench log supports its observed cases, not these inputs. This is a review of `f1b53151f` and the plan's Design 1–5 / Tasks 2b–3; no code was changed by Codex.

## Findings

1. **F1 · P1 · Phase-10 hospital write can fail after the feed stamps an injury.** `applyGameNightMoments.js:394,396-401,431-468` resolves any non-dead named citizen, with no GAME-clock or Status gate. `sportsInjure_` tests only health states at `:288-307`: an A's/Oaks `injury` row naming a `Status=detained` citizen changes that row to `injured`, stamps the Cycle, and emits `priorStatus: 'detained'`. `buildCyclePacket.js:955-960` rejects that intake. The rejection occurs **inside** the event loop, after any earlier admissions may have been written; `buildCyclePacket.js:81-86` catches it as a hospital failure, while `godWorldEngine2.js:838,859` still reaches the later Simulation_Ledger commit. Input → result: a validly resolved named row with detained Status can become injured without a corresponding bed, and can stop the remaining hospital events and missed-admission reconcile from this fire. The C114 snapshot has no detained row, so this is a reachable source path, not an observed bench case. Gate injury against custody before changing the row, or define an explicit care-from-custody handoff that supplies an allowed prior status.

2. **F2 · P2 · The claimed off-layer retirement guard has live-snapshot counterexamples.** `applyGameNightMoments.js:266-278` skips only when **both** `ClockMode != GAME` and `EconomicProfileKey != SPORTS_OVERRIDE`. The named local `output/simulation_ledger_snapshot.jsonl` at C114 (metadata: `output/simulation_ledger_snapshot.meta.json`) contains `POP-00508`, `POP-00509`, and `POP-00510` as ENGINE / SPORTS_OVERRIDE / Retired, with MUBA Hall-of-Famer roles. `applyGameNightMoments.js:394,396-401,463-465` would admit any of those names on an A's/Oaks retirement row, clear the key, prefix `Former`, prepend a new retirement bio sentence, and append a bare `Retirement` log event. Input → result: a citizen already off the GAME clock can be falsely retired again. This snapshot is C114 disk evidence, not a current Sheet read; it disproves the brief's claim that the named snapshot has no half-state rows. Require the intended sports-layer combination and check the status/club eligibility before emitting the milestone; keep a durable receipt if re-fire identity must survive partial writes.
