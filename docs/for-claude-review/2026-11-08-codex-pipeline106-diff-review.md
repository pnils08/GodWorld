## Findings

1. **High — `read_source` treats a search shelf as a canon allowlist.** `scripts/loreWriter.js:230-239` accepts any normalized path for which `lib/mags.js:614-620` returns true, without proving that `search_articles` returned it. The broad `archive/non-articles/` rule admits `archive/non-articles/templates/CYCLE PULSE TEMPLATE v1.2.txt:1-3`, an editorial template, as a full “canon” source. `/editions/<name>` is also accepted after the leading slash is stripped; traversal above the repo is rejected. `lstatSync(full)` checks only the leaf, so a symlink in a shelf parent could redirect a read outside the repo (none was present in the inspected shelves). Template or redirected content → model receives it as established world fact. Require a canon-specific path gate and resolved-path containment, including parent symlinks; test an admitted noncanon file and a parent-link escape.

2. **Medium — Supermemory auth and transport failures become ordinary no-hit answers.** `lib/supermemory.js:68-80` resolves `[]` for malformed/error responses and timeout without exposing the failure; `scripts/loreWriter.js:201-223` then returns “No published piece came back.” An expired key or 401 → the writer gets a no-hit answer and can miss published history. The warning says absence is unproven, but the lookup failure is not diagnosable from its result. Return a distinct unavailable/error status to the tool loop.

3. **Medium — a thought text part can become the saved draft.** The model turn correctly retains all `content.parts` for function-call continuity (`scripts/loreWriter.js:370-380,498-501`). But `parts.find(p => p.text)` also accepts a `{thought: true, text: ...}` part (`:382-386`); if the turn has no `write_file`, `lastText` can cross the 400-character fallback threshold and be saved as `AUTOSAVE` (`:504-512`). A thought-only or thought-first response → quarantine contains reasoning instead of the piece. Select visible text parts explicitly and test a response containing thought text plus function calls/final text.

4. **Medium — the no-overwrite promise is not atomic.** `scripts/loreWriter.js:160-165` checks `existsSync` and then writes with the default truncate flag. Two overlapping runs can both see an absent filename, and the second write replaces the first; `scripts/cron-lore-run.js:106,123-140` compares filename sets, so that replacement is not reported as a new file. `scripts/loreWriter.test.js:44-55` covers only sequential calls. Open with exclusive creation (`wx`) and test the collision path. Sequential new filenames remain visible to the cron.
