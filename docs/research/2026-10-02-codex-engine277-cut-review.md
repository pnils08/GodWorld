# Engine.277 proposed cut review

**Scope:** Read-only source review of the proposed cut at `docs/plans/2026-09-21-care-and-justice-system.md:619-627`. No code or tests changed or run. The builder ruled Tribune reading remains a sociability event; routine job and faith colour becomes a plain day (`docs/plans/2026-09-21-care-and-justice-system.md:619`).

**Verdict: SHIP-WITH-FIXES.** The two-tag mechanism is sound for newly emitted ordinary lines, but the plan's unconditional forward-only claim is false. The new faith tag also lacks citizen-page reader support. Apply the required changes below before calling the cut complete.

## Findings

1. **MEDIUM — CONTRADICTED: the map change is not unconditionally forward-only.** Stamped LifeHistory entries with `cycle > DialState.folded` are re-evaluated using the map installed at fold time, even if the entry was emitted before deployment (`utilities/compressLifeHistory.js:533-545`, `utilities/compressLifeHistory.js:1534-1552`). Unstamped legacy entries are still folded when they leave the raw window, also through the current `nudgesForEvent_` (`utilities/compressLifeHistory.js:610-616`, `utilities/compressLifeHistory.js:1511-1523`, `utilities/compressLifeHistory.js:1556-1559`). Thus an old `[Work]` entry awaiting either fold loses its prior drive effect when `Work` becomes `{}`; no cutoff/version check appears in those paths. Already folded DialState is not replayed by ordinary compression because the watermark excludes stamped entries at or below it (`utilities/compressLifeHistory.js:538-545`). Separately, the opt-in backdating script replays archived and current LifeHistory through the *current* map, so a future rebuild can reinterpret old `[Work]` lines (`scripts/backdateCitizenDials.js:56-65`, `scripts/backdateCitizenDials.js:105-107`, `scripts/backdateCitizenDials.js:115-143`). **Fix:** either add a deployment-cycle/version boundary to the fold/rebuild contract with tests, or explicitly narrow the plan to “newly emitted lines; pre-cut unfurled and rebuilt history may be reinterpreted” and obtain acceptance of that effect.

2. **LOW — CONFIRMED reader gap, not a proven new live-page regression.** The dashboard maps only `Faith` to its faith colour and sends unknown tags to `General` (`dashboard/src/App.jsx:920-931`, `dashboard/src/App.jsx:1003-1013`). Its legacy date-line parser also accepts only `\w+` inside brackets, so it cannot parse a hyphenated `Faith-Practice` tag on that format (`dashboard/server.js:2097-2110`). The same parser already does not recognize current in-world `C`/`Y...C` stamps, so current live-page handling of these new lines is already limited (`utilities/compressLifeHistory.js:771-790`, `dashboard/server.js:2101-2116`). **Fix:** add the new tag to the display mapping and use a bracket-safe tag parser if this page is expected to display LifeHistory tags; otherwise record the existing parser limit and new-tag gap as accepted. Dashboard source is gated engine-sheet scope under `AGENTS.md`.

3. **LOW — QUALIFY: `source:faith` and `source:occupation` are source markers, not unconditional primary tags.** The router checks grief, media, relationship and arc tags before faith/work (`phase05-citizens/generateCitizensEvents.js:803-843`). The proposed change only neutralizes entries whose selected *primary* tag is `Faith-Practice` or `Work`. For example, a grief-reconnection faith entry routes to `Community`, which still moves dials (`phase05-citizens/generateCitizensEvents.js:808-810`, `utilities/citizenDialMap.js:55-66`). That is consistent with keeping a real reconnection event, but the plan should say “routine lines that resolve to these primary tags” and test a higher-priority tagged entry. Preserve the existing priority to avoid changing unrelated events.

## Claim-by-claim checks

1. **Work — CONFIRMED with the source-marker qualification above.** The current map gives `Work` drive +4 (`utilities/citizenDialMap.js:32-43`); exact tag lookup precedes content fallback, so an explicit empty map is dial-neutral regardless of prose (`utilities/citizenDialMap.js:279-303`). The only code sites in the requested five directories that *emit a literal Work primary tag* are the `source:occupation` router and the five media-staff pool mappings (`phase05-citizens/generateCitizensEvents.js:843`, `phase04-events/generateGameModeMicroEvents.js:151-200`, `phase04-events/generateGameModeMicroEvents.js:520-525`). The router keeps `source:occupation` for draw weights and archetype weighting (`phase05-citizens/generateCitizensEvents.js:2896-2903`, `phase05-citizens/generateCitizensEvents.js:2924-2929`). Keeping the primary `Work` spelling preserves the separate trait fold (`utilities/compressLifeHistory.js:178-179`, `utilities/compressLifeHistory.js:874-877`, `utilities/compressLifeHistory.js:909-915`). This statement is about code emitters; stored/manual `[Work]` history can also be read at fold time (Finding 1).

2. **Routine faith and other faith mechanisms — CONFIRMED for newly routed entries.** The router currently maps `source:faith` to `Faith` and the faith fan-out builds entries with that source marker (`phase05-citizens/generateCitizensEvents.js:837`, `phase05-citizens/generateCitizensEvents.js:1472-1497`). Adding an exact empty `Faith-Practice` map works because `baseTag_` strips only four calendar suffixes, leaving `Faith-Practice` intact (`utilities/citizenDialMap.js:247-263`, `utilities/citizenDialMap.js:279-296`). The chosen primary tag and source tags are stored separately; the proposal changes only the former (`phase05-citizens/generateCitizensEvents.js:3176-3183`, `phase05-citizens/generateCitizensEvents.js:3195-3207`). Exposure and join dice still key on `source:faith` and `S.faithExposures`, while the congregation join writes its own `[Faith]` line (`phase05-citizens/generateCitizensEvents.js:3125-3132`, `phase05-citizens/bondEngine.js:1015-1035`). Grief support also keys on `source:faith` (`phase05-citizens/generateCitizensEvents.js:102-120`). The reflection classifier still offers `Faith`, and reflection write-back resolves that event tag through the unchanged `Faith` map (`lib/reflectionClassifier.js:31-46`, `utilities/citizenMemory.js:181-186`, `utilities/citizenDialMap.js:66`, `utilities/citizenDialMap.js:316-326`). T1 essence emits `Faith` directly (`utilities/tier1EssenceEvents.js:390-391`, `utilities/tier1EssenceEvents.js:724-725`). Keep its +3 warmth/+2 composure (`utilities/citizenDialMap.js:66`).

3. **Hood pulse — CONFIRMED if the new pulse entry is copied exactly.** A citizen's first event calls `recordPulse_` with both primary and source tags (`phase05-citizens/generateCitizensEvents.js:3212-3219`). Pulse effects add the primary-tag map and `source:faith` marker; today `Faith` contributes sentiment +1/attractiveness +1 and that marker adds another sentiment +1 (`utilities/neighborhoodPulseMap.js:35-36`, `utilities/neighborhoodPulseMap.js:61-65`, `utilities/neighborhoodPulseMap.js:86-105`). Thus `Faith-Practice` with the proposed identical pulse entry yields the same combined pulse, including event count; `Faith` remains needed for the independent congregation/org-side pulse (`phase04-events/faithEventsEngine.js:164-175`). The faith beat slice reads `Faith_Ledger` and `Faith_Organizations`, so this citizen primary-tag split does not change its input contract (`scripts/buildFaithSlice.js:61-69`, `scripts/buildFaithSlice.js:86-99`).

4. **Other readers — no additional semantic break found in the five-directory sweep.** Stored new lines and `S.citizenEvents` carry the selected primary tag (`phase05-citizens/generateCitizensEvents.js:3176-3183`, `phase05-citizens/generateCitizensEvents.js:3230-3237`); the bond engine consumes the latter as an active-citizen pool without filtering its tag (`phase05-citizens/bondEngine.js:365-376`). The citizen card takes only milestone tags from LifeHistory, excluding both routine faith and work (`scripts/buildCitizenCards.js:562-588`, `scripts/buildCitizenCards.js:720-733`). Wake perception scores each stored tail line with `nudgesForEvent_`, so old `[Work]` lines and new `[Faith-Practice]` lines cease contributing to its recent-event magnitude even while still visible in the text tail (`lib/wakePerception.js:30-45`); this is the plan's intended wake-selection effect, with the historical-read caveat in Finding 1. `Faith-Drift` stays independently neutral (`phase05-citizens/bondEngine.js:1065-1077`, `utilities/citizenDialMap.js:176-177`). A separate faith-ledger emitter uses `Faith` only for org-side hood pulse (`phase04-events/faithEventsEngine.js:159-175`). A manual faith-leader seed writes `[Faith]` and remains dial-moving if folded (`scripts/integrateFaithLeaders.js:211-216`, `utilities/citizenDialMap.js:66`).

5. **Tests — no existing exact Work/Faith dial assertion found that must fail from this cut alone.** The citizen-dial suite asserts unrelated tag values and generic plain-day behaviour (`scripts/citizenDials.test.js:79-99`, `scripts/citizenDials.test.js:179-205`); the pulse suite asserts `Faith` remains positive, which this cut preserves (`utilities/neighborhoodPulseMap.test.js:97-99`). The compressor suite asserts fold shape/once behaviour without exact Work/Faith values (`scripts/compressLifeHistory.dial.test.js:71-96`, `scripts/compressLifeHistory.dial.test.js:114-142`). Add the plan's proposed Work/Faith-Practice/Faith/Media/pulse/router assertions, plus a pre-cut unfurled-history boundary test and a dashboard tag-display test if its reader is updated (`docs/plans/2026-09-21-care-and-justice-system.md:626`, `dashboard/server.js:2101-2116`). Existing tests were inspected, not executed; their pass state after implementation is unverified.

## Required changes before SHIP

1. Resolve the historical-fold boundary in Finding 1 and state the accepted behaviour accurately in the owning plan.
2. Add `Faith-Practice` to the citizen-page display contract if that page is in the build scope, or explicitly accept its current parser limit and new-tag gap.
3. Narrow the plain-day claim to entries that actually resolve to `Work` or `Faith-Practice`, and add a higher-priority source-tag case to the routing tests.
