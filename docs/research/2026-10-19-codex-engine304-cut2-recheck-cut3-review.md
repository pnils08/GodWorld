## B. Cut 3 diff review

Earned citations and recent-media attention skip it (`:1285-1296,1425-1435`); Media Room marks it routed without Intake/Advancement (`phase07-evening-media/mediaRoomIntake.js:453-465`); both citizen-context readers skip it (`phase05-citizens/citizenContextBuilder.js:623-650,1229-1258`). The latter two files use `typeof isFamilyUsage_` guards, so this fence depends on a complete Apps Script bundle. C7 executes GC-only and citation behavior but checks the other three readers by source regex/count only (`scripts/engine304FamilyLottery.test.js:500-525`).
2. **SHIP — other direct consumers found.** `scripts/buildDeskPackets.js:140-157` admits only mentioned/quoted/referenced/featured to the citizen archive. `scripts/cron-saturday-run.js:429-481` and `scripts/cron-desk-run.js:273-304` read existing rows for dedupe while producing their own types; `scripts/cleanCitizenMediaUsage.js:88-109` is a maintenance reader. The engine and dashboard search found no further active coverage counter; archived snapshots/staged output are not live readers. No desk packet or dashboard path found that counts this new type as coverage.
3. **SHIP for admission and row shape; FIX for durable one-page credit.** `appendReflection_` waits for successful page POST and stable customId; the admission predicate requires metadata type `reflection`, an exact wake slot and non-operator POPID (`lib/citizenPage.js:66-74,114-156`). The family scan requires Status Family, matching FamilyOf, nonblank role and First+Last; rows follow the live writers' header-driven Timestamp/Cycle/CitizenName/UsageType/Context shape, leaving Reporter/Sentiment/Processed blank (`:77-111`; `scripts/cron-saturday-run.js:442-481`; `scripts/cron-desk-run.js:284-304`). A failed page POST writes no usage; a failed Sheet action leaves the page successful with `familyMentionsError` (`lib/citizenPage.js:145-157`). Callers check only `appended.error`, not that new field (`scripts/citizen-wake.js:404-408`; `scripts/citizenVoice.js:198-207`; `scripts/citizen-exchange.js:169-172`; `scripts/cron-work-wake.js:282-286`). There is no durable retry/backfill, so a transient Sheet failure can permanently lose an earned family tick.
4. **FIX — dedupe is race-prone.** The hook reads all existing usage rows, checks member name + type + customId, then appends (`lib/citizenPage.js:90-111`). Two simultaneous recordings/retries of one customId can both see no row and append duplicates; `processMediaUsage_` increments for each unprocessed row (`processAdvancementIntake.js:424-525`). The sequential retry test (`lib/citizenPage.test.js:94-102`) does not cover this. Use a serialization/receipt path and a recovery check for failed appends before claiming one row per page per member.
5. **SHIP within the explicit naming rule, with bounded misses.** `namesMember_` accepts a case-insensitive full name or capitalized first name on Unicode letter/number boundaries (`lib/citizenPage.js:71-75`). “May”/“Will” at sentence start or an unrelated same-first-name person can credit a member; pronouns, nicknames and surname-only references miss. This is the plan's stated first/full-name rule, not identity resolution (`docs/plans/2026-10-08-engine-286-game-of-life-events.md:499,518`). The scan page slots match `scripts/scanCitizenPages.js:52`; ordinary citizen-wake, work, PRESS and exchange reflections enter (`scripts/citizen-wake.js:404-408`; `scripts/cron-work-wake.js:282-285`; `scripts/citizenVoice.js:198-207`; `scripts/citizen-exchange.js:169-172`).
