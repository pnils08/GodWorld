# engine.275 diff review — HOLD

Read-only source review of the requested diff against Revision 1. `node scripts/fireGuard.test.js`: **62 passed, 0 failed**. No live Apps Script execution, Sheet read, deployment, or write was made. The live fire is the sheet menu binding at `utilities/godWorldMenu.js:25-28`; the web trigger is a separate entry at `utilities/webTrigger.js:31-62`.

## Findings

1. **CRITICAL — A prior admission for the *same* Cycle becomes eligible again.** `phase01-config/godWorldEngine2.js:294-317` applies the time window and then merely logs when `prior.cycle === target`; it still overwrites the record with `running`. With live `fireGuardMinutes=60`, an unadvanced `cycleCount` after a partial run allows the same Cycle to run again after an hour. With bench `fireGuardMinutes=0`, the identical `expect` can be replayed immediately. The counter failure is a real supported path: `utilities/sheetCache.js:199-205,304-308` continues after an individual write failure, and `phase01-config/godWorldEngine2.js:919-942` explicitly handles a counter repair that also fails. `utilities/webTrigger.js:43` supplies `expect`, but when the cell remains unchanged that expectation still matches. This costs doubled aging, ledger/event writes, and other Cycle effects; a `Phase1-FireGuard` note is not a stop. **Fix:** refuse any non-aborted prior record naming the proposed Cycle, regardless of elapsed minutes or guard setting; require an explicit reconciliation decision before a controlled retry. A one-shot override must not silently stand in for reconciling a partial Cycle. Add a test where the body writes world effects but the counter write and repair fail, then replay the identical web request (also test menu after 61 minutes).

2. **HIGH — `aborted` can mean the body continued after AdvanceTime failed.** `phase01-config/godWorldEngine2.js:420` wraps `advanceWorldTime_` in `safePhaseCall_`, which logs and returns false without stopping (`:159-169`). If it throws before assigning `ctx.summary.cycleId` (`:811-835`), later phases still run (`:421-736`) and can persist world effects; `closeCycleFire_` then calls the fire `aborted` solely because the summary is unset (`:322-327`). Admission ignores `aborted` at `:295`, so another menu fire can start immediately inside the hour. This is the unsafe cost of an `aborted` mislabel. Conversely, an exception *after* summary assignment is conservatively called `failed` and blocks a repair inside the hour even if no counter write landed; that is an availability cost. **Fix:** make failed AdvanceTime fatal to the body, and classify `aborted` only after proving that no Cycle phase or counter write executed. Keep ambiguous outcomes guarded until Sheet state is reconciled. Test a throw before summary assignment with a later phase effect, and a throw after assignment before counter persistence.

3. **HIGH — `done` is a control-flow label, not a persisted-success result.** The body logs partial cache flushes and failed counter repair without throwing (`phase01-config/godWorldEngine2.js:743-762,865-899,919-942`); other `safePhaseCall_` failures are likewise swallowed (`:159-169`). On a normal return, `closeCycleFire_` writes `done` from `summary.cycleId` (`:322-327`), while `doGet` returns `ok:true` (`utilities/webTrigger.js:43-45`). `SpreadsheetApp.flush()` runs *after* `done` is recorded, and its exception is logged and suppressed (`godWorldEngine2.js:346-348`). The cost is a false successful-fire signal over partially committed world state; with finding 1, a later retry can rerun that Cycle. **Fix:** close only after the pending Spreadsheet flush and counter read-back; propagate a failed flush or unresolved counter mismatch as an ambiguous/failed result to the caller. Do not turn individual nonfatal phase errors into a blanket failure if their existing contract permits continuation; specifically gate the counter/commit evidence. Inject partial cache flush, failed repair, and `SpreadsheetApp.flush()` failure in tests.

4. **HIGH — The lock and admission record are scoped to one script project, not the target Sheet.** `runWorldCycle` uses `LockService.getScriptLock()` and `PropertiesService.getScriptProperties()` (`phase01-config/godWorldEngine2.js:283-284,333-340`). `openSimSpreadsheet_` permits a deliberately aimed copied project via `SIM_SSID` and `ALLOW_CROSS_TARGET=1` (`utilities/utilityFunctions.js:204-214,234-248`). Two such projects aimed at the same live Sheet have independent locks and `FIRE_ADMISSION_JSON` values; both can read the same pre-advance counter and pass before either persists it. This is a conditional cross-project overlap path, not evidence that PROD currently has that configuration. **Fix:** inventory all enabled projects/triggers that can target PROD before claiming the invariant; prohibit a second project from firing it, or add coordination tied to the target Sheet that every permitted project must honor. Keep the common script lock for menu/web calls within one project.

5. **MEDIUM — The property parser does not enforce the claimed fail-closed record shape.** `phase01-config/godWorldEngine2.js:286-292` accepts `Number(null) === 0`, missing/null `cycle`, and an arbitrary `state`; a parseable record with `state:'aborted'` bypasses the time test at `:295`. A stale or malformed script property can therefore erase the guard, contrary to Revision 1's “present but unreadable → refused.” This requires malformed external/property state; the implementation's own serializer does not create it. **Fix:** require own numeric finite integer Cycle, positive finite integer epoch milliseconds, known state (`running|done|failed|aborted`), and the appropriate finished timestamp; reject all other shapes. Add null, missing-field, invalid-state, and future-start tests.

6. **MEDIUM — Extracting the body breaks the production phase-order audit.** `scripts/ctxMap.js:283-306` scans only the text between `function runWorldCycle(` and the next top-level function. The new `runWorldCycleLocked_` starts at `phase01-config/godWorldEngine2.js:352`, so the scanner stops before every production `safePhaseCall_` at `:414-736`. It can report a nonempty but truncated direct-call sequence instead of the actual phase order. This does not itself fire a second Cycle, but removes a source check used to find ordering errors before PROD. **Fix:** update `ctxMap.js` to resolve the wrapper's `runWorldCycleLocked_` call and scan that function; assert expected production phase sentinels in its test or CLI validation.

## Apps Script evidence and test limit

- [Google Lock](https://developers.google.com/apps-script/reference/lock/lock) documents that `tryLock(5000)` waits at most five seconds, script locks exclude concurrent sections within the same script, a lock is released when script execution terminates, and pending Sheet changes should be flushed before release. The source order at `godWorldEngine2.js:345-349` does hold the lock while `SpreadsheetApp.flush()` runs. A four-minute body does not by itself expire the lock; a competing fire either times out or acquires it after release and then faces admission. [Google quotas](https://developers.google.com/apps-script/guides/services/quotas) currently list six minutes per execution, so a four-minute body leaves limited headroom for flush and close. Node cannot verify actual Apps Script scheduling or service latency.
- The JSON record is far below Google's [9 KB per property value and 500 KB per store limits](https://developers.google.com/apps-script/guides/services/quotas). A full store or exhausted property-call quota can still make admission/close throw. Admission failure stops before body; close failure is swallowed as described in finding 3. Script properties are [per script](https://developers.google.com/apps-script/reference/properties), relevant to finding 4.
- [Range.getValues()](https://developers.google.com/apps-script/reference/spreadsheet/range) can return `Date`, Number, Boolean, or String. `readFireGuardConfig_` intentionally rejects an actual `Date` for `cycleCount` (`godWorldEngine2.js:249-256`), rather than interpreting its epoch milliseconds as a Cycle. That matches the whole-number contract, but a date-formatted counter would block the weekly fire and require fixing the cell. The VM uses a custom `Date` constructor and contains no `Date`-valued counter case (`scripts/fireGuard.test.js:38-49,167-192`), so it does not establish this Apps Script behavior.
- The 62 passing VM assertions replace the entire production body with a synchronous increment (`scripts/fireGuard.test.js:62-73`). They cannot test `safePhaseCall_`, `sheetCache.flush()`, `verifyCycleCountPersisted_`, `SpreadsheetApp.flush()` exceptions, property write exceptions, real LockService contention, or cross-project locks. The mock lock also has no time/ownership model (`:49`). These are the specific missing fault-injection and Apps Script checks behind the HOLD, not a claim that the passing assertions are false.

**Verdict: HOLD before PROD.** The same-Cycle replay after a counter persistence failure remains an executable path, and `aborted` can reopen the guard after a swallowed AdvanceTime failure. The script lock closes the original same-project overlap gap, but those two paths do not satisfy the builder's live double-fire invariant.
